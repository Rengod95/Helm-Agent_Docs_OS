# a00-nav-context 메모

S-01 셸 내비 정합, N-01 보기 기준 칸, N-04 시험 표지, 시험 대화 정리를 한 폴더에 둡니다. 대부분은 `_shell` 변경이고, 이 폴더는 그 변경을 보이는 무대입니다.

## 셸에서 바꾼 것(`_shell`, 다른 묶음에도 들어감)

- 대화 내비 다섯: "연결"을 대화 영역에 되돌렸습니다(U-3, 결정 3). 작업대 내비는 여섯이고 "만들기"를 뺐습니다(C-6, 캔버스 결정 6). 라벨은 모두 `T`에서 옵니다.
- 보기 기준 칸(`ContextPicker`): `Select` 묶음 넷(전체, 대화, 프로필, 시험). 대화 기준이면 옆에 자물쇠(`LockOpen` 따라감 / `Lock` 고정, `aria-pressed`)와 "대화로 가기". 셸 상태는 `context: WorkbenchContext`(§4.9.5 [제안] 모양 그대로), `followThread`, `pinThread`. 옛 `contextThreadId`는 호환용으로 남겼습니다.
- 작업대 머리(`WorkbenchHead`): 패널이 닫혔을 때만 "보기 기준 <종류> <이름>"(고정이면 자물쇠). 누르면 패널을 열고 칸에 초점.
- 대화 목록: 시험 대화는 폴더 안 "시험" 묶음 한 행으로 접히고 meta에 "실행 중 n · 멈춤 n", 펼치면 행마다 실행 중·멈추는 중·멈춤·끝남. 끝난 시험이 있으면 묶음 끝에 "끝난 시험 n개 지우기…"(`onClearTrials`를 주면 확인과 지우기는 페이지가 맡음).
- 고정 데이터: 시험 대화 t8(실행 중), t10(멈춤), t9(끝남), 제작 대화 ta.

## 레이아웃 결정

- 작업대 가운데는 대역(stand-in)입니다. P-16 개요(목록 + 캔버스)는 캔버스 v3 결정 대기라 그리지 않고, 같은 확장 목록이 기준 넷에 따라 어떻게 바뀌는지만 보입니다(층 mono 열 DP-31, 확장 id mono DP-39, 행 사이 선 없음 DP-26).
- 프로필·시험 기준은 "덮어쓴 칸"만 표시합니다: 원래 값은 흐린 취소선, 새 값은 중립 Badge. 색으로 차이를 칠하지 않습니다(DP-29).
- 시험 정리 확인은 `Dialog kind="alert"`이고 기본 초점은 "취소"입니다. 확인 안의 지울 목록은 `ListDescription`(DP-12).
- "행 메뉴"는 caustic `ListNavigationItem`에 끝 동작 자리가 없어 묶음 끝 하위 행("끝난 시험 n개 지우기…")으로 대신했습니다. 빈틈: 목록 행 끝 동작(⋯ 메뉴) — caustic에 요청할 만합니다.

## caustic 부품

`SidePanel`, `ListNavigation*`(하위 행 포함), `Select`/`SelectGroup`/`SelectHeading`, `IconButton`(aria-pressed), `SegmentedControl`, `Dialog`(alert), `ListDescription`, `Alert`, `Badge`, `Toaster`/`toast`, `Message`, `ToolCall`(p02 ToolRow), `Composer`.

## 웹·좁은 폭

- 720px 미만: 왼쪽 패널이 떠 있는 시트(`narrow`). 작업대에서는 패널이 닫혀 있어 머리의 "보기 기준" 글이 기준 칸으로 가는 기본 진입입니다(`narrow-wb`). 좁은 폭에서는 확장 id mono 열을 뺍니다.
- 웹: ⌘1~⌘5가 브라우저 탭 키와 겹칩니다. 내비 키는 ⌥ 조합으로 두자는 제안(커버리지 §4-9)은 묶음 E 몫이라 여기서는 화면에 키를 그리지 않습니다(DP-06).

## 빈틈과 남은 것

- 시험 대화 이름은 사용자가 정하지 않으면 첫 입력에서 만듭니다(목업은 고정 이름).
- 기준이 "프로필"일 때 대화 영역에서 대화를 바꿔도 기준은 그대로입니다(따라가기는 대화 기준에만). spec §4.9.3에 한 줄 더하기를 제안합니다.
