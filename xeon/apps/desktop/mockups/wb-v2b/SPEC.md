# 캔버스 v2 · 방향 B "정교한 노드 편집기" 명세 제안 (wb-v2b)

런타임 지도(개요)와 블록 구성기를 하나의 시각 체계로 다시 그린 제안입니다. Blender 지오메트리 노드, Unreal 블루프린트, Figma, Linear 수준의 다듬음을 목표로 했고, 처음 보는 사람도 "플러그인이 어떻게 설치되고 어디에 꽂히는지"를 몇 초 안에 알도록 만들었습니다. desktop-ux 명세에 합칠 원고이며 spec.md는 고치지 않았습니다.

- 시안: `xeon/apps/desktop/mockups/wb-v2b/` · `?state=S1..S14` · `?theme=dark`
- 실행: `MOCKUP=wb-v2b MOCKUP_PORT=8921 mise exec -- bun run mockup`
- 2026-10-31 사용자 결정(나눔 보기, 운영/구조 편집 분리, 맥락 칸 하나, 층별 자동 배치, 구성·만들기 합침, composition 선언, gate 원시, 경계에서 멈춤)을 반영했습니다(§7).

## 1. 시각 언어

### 1.1 한 장의 흐름

모든 캔버스는 **왼쪽에서 오른쪽으로** 읽습니다. 지도는 열 셋입니다.

| 열(lane) | 담는 것 | 블록이 내는 포트 |
|---|---|---|
| `L1·L2` 기능 공급 | 코어(L1·L0, 부품 9를 접은 그룹), L2 기능 확장. 제공자는 받는 블록 아래에 붙여 쌓습니다(웹 └ Exa 검색) | 오른쪽: 기능 |
| `L3` 플러그인 그룹 + `plugin` 외부 확장 | Helm, 계획 먼저, 학습, 리뷰 / acme 노트, OAuth 모델 | 왼쪽: 기능 입력 · 오른쪽: on, post, drive |
| `X` 훅 | 에이전트 루프의 소켓을 루프 순서(session → input → tool → boundary → lifecycle)대로 위에서 아래로, 핸들러 없는 39개는 한 줄. 아래에 post 큐와 주도 | 왼쪽: 받는 소켓 |

"기능을 주는 것 → 기능을 쓰고 루프에 꽂히는 것 → 루프의 소켓"이라는 한 문장이 화면 배치 자체입니다. 열 이름은 mono 층 표기 + 짧은 한국어 이름 + 수(DP-31)입니다.

### 1.2 블록 해부

```
╭───────────────────────────────╮
│ [아이콘 면] 이름         층 표기 │  머리: 22px 아이콘 면(상태 tone은 여기만, DP-29) · 13.5px 600 · mono 10px
│      user · 0.1.0              ├─ on 6 ■   출력 포트 알약(가장자리에 걸침)
│○ 기능 6                         ├─ post ▶
│      ⌒⌒ 부품 7 ›  실패 1        ├─ drive ◆
╰───────────────────────────────╯  몸: 상태 한 줄 + 핵심 숫자(7일 스파크라인, 부품 수, 실패)
   ╰─ 뒤에 쌓인 두 장 = 열 수 있는 그룹(composition 선언)
```

- 면: `surface.base` + 아주 옅은 안쪽 선(글자색 9%) + 부드러운 그림자 2단. 테두리로 구분하지 않고 면과 그림자로 들어 올립니다.
- 머리: 아이콘 면 · 이름 · 오른쪽 끝 층 표기(L3, plugin) 또는 기계 이름(기능 열은 `web`, `knowledge`, DP-39).
- 상태 줄: 등급·버전이 기본이고, 상태가 있으면 그 문장이 대신합니다(자동 꺼짐 · 연속 5번, 실패 2 · 예외 → 거부, drive 보유 · 턴 1/4, 다음 단계 경계에 켜져요).
- 숫자 줄: 스파크라인(토큰 7일), "부품 7 ›"(누르면 그룹 하위 캔버스), 실패 수. 부품을 선언하지 않은 그룹은 "구성 정보 없음"(결정 7)이고 열리지 않습니다.
- 그룹 블록 뒤의 두 장 겹침이 "이 블록은 부품 묶음"이라는 접힘 표시입니다. 꺼진 블록은 면 없이 윤곽선만, 다음 경계에 켜질 블록은 점선 윤곽입니다.
- 크기: 그룹 210 × 84, 기능 180 × 60, 소켓 184 × 28. 1280px 개요에서 실제 글자가 11px 밑으로 내려가지 않게 맞춤 줌 하한을 0.82로 둡니다.

### 1.3 포트 타입

| 타입 | 모양 | 색(토큰) | 어디서 어디로 |
|---|---|---|---|
| 기능 capability | 원(속 빈 원 = optional, 찬 원 = requires) | success 색상(민트) | 기능 확장 `provides` → 그룹·plugin `requires/optional` |
| on | 둥근 네모(소켓) | info 색상(아이리스) | 블록 → X 훅 |
| post | 삼각(보냄) | agent 색상(금색) | 블록 → post 큐 |
| drive | 마름모(구동) | 잉크(text.primary), 선 굵기 2.25 | drive 그룹 → 주도 / 단계 머신 전이 |
| record(부품 사이 상태) | 작은 네모 | tertiary | 그룹 안 부품 → 부품, 공개 기록 `grp.*` |

- 모양과 색이 겹쳐 뜻을 주므로 색을 구분하지 못해도 읽힙니다. 포트 알약에 "on 6", "기능 2" 같은 글자가 있어 범례가 필요 없습니다.
- 훅 소켓에는 fold 글리프(collect 고리, first 마름모 관문, chain 사슬, tap 점)를 둡니다.
- 색 값은 `color-mix(in oklab, solid, text)`로 만들어 라이트·다크 모두에서 1.5px 선이 바탕 위에 읽힙니다. hex·rgb는 쓰지 않습니다.

### 1.4 선 규칙

1. **기본은 숨김.** 개요에서는 선을 그리지 않고 알약 끝의 8px 꼬리만 보입니다(스파게티 방지).
2. **고르면 그 경로만.** 블록을 고르면 그 블록의 선만 타입 색으로 그리고, 관계없는 블록은 38%로 물러납니다. 목록 행을 골라도 같습니다(양방향 동기).
3. **올리면 미리.** 블록이나 목록 행에 올리면 같은 경로를 70% 농도로 미리 보입니다.
4. **묶음과 경유점.** on 선은 블록에서 굵은 한 줄기(2.75px)로 나와 훅 열 바로 앞 경유점(숫자 = 묶인 선 수)에서 갈라집니다. 기능 선은 받는 블록 바로 앞 경유점에서 모여 한 줄기로 들어갑니다. 그룹 하위 캔버스에서 기록 셋이 한 출력 행으로 모일 때도 경유점을 둡니다.
5. **할로.** 모든 선 아래에 바탕색 받침(선 굵기 + 3px)을 깔아 교차할 때 앞선이 뒤선을 끊어 보이게 합니다.
6. **선 종류.** optional 기능은 점선(1.5 · 4), 초안은 짧은 대시, 잘못된 연결은 danger 짧은 대시, 유령 미리보기는 대시 75%, 실시간 주도는 흐르는 대시(prefers-reduced-motion에서 멈춤), 실패 경로는 danger 실선.
7. **실시간 움직임은 둘까지**(보유 주도 흐름, 테스트 실행 토큰 하나).

### 1.5 프레임(맥락 묶음)

- 맥락(대화 · 프로필 · 테스트)은 캔버스 위 **프레임**입니다. 둥근 윤곽 + 5% 채움 + 윤곽 위에 걸친 제목 탭(종류 · 이름 · 멤버 수 · 턴 · 실시간 점).
- 대화 프레임은 아이리스 실선(실제로 도는 맥락), 프로필은 잉크 점선(가정), 테스트는 금색(떨어진 실행)입니다.
- 대화 맥락에서는 블록을 다시 배치해 **멤버를 프레임 안, 비멤버를 프레임의 홈(notch) 안**에 둡니다. 프레임 모양 자체가 "이 대화에 들어온 것"을 그립니다. 주도 블록은 프레임 안에서 보유·차수·턴/spawn/토큰 막대를 보입니다.
- 맥락 차이는 두 프레임을 나란히 두고 같은 확장을 같은 줄에 맞춘 뒤 가운데 홈에 `+ 켜요`, `− 꺼요`, `~ 설정`(diff 토큰) 표지와 이유(enable에 있음, `ext.helm.maxLenses 3 → 4`)를 둡니다.

### 1.6 중첩

- 그룹 블록 "부품 n ›" → 그 그룹의 하위 캔버스. 캔버스 왼쪽 위 떠 있는 경로(`런타임 지도 › Helm › 단계 머신`)가 깊이를 보입니다. 창 머리 경로가 아니라 캔버스 안 깊이 표시라 DP-05와 부딪치지 않습니다.
- 하위 캔버스는 Blender 그룹 노드처럼 **그룹 입력**(기능, 왼쪽 옆에 이 맥락의 제공자 꼬리표) → 부품 → **그룹 출력**(훅·post·drive·기록)입니다. Helm 부품: 신호 감지(signal), 렌즈 주입(lens), 쓰기 거부(guard), 상태 복원(restore), 단계 머신(drive), 지식 소비(knowledge), 발견 기록(record).
- drive 부품은 한 번 더 열려 단계 머신 상태 그래프가 됩니다(§2.4).
- 미니맵은 내용이 화면을 넘칠 때와 하위 캔버스에서만 보이고, 다 보이면 줌 캡슐만 남습니다.

### 1.7 색 쓰기

- 캔버스 안 색은 **포트 타입 하나에만** 씁니다. 층은 색이 아니라 열 위치와 이름으로 나눕니다.
- 상태 tone(warning, danger)은 아이콘 면, 소켓 칸의 실패 면, 실패 선에만 씁니다.
- 열지도는 on 포트와 같은 아이리스 한 색상 순차 눈금(oklab 섞기)이고, 예산을 넘은 칸만 danger 면입니다.
- 선택은 잉크 1.5px 고리, 실행 중은 아이리스 2px 고리입니다.

## 2. 화면

### 2.1 개요 = 나눔 보기 (결정 1)

- 왼쪽 목록(224px, 투명한 가운데 위의 열) + 오른쪽 캔버스. 목록은 층 묶음(L3, plugin, L2, L1·L0)이고 행 순서는 캔버스 lane 순서와 같습니다. 고른 행은 raised 면 하나(DP-43).
- 켜기·끄기 Switch는 고르거나 올린 행에만 보입니다. 열둘이 늘 보이면 잉크 덩어리가 지도를 누릅니다. 나머지 행은 "꺼짐", "다음 경계" 글자만.
- 캔버스 오른쪽 위: 목록 접기, 자동 배치로 되돌리기(결정 4), 지도 ↔ 표 보기.
- 오른쪽 well은 검사기입니다. well이 열리면 1280px에서 목록이 자동으로 접힙니다(머리 버튼으로 다시).
- 검사기: 머리(아이콘 면, 이름 + mono id, 층·종류·등급·버전), 운영 동작(이 대화에서 끄기, 설정 덮어쓰기, 구성기에서 열기, 다시 켜기), 포트를 역할로 묶은 구역(입력 · 기능 ← 제공자 / 출력 · on: fold, 훅, 예산 대비 막대, p95 / 출력 · post · drive), 설정, 최근 실패.

### 2.2 그룹 하위 캔버스

- 런타임에서 열면 읽기 전용(머리 동작 "구성기에서 열기"). 구성에서 열면 편집입니다.
- 부품 사이 상태 흐름(record)은 고르기 전엔 옅게, 바깥으로 나가는 포트 선이 주인공입니다.

### 2.3 구성 (결정 2·6)

- 구성과 만들기를 하나로 합쳤습니다. 머리 동작은 "테스트", "새 그룹"(템플릿 drive · 정책 · 관찰)입니다. 설치된 그룹은 복제(`lens-review`, Helm에서 복제)해서 고칩니다.
- **놓기 미리보기(S5)**: 캔버스 왼쪽 아래 떠 있는 "블록" 팔레트에서 `문서 검색 docs-search`(knowledge.search 제공)를 끌면, 유령 블록이 그룹 입력 옆에 붙고, 그룹 입력의 knowledge.search 행과 지식 소비의 같은 입력이 맥박 고리로 켜지며 유령 선이 둘을 잇습니다. 설명 카드: 제공해요 → 지식 소비가 쓰게 돼요(저하 풀림) → 설치 승인 뒤 다음 단계 경계부터. 설치는 승인 카드로 확인합니다(그룹 밖 구조 변경은 설치 흐름이 구성기에서 끝남).
- **잘못된 연결(S6)**: web.search를 신호 감지(on 핸들러)로 끌면 danger 대시 선과 ✕, 신호 감지 블록이 danger 면, 이유 카드 "신호 감지는 on 핸들러라 기능을 부르지 않아요 · `on_capability_call` · ADR-0015"와 맞는 곳(지식 소비의 web.search)을 맥박 고리와 유령 선으로 제안합니다.
- **포트 잇기(S14)**: 흐름 보기에서 수렴의 출력을 새 사람 확인(gate) 노드로 끄는 중. 받을 수 있는 포트만 맥박 고리. gate 노드는 "주도 반납" 예산 배지와 "기다리는 동안 주도를 내려놓고, 답이 오면 다음 단계 경계에서 다시 받아요 · ADR-0018 승인 요청" 설명(결정 8).

### 2.4 단계 머신 (흐름)

- 고리 배치: 위 줄은 오른쪽으로(idle → 확산 → 탐색 → 렌즈 셋 펼침 → 모으기), 아래 줄은 왼쪽으로 돌아옵니다(수렴 → 적용 → 끝 → idle). 아래 줄 노드는 입력이 오른쪽, 출력이 왼쪽입니다. "단계마다 커밋하고 다시 불린다"를 고리 모양으로 보입니다.
- 전이 이름표는 ◇(단계 경계) + 짧은 조건(`주도 · pending`, `diverged`, `done ≥ 1`, `발견 ≥ 1`, `applied`). 실패 출구는 선으로 잇지 않고 노드 아래 점선 꼬리표("aborted → 끝")로 둡니다.
- 머리 오른쪽 예산 배지: 확산 턴 1, 탐색 spawn 3, 수렴 턴 0, 적용 턴 1. 캔버스 위 줄: 주도 상한 턴 4 · spawn 8 · 토큰 400k.
- 쓰기 거부 구간: danger 14% 빗금 면 + 이름표(tool.call.before · first · main, subagent:explorer).
- **테스트 실행(S11)**: 같은 그래프 위에 지난 단계는 흐린 이름, 지금 단계·도는 렌즈는 아이리스 고리, 실패 렌즈는 danger 면, 도는 렌즈로 가는 선에 토큰 하나가 흐릅니다. 위 줄: 단계·턴·경과, 주도 막대 셋, "경계에서 멈춤"(다음 단계 경계에서 실제로 멈추고 주도는 쥔 채, 결정 9), "한 경계씩". 왼쪽 아래: 경계 기록(seq, 이벤트, 요약). 쓰기 거부 이름표에 "거부 1 · bash".

### 2.5 표 보기: 층 × 훅 열지도 + 지표

- 행 = 층 묶음 안의 확장, 열 = 캔버스 훅 열과 같은 순서·가족 묶음. 칸 = p95 값과 예산 대비 %, 모서리 실패 점과 수. 값 바꾸기: 지연 p95 · 실패 · 호출. 오른쪽 "최악" 막대.
- 아래 지표 표: 토큰(스파크라인 + 값), 비용, 주도 시간, p95 추이(면 스파크라인, 예산 넘으면 danger), 실패, 거부. 숫자는 오른쪽 맞춤 tabular(DP-26).

### 2.6 빈 상태 "첫 플러그인"

- 내장만 있는 지도에서 L3 열 맨 위에 점선 자리: "첫 그룹을 여기에 꽂아요"와 세 단계(설치 ● · 꽂기 ■ · 켜기 ◆, 각 단계에 그 포트 글리프), "새 그룹"(구성기로) · "가져오기". 자리의 출력 알약에서 훅 소켓·post 큐·주도로 유령 선이 이미 그려져 있어 "꽂으면 어디에 이어지는지"를 놓기 전에 압니다.

### 2.7 좁은 창

- 1100px 이하(medium): 목록을 접고 캔버스만, 줌 하한 0.82로 왼쪽에 붙입니다. 넘치면 미니맵. well은 시트.
- 720px 이하(compact): 캔버스 대신 목록만. 행 오른쪽에 포트 글리프 요약(○6 ■6 ▶ ◆)으로 연결 모양을 남깁니다.

## 6. 새 원칙 제안

- DP-V2B-1 캔버스 흐름은 왼쪽 → 오른쪽 하나입니다: 공급 → 소비·꽂기 → 소켓. 열 = 층(lane), 열 이름은 mono 층 + 짧은 이름 + 수.
- DP-V2B-2 캔버스 안 색은 포트 타입에만 씁니다(기능 민트, on 아이리스, post 금색, drive 잉크). 모양이 색을 겹쳐 말합니다(원, 둥근 네모, 삼각, 마름모). 층에는 색을 주지 않습니다. 상태 tone은 아이콘 면·실패 면·실패 선에만(DP-29 유지, "tone은 아이콘에만"을 포트 타입에 한해 푸는 제안).
- DP-V2B-3 개요 선은 기본 숨김입니다. 고른 경로만 실선, 올린 경로는 미리보기, 나머지는 알약 꼬리. 같은 블록의 같은 타입 선은 한 줄기로 묶고 경유점에 수를 씁니다.
- DP-V2B-4 포트는 가장자리에 걸친 알약이고 글자(타입 + 수)를 가집니다. 범례가 없어도 읽혀야 합니다.
- DP-V2B-5 블록은 면과 그림자로 들고, 테두리는 글자색 9% 안쪽 선 하나까지입니다. 꺼짐은 윤곽만, 다음 경계 대기는 점선 윤곽, 열 수 있는 그룹은 뒤에 두 장 겹침.
- DP-V2B-6 맥락은 프레임입니다. 대화 = 실선, 프로필 = 점선(가정), 테스트 = 금색. 제목 탭에 종류·이름·멤버 수·실시간. 멤버는 안, 비멤버는 프레임 홈 안.
- DP-V2B-7 중첩 깊이는 캔버스 안 왼쪽 위 떠 있는 경로로만 보입니다(창 머리 경로 아님, DP-05와 양립).
- DP-V2B-8 편집 피드백은 놓기 전에 줍니다: 끄는 동안 맞는 포트만 맥박 고리, 유령 선으로 결과 미리보기, 안 맞으면 이유 + 규칙 코드 + 맞는 곳 제안.
- DP-V2B-9 상태 그래프는 고리로 그립니다(위 줄 →, 아래 줄 ←). 실패 출구는 선 대신 꼬리표. 단계 경계 전이는 ◇.
- DP-V2B-10 캔버스 글자는 실제 11px 밑으로 줄이지 않습니다(맞춤 줌 하한). 더 줄여야 하면 넘치게 두고 미니맵을 보입니다. 미니맵은 넘칠 때만.
- DP-V2B-11 표는 캔버스와 같은 축을 씁니다(열지도 열 = 훅 열 순서, 색 = on 포트 색). 지도와 표가 한 체계로 읽혀야 합니다.
- DP-V2B-12 색 섞기는 `oklab`로 합니다. `oklch`로 무채색과 섞으면 색상각이 돌아 아이리스가 분홍으로 번집니다.

## 7. 결정 반영(2026-10-31)

1. 개요 = 목록 + 캔버스 나눔, 고름 양방향, well = 검사기 → §2.1.
2. 캔버스는 운영만(켜기·끄기, 다시 켜기, 덮어쓰기), 구조 편집은 구성기 → 지도·검사기에는 연결 편집이 없고 "구성기에서 열기"만. 놓기 미리보기·연결·잘못된 연결은 구성(S5·S6·S14).
3. 맥락 칸 하나 → 왼쪽 패널 맥락 칸(전체·대화·프로필·테스트)이 지도(프레임), 차이, 흐름(테스트)을 모두 바꿉니다.
4. 층별 자동 배치, 층 안 끌어 옮기기만, "자동 배치로 되돌리기" → 캔버스 머리 아이콘.
6. 구성·만들기 합침 → 크래프트 내비에서 "만들기" 뺌, "새 그룹"은 구성기 머리 동작.
7. composition 선언 → 부품 수 표시, 선언 없는 그룹(계획 먼저)은 "구성 정보 없음".
8. gate = drive 원시, 기다리는 동안 주도 반납 → S14 gate 노드와 설명, 팔레트 "사람 확인 · 주도 반납".
9. 테스트 멈춤은 다음 단계 경계에서 실제로, 주도 유지 → S11 "경계에서 멈춤", "한 경계씩".

## 8. caustic

- 쓴 것: `ZoomControl`(glass), `SegmentedControl`, `Button`, `IconButton`, `Switch`(sm), `Alert`, `ListDescription`, `Input`, `Select`(맥락 칸), glass 유틸, diff·danger·info·success·agent 토큰.
- NodeGraph(efc4b3e)는 쓰지 않았습니다. 이유: (1) 포트 타입별 색·모양이 없음, (2) 가장자리에 걸친 알약 포트가 없음, (3) 묶음 선·경유점이 없음, (4) DOM 측정 선이라 상태별 스크린숏 좌표가 흔들림. 시안 `parts/kit.tsx`, `parts/node.tsx`, `parts/viewport.tsx`에 토큰으로 만들고 머리 주석에 빈틈을 적었습니다. caustic `packages/react`에 넣을 것을 제안합니다:
  - `GraphPort`에 `type`(capability · on · post · drive · record)과 `shape`, 알약 모양(`variant="pill"`) 추가.
  - `GraphEdge`에 `type` 색, `halo`, `bundle`(경유점 id), `look`(lit · hover · dim · ghost · draft · invalid · live).
  - `GraphReroute`(경유점, 수 표시), `GraphFrame`(맥락 프레임, 제목 탭, 홈 모양), `GraphGroupStack`(뒤 두 장 겹침).
  - `CanvasViewport` + `CanvasMinimap`(넘칠 때만), 캔버스 안 깊이 경로 `CanvasDepth`.
- caustic 서브모듈은 `fresnel/m4-design`으로 바꿨지만 커밋하지 않았습니다(이 시안은 caustic을 고치지 않음).

## 9. 미결

1. 개요 캔버스의 L1·L0를 접은 "코어" 블록 하나로 둘지, 펼쳐 별도 열로 둘지(시안은 접음, 부품 9).
2. 대화 프레임에서 비멤버를 프레임 홈으로 옮기는 재배치가 결정 4(사용자 순서 기억)와 부딪칠 때의 우선순위.
3. 하위 캔버스의 부품 배치를 composition 선언 순서로 자동 배치할지, 작성자가 좌표를 줄 수 있게 할지.
4. 상태 그래프 고리 배치(아래 줄 ←)가 다른 drive 그룹의 단계 수(3 또는 6 이상)에서도 맞는지. 단계가 많으면 위 줄을 접는 규칙이 필요합니다.
5. 열지도에서 46개 훅 전체 보기(가족 접기·펴기)를 둘지.
