# f02-compose-trial 시나리오

상태와 시나리오는 `flow.ts`의 상태 기계 하나입니다. `?state=<id>`는 대본의 앞 n개 동작을 적용한 모습에 머뭅니다. `?scenario=<id>&step=<n>`도 같고, 거기서부터 이어서 돕니다. `&hold=1`이면 그 순간에 멈춥니다. `?dev=1`이면 시나리오 막대와 다음에 누를 것이 보입니다.

## 시나리오

| id | 누르는 것 | 화면에서 바뀌는 것 | 근거 |
|---|---|---|---|
| `pause-step-resume` | ① "멈춤" → ② (기다림) → ③ "한 단계씩" → ④ (기다림) → ⑤ "이어서" | ① "멈추는 중"(잠김), 수렴 옆에 연한 표지 ② 수렴 앞에서 멈춤, 주도 유지, 막대 멈춤 ③ 수렴만 돎, 적용 옆 연한 표지 ④ 적용 앞에서 멈춤 ⑤ 적용 뒤 끝, 주도 반납 | C-9, W-48, W-50 |
| `replay-unlock` | ① 잠긴 "다시 돌려 검사" → ② "개발 모드 켜기…" → ③ "켜기" → ④ "다시 돌려 검사" | ① 이유 툴팁 ② 대화 상자 ③ 확인 중, 잠금 풀림 ④ 흐름 판이 절단을 따라감, 절단 17에서 수렴에 첫 차이, 끝나면 검사 보고와 JSON 복사 | U-4, 결정 9 |

## ?state= 목록

| id | 모습 |
|---|---|
| `trial-paused`(기본) | 수렴 앞에서 멈춤, 노드 표지, 주도 유지 |
| `trial-running` | 탐색 중, 렌즈 셋, 실패 렌즈 |
| `trial-pausing` | 멈추는 중, 다음 단계 사이 기다림 |
| `trial-step` | 수렴 한 단계만 도는 중 |
| `replay-locked` | 배포 앱: 끝난 테스트, 잠금 이유, 지난 결과 |
| `replay-dev` | 개발 모드: 검사 보고, 절단 띠, 첫 차이 |
