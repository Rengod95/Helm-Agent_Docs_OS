# B01 플러그인 화면 호스트 — 시나리오와 상태

크래프트 P-18에서 자체 코드 화면(frame)과 기본 부품 화면(declarative)의 남은 상태를 눌러 볼 수 있게 했습니다. `?scenario=<id>`로 시작하고 `&step=<n>`이면 n번째 순간(0부터)에서 시작합니다. `?dev=1`이면 왼쪽 아래 시나리오 막대가 보입니다.

## 시나리오

| id | 누르는 것 | 화면에서 바뀌는 것 | 근거 |
|---|---|---|---|
| `frame-open` | (자동) 화면이 뜸 → 대기 열 "진행으로" → 확인 줄 "허용" 또는 "거절" → "이 화면에서 묻지 않기"를 켜고 다른 작업 "진행으로" | 상자 안 Skeleton(`ready` 대기) → 판. 상자 밖 셸 확인 줄("작업 흐름이 작업 순서 바꾸기를 하려고 해요", `ext.taskflow.move`). 허용이면 카드가 진행으로 옮겨지고 그래프 테두리. 실패 갈래: 거절이면 판은 그대로이고 셸 줄 "거절했어요 · 오류 응답". 묻지 않기를 켜면 다음 이동은 바로 되고 토스트만 | ADR-0021 §3.4 확인 줄, §3.7 `loading`, N-15, N-17, N-18, spec §12.1 27번 |
| `frame-approval-link` | "대기 작업 맡기기" → 받은 요청 well의 승인 카드 "허용" 또는 "거부" → 판 안 "이슈 #412" → 외부 링크 확인 "브라우저에서 열기" | 셸 줄 "승인을 기다려요 · 승인은 앱 카드로만 받아요", 받은 요청 well에 표준 승인 카드(출처 `ext:taskflow`, 보낸 화면 표시). 실패 갈래: 거부면 판에 "맡기기를 거부했어요". 링크는 셸 대화 상자(기본 초점 취소) | ADR-0021 §3.4 `requestApproval`·`navigate`, §3.6.6, DP-22, DP-33, N-19 |
| `frame-dies` | (자동) 생존 확인 1번 놓침 → 2번 놓침 → "다시 불러오기" → 또 멈춤 → "다시 켜기" | "응답이 늦어요" 셸 줄 → 상자 안 "응답이 없어 이 화면을 내렸어요"(연속 실패 4/5) → 다시 띄움 → 5번째에 "이 화면이 연속 실패해 꺼졌어요"(`view_disabled`, 확장은 켜짐) → 다시 켜기로 장부를 비우고 정상으로 | ADR-0021 §3.7 장부(ping 5초, 무응답 2번, 연속 5번), T-18, N-17 |
| `frame-blocked-fallback` | 막힌 화면의 "설정 열기" → "자체 코드 화면 허용" 켜기 | 머리 표지가 "대체 화면", 셸 줄 "설정에서 자체 코드 화면을 꺼 두었어요 · 대체 화면으로 보여요", 대체 화면(기본 부품 목록, 확인 줄 없이 바로 옮김) → 켜면 상자가 뜸. 실패 갈래(step 3): 보안 확인 전 빌드는 설정이 잠겨 켤 수 없음 | ADR-0021 §3.6.2 3번, §3.6.7, §3.7 `frame_blocked`, N-16 |
| `project-frame` | 노트 지도(프로젝트 확장) "켜는 방법" → "프로젝트 확장의 자체 코드 화면" 켜기 | 자리표시 "이 화면은 자체 코드가 필요해요" + 사유 + frame.reason → 설정 대화 상자(조건 두 줄: 프로젝트 신뢰, 저장 범위 = 사용자 설정) → 켜면 지도가 `이 프로젝트 확장` 배지와 함께 뜸. 실패 갈래(step 3): 폴더 신뢰를 아직 정하지 않아 스위치가 잠기고 "이 폴더 신뢰…"로 감 | ADR-0021 §3.5 등급표, §3.6.7, AU-006, N-26 |
| `declarative-states` | (자동) | Helm 탐구(기본 부품): 읽는 중 Skeleton → 그림 → 오프라인(마지막 값 흐림, 동작 잠금, 셸 줄) → 다시 연결 → 연속 실패 5번 → "이 화면이 연속 실패해 꺼졌어요" + "다시 켜기" | ADR-0021 §3.7, spec §6.25 상태, N-20 |
