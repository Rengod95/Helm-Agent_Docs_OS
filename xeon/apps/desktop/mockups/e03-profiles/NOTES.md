# e03 프로필 관리 (N-57)

## 자리: 작업대 "구성"의 "프로필" 보기
- 설정 탭이 아니라 작업대 구성에 둡니다. 이유: (1) 프로필은 확장 켜기·끄기·설정 덮어쓰기·진행 그룹의 묶음이라 그룹 구성과 같은 종류의 런타임 물건입니다. (2) 왼쪽 보기 기준 칸이 이미 프로필을 고르고, 구성기 프로필 보기(§6.28.3)가 내용을 고칩니다. 목록 관리까지 같은 자리에 두면 한 물건의 집이 하나입니다. (3) 설정(P-09)은 "한 범위의 값"을 바꾸는 곳이고 프로필은 이름 붙은 값 묶음이라 성격이 다릅니다. P-09 "플러그인과 그룹" 탭에는 "프로필 관리" 링크 한 줄만 두기를 제안합니다.
- 프로필은 엔진 호스트(`profiles.json`, `profile.list·get·put·delete·apply`, W-46)에 있고 데스크톱·웹·앱이 같은 목록을 봅니다(결정 5, CLI 없음). 머리 둘째 줄이 그것을 한 줄로 말합니다.
- 캔버스(실효 스택 그림)는 이번 범위가 아니라 목록 + 상세로 그렸습니다. 내용 편집은 "구성기 캔버스에서" 한 줄로 넘깁니다.

## 상태와 규칙
- 목록 행: 이름 + mono id, 둘째 줄 "+켜기 −끄기 ~덮어쓰기" 수와 "쓰는 곳 n". 고른 행은 raised 면 하나(DP-43). 행 메뉴: 이름 바꾸기, 복제, 지우기….
- 만들기: 작은 Dialog(이름 하나). 지금 대화의 켜짐 상태에서 시작합니다.
- 이름 바꾸기: 상세 머리 제목 자리가 입력칸 + 저장·취소로 바뀝니다(대화 상자 없음).
- 지우기 확인: 쓰는 곳 목록(시험 대화와 그 상태, 이 프로필을 보기 기준으로 쓰는 다른 창)과 결과(시험 대화는 이미 적용한 값을 그대로, 보기 기준은 전체로). 실행 중 시험이 있어도 막지 않습니다(값은 이미 session 범위에 써짐).
- baseRev 충돌: 상세 위 warning Alert 하나(DP-28)에 누가·언제·rev, 그쪽 바꿈과 내 바꿈을 한 문장으로. "다시 읽기"(기본)는 그쪽 판을 받고 내 이름은 입력칸에 남겨 다시 저장하게 하고, "내 것으로 덮어쓰기"는 그쪽 바꿈이 사라진다고 토스트로 말합니다.
- `profile.changed`: 목록 행에 "방금 바뀜", 토스트 "'조용히'가 다른 곳에서 바뀌었어요 · 앱 · iPhone · rev 4". 보고 있던 상세는 바뀐 프로필이면 그대로 새로 그립니다(입력 중이면 충돌 흐름).
- 읽는 중: 목록 Skeleton 3행 + 상세 Skeleton. 오프라인: 머리 아래 warning inline, 쓰기 잠금. 빈: EmptyState 한 줄 설명 + 새 프로필.

## caustic 부품
`Alert`, `Badge`, `Button`, `Dialog`(sm, alert), `EmptyState`, `IconButton`, `Input`, `ListDescription`, `Menu`, `SegmentedControl`(구성 보기 넷), `Skeleton`, `toast`.

## 직접 만든 것과 빈틈
- 목록 행은 caustic `ListNavigationItem`에 행 동작 자리가 없어(묶음 D와 같은 빈틈) 버튼 행 + 겹친 메뉴 버튼으로 만들었습니다.
- 보기 기준 칸(셸)에 "프로필 관리…" 항목을 더하면 바로 오게 할 수 있습니다. 셸 Select를 고치지 않고 제안으로 둡니다.

## 웹·좁은 폭
- 웹은 같은 화면입니다(같은 호스트 목록). 700에서는 목록 위, 상세 아래 한 열입니다. 390에서는 작업대가 읽기 전용이라 목록과 상세만 보이고 메뉴·만들기가 없습니다(e05).
