# e02 바로 가기 키 · 시나리오

`?scenario=<id>`(`&dev=1`이면 막대), `&step=<n>&hold=1`은 멈춘 모습. 스크린숏 `sc-<id>-<n>.png`. 키 바꾸기와 웹 키 표는 "계획에 없음"(coverage-v2 §4의 11, 9) 항목을 그린 것입니다.

| 시나리오 | 누르는 순서 | 화면에서 바뀌는 것 | 근거 |
|---|---|---|---|
| `rebind-key` | "새 대화" 행 연필 → ⌘⇧N | 키 자리가 기록 칸으로 → 새 키와 "저장됨", 되돌리기 아이콘, 바닥 "바뀐 키 1개 · 이 기기에만", 토스트 | 계획에 없음 11, spec §4.8 |
| `rebind-key-conflict` (실패) | "새 대화" 연필 → ⌘K → 바꿔 쓰기 | 행 아래 Alert "⌘K는 '명령 팔레트'가 쓰고 있어요…" → 바꿔 쓰면 명령 팔레트가 "키 없음", 토스트 | 계획에 없음 11 |
| `web-keys` (실패 포함) | 웹 → "새 대화" 연필 → ⌘N → 다른 키 누르기 → ⌥⇧M | 웹 표에서 ⌘N·⌘1–5가 줄 그은 키 + ⌥⇧ 대체 키. ⌘N을 고르면 "브라우저가 가져가…" Alert, 다른 키는 저장 | 계획에 없음 9, coverage S-01 웹 |
| `reset-all` | 모두 기본값으로 → 기본값으로 | 확인 대화 상자(바뀐 키 n개, 이 기기에만) → 모두 돌아감, 토스트 | 계획에 없음 11 |

## `?state=` 목록

`main`(기본), `area-keys`(찾기 "영역"), `record`, `conflict`, `swapped`, `changed`, `reset-confirm`, `web`, `web-conflict`, `linux`, `empty`(찾기 결과 없음, N-48).
