# 크래프트 v5 (wb-v5)

wb-v4를 대신하는 크래프트 화면 시안입니다. 상태 전환기는 없고 눌러서 봅니다. 실행: `MOCKUP=wb-v5 bun run mockup`. 글자는 변형 d입니다.

범위 막대와 표는 없습니다. 사람이 에이전트를 만지는 방식을 따릅니다: "도구를 쓰기 전에 내 검사를 돌려라", "이 프로젝트에 이 플러그인을 켜라", "묶음을 깔고 마음에 안 드는 하나만 꺼라".

## 배치

- 왼쪽 위 지도(구성): 가운데 `core.loop`(기본 에이전트), 고리는 매니페스트 `plugins[].layer`(L1, L2, L3, 외부), 점은 플러그인, 바깥 두꺼운 호는 플러그인 그룹이 담은 것. 점선은 기능 요구·제공 관계와 대체 관계, 실선은 고른 것이 기본 에이전트에 닿는 곳. 맨 위 왼쪽 칸은 스킬·명령·도구·MCP·훅·기능 찾기.
- 왼쪽 아래 카드: 고른 것 하나를 물건처럼 보입니다. 플러그인, 플러그인 그룹, 훅(순간), 내장·기능 줄, 아무것도 안 골랐으면 에이전트 전체.
- 오른쪽 순서: 한 턴이 흐르는 순간 13개를 위에서 아래로(시작, 생각, 행동, 마무리), 줄마다 걸린 핸들러 칩. 아래에 기능 제공자 줄, 맨 아래에 나머지 훅 33개. 위 오른쪽의 "실패", "주도"가 작은 서랍을 엽니다.
- 지도, 순서, 카드는 같은 선택을 읽습니다. 어디서 골라도 나머지가 따라갑니다. Esc는 선택을 풉니다.

## 눌러 보기

- 점이나 호 이름표를 누르면 카드가 바뀌고, 순서에서 그 플러그인이 걸린 줄과 칩이 밝아집니다. 순서의 칩이나 줄 이름을 눌러도 지도가 따라갑니다.
- 칩의 점은 켜기·끄기. 칩은 같은 줄 안에서 끌어서(또는 Alt+←·→, 카드의 ‹ ›) 순서를 바꿉니다. 막기·고치기 줄에는 순서 번호가 붙습니다.
- 카드의 "꺼짐 · 이 대화 · 이 프로젝트 · 모든 대화"가 그 플러그인이 어디서 도는지입니다. 값 아래에 출처가 조용히 적히고, 칩 뒤에 "이 대화"·"프로젝트"가 붙습니다. 프로젝트가 가져온 플러그인은 "모든 대화"를 고를 수 없습니다.
- "+ 더하기"는 설치한 플러그인에서 고르기, 명령 하나 걸기, 새로 만들기. 지도의 점을 순서 줄로 끌어 놓아도 더해집니다. 빈 줄의 "+ 만들기"는 걸 훅을 이미 아는 빌더를 엽니다.
- "내장"(점선 칩) 옆 "대체": 내장 요약, 기능 제공자(웹 검색)를 플러그인으로 대체합니다. 내장은 취소선, 화살표 뒤에 "대체" 칩. 카드에서 되돌립니다.
- 실패는 지도의 점과 줄의 칩에서 그 자리에 보이고, 눌러 서랍을 엽니다. 서랍은 이유, 연속 횟수, 다시 켜기·끄기, 주도 한도, 차례를 보입니다.

## 아직 모형인 것

가져오기, 플러그인 지우기, 그룹에서 빼기, 그룹 풀기, 하나씩 꺼 보기(알림만). 에이전트 대화(정해진 답)와 실행 테스트(가짜 결과). 대체·더하기가 확장 정보 파일을 고치는 일(알림만). 명령 훅 실행. 나머지 훅 33개의 한국어 이름. 프로필 적용. 테스트·성능 측정 내비(옆 시안으로 감).

## 스펙과 다른 것

- 그룹 구성원 하나씩 끄기: F.extensions §4.5는 그룹 구성원을 한 번에 켜고 끈다고 정합니다. 여기서는 구성원마다 켜고 끕니다.
- 사용자가 훅 안의 핸들러 순서를 바꿈: §4.2의 순서는 tier, 확장 로드 순서, 등록 순서입니다. 사용자 순서 값은 스펙에 없습니다.
- 켜진 곳이 "가장 넓은 범위 하나": ADR-0022 §3.3은 전역, 프로젝트, 대화를 덧씌우므로 넓은 곳은 켜고 좁은 곳에서 끌 수 있습니다. 여기서는 그것을 나타내지 못합니다. 덧씌우기를 Registration의 대화별 켜짐으로 옮기는 규칙도 미결입니다(§3.3 5번).
- 줄에 플러그인 더하기: §3.1의 `hooks[]`는 정적 선언이고 선언 없는 `on`은 `hook_undeclared`입니다. 여기서는 더하면 선언이 고쳐지는 것으로 봅니다.
- 훅의 "내장" 칩과 대체: 스펙에 내장 핸들러라는 말은 없습니다. 기능 제공자 대체는 있지만, `thread.compact.before`를 내장 요약의 대체로 보이는 것은 화면의 해석입니다.
