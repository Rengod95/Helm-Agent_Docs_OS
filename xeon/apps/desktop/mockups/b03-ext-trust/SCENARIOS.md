# B03 확장 가져오기와 신뢰 — 시나리오와 상태

작업대 "확장"(P-13 줄인 것) 위에서 열리는 대화 상자 넷: 가져오기(N-37), 신뢰 확인(O-10), 업데이트 뒤 다시 확인(O-10 차이 모드, coverage §4-2), 지우기 확인(N-38, O-06 변형). `?scenario=<id>&step=<n>`(0부터), `?dev=1`이면 시나리오 막대가 보입니다.

## 시나리오

| id | 누르는 것 | 화면에서 바뀌는 것 | 근거 |
|---|---|---|---|
| `install-folder` | 머리 "가져오기" → "폴더 고르기…"(목업: 고를 폴더 메뉴) → 검사가 하나씩 돎 → "다음: 확장 신뢰 확인" → "켜기" | 검사 여섯 줄이 차례로 통과, 설치 위치(사용자 확장 위치)와 위치 상한. 신뢰 확인에 요청·위치 상한·실제 수준, 쓰는 연산, 연결 지점, 자체 코드 화면과 `frame.reason`. 켜면 목록에 "그래프 렌즈 · 켜짐". 실패 갈래 1(step 5): `helm-fork` 폴더는 이름 겹침·수준 초과·이유 없는 자체 코드 화면으로 `Alert` + "다른 폴더 고르기". 실패 갈래 2: 신뢰 확인에서 "취소"(기본 초점)면 "신뢰 확인 기다림"으로 남고 행의 "켜기…"로 다시 엶 | spec §6.31 O-10, §7.10, ADR-0021 §3.5, X.loading-trust §4.2·§4.6, N-37, coverage §4-12 |
| `update-reprompt` | 작업 흐름 행 "0.4.0 업데이트…" → "업데이트 켜기" 또는 "0.3.0 그대로 쓰기" | 늘어난 것만(진행 맡기기 `drive`, 연결 지점 하나, 자체 코드 옆 패널과 이유) "늘어남" 배지로, 그대로인 것은 한 줄. 받으면 0.4.0, 거절하면 0.3.0 유지(토스트 "0.4.0은 버전 탭에 남아요"). 줄어든 변경(Exa 웹 검색 1.0.4)은 묻지 않고 목록 위 한 줄로만 | coverage §4-2, spec §6.24.1 |
| `uninstall` | 작업 흐름 행 메뉴 "지우기…" → (확장 저장 데이터도 지우기) → "지우기" | 쓰는 프로필 둘, 플러그인 화면 넷, 저장 테이블 둘. 지우면 행이 "지우는 중 · 이번 단계 뒤"로 바뀌었다가 빠짐. 실패 갈래: 저장 데이터까지 지우면 목록 위 `Alert`(테이블 잠김) + "다시 시도". 내장 확장은 메뉴의 "지우기"가 잠김 | X.loading-trust §4.4.5, spec §6.24, N-38 |

- §4-2(다시 확인)와 §4-12(URL 설치)는 spec·m4-plan에 없는 화면입니다(계획에 없음 · 제안). URL 설치는 가져오기 대화 상자의 "다음 단계" 한 줄뿐입니다.

## `?state=` 목록

| id | 상태 |
|---|---|
| E1 | 확장 목록(업데이트 하나, 줄어든 업데이트 알림 한 줄) |
| I1 | 가져오기: 고르기(폴더·묶음 파일, URL은 다음 단계) |
| I2 | 가져오기: 검사 중 |
| I3 | 가져오기: 검사 통과, 설치 위치 |
| I4 | 가져오기: 검사 실패 |

| T1 | 신뢰 확인: 사용자 설치, 자체 코드 화면 |

| U2 | 다시 확인 거절 → 이전 버전 유지 |

| R2 | 지우기 실패(저장 데이터) |
