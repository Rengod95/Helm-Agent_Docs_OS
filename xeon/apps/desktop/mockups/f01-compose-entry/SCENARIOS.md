# f01-compose-entry 시나리오

상태와 시나리오는 `flow.ts`의 상태 기계 하나입니다. `?state=<id>`는 대본의 앞 n개 동작을 적용한 모습에 머뭅니다. `?scenario=<id>&step=<n>`도 같고, 거기서부터 이어서 돕니다. `&hold=1`이면 그 순간에 멈춥니다. `?dev=1`이면 시나리오 막대와 다음에 누를 것이 보입니다.

## 시나리오

| id | 누르는 것 | 화면에서 바뀌는 것 | 근거 |
|---|---|---|---|
| `new-group-make` | ① 머리 "새 그룹" → ② 이름 쓰기 → ③ 시작점 "Helm 복제" → ④ "구성 시작" → ⑤ 보기 "코드" → ⑥ "플러그인 빌더로 만들기" | ① 내비는 그대로 구성 ④ 작성 중 블록 쌓기 ⑤ 코드 보기 아래 다음 길 ⑥ 제작 대화로 넘김 → (기다림) 만든 뒤 다음 동작 | C-6, §6.28.5, §6.29 |
| `authoring-off-enable` | ① "플러그인 빌더 켜기" → ② (기다림) → ③ "플러그인 빌더로 만들기" | ① "켜는 중" ② 같은 자리가 "플러그인 빌더로 만들기" ③ 제작 대화로 넘김 | §6.29 |
| `gate-trial` | ① "테스트 대화에서 돌려 보기" → ② (기다림) → ③ "답하기" → ④ 카드에서 답 | ② 사람 확인 노드에 warning 점, 주도 반납, 상태 표시줄 "확인 기다림" ③ 받은 요청 well ④ 주도 다시 받음, 적용, 끝 | C-8, §6.30 |

그룹 고르기 `Select`로 `audit-trail`(구성 정보 없음), `review`(흐름 보기에서 단계 선언 없음)를 엽니다. 이름 칸은 실제로 검사합니다(`Helm`, `helm`).

## ?state= 목록

| id | 모습 |
|---|---|
| `new-group`(기본) | 구성 안의 새 그룹: 이름, 대상 폴더, 시작점 |
| `new-group-name-error` | 예약된 이름 오류 |
| `new-group-authoring` | 작성 중 블록 쌓기, "플러그인 빌더로 만들기" |
| `new-group-authoring-off` | 같은 자리에 "플러그인 빌더 켜기" |
| `new-group-started` | 제작 대화로 넘김 |
| `new-group-created` | 만든 뒤 다음 동작 |
| `code-forward` | 코드 보기의 다음 길(제안) |
| `code-forward-off` | 코드 보기: 플러그인 빌더 꺼짐(제안) |
| `code-forward-no-engine` | 코드 보기: 엔진 없음(제안) |
| `no-composition` | 블록 하나 "구성 정보 없음" |
| `no-phases` | "단계 선언이 없어요"와 진행 블록 하나 |
| `gate-node` | 사람 확인 노드, 배지 없음, 속성 well |
| `gate-node-trial` | 테스트가 그 노드에서 기다림 |
