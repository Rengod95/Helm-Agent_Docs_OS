# Helm UX Writing Guide

## 1. 기본 목소리

Helm의 문장은 차분하고 구체적이며 책임을 숨기지 않는다.

- 사실을 단정하기 전에 무엇을 직접 확인했는지 말한다.
- 사용자가 왜 지금 읽어야 하는지 먼저 말한다.
- system이나 agent를 사람처럼 과장하지 않는다.
- 불확실성을 겁주거나 숨기지 않고 다음 행동과 연결한다.
- 사용자의 선택이 무엇을 바꿀지 바로 보여준다.

## 2. 문장 순서

상태와 요청은 기본적으로 다음 순서를 따른다.

```text
무엇이 달라졌는가
→ 왜 중요한가
→ 그대로 두면 무엇이 일어나는가
→ 사용자가 무엇을 할 수 있는가
```

## 3. 화면별 고정 표현

### 복귀 요약

- **돌아온 뒤 달라진 점**
- **왜 중요한가**
- **그대로 두면**
- **지금 선택이 필요함**
- **지금 읽지 않아도 됨**

### 선택 요청

- **지금 정할 것**
- **왜 지금인가**
- **추천**
- **다른 선택**
- **핵심 근거**
- **아직 모르는 점**
- **되돌릴 수 있나**
- **다시 볼 조건**

### 진행 작업

- **지금 하는 일**
- **이 일을 하는 이유**
- **다음 단계**
- **맡긴 범위**
- **도움이 필요한 조건**
- **마지막 중요한 변화**

### 결과 확인

- **확인된 것**
- **확인하지 못한 것**
- **남은 제한**
- **반대 근거**
- **전체 영향**
- **다시 확인할 조건**

## 4. 버튼은 결과를 말한다

| 피할 표현 | 권장 표현 |
|---|---|
| 확인 | 이 선택으로 진행 |
| 승인 | 결과 확인 |
| 거절 | 수정 요청 |
| 계속 | 맡긴 범위 안에서 계속 |
| 취소 | 작업 중단 |
| 자세히 | 근거 보기 / 전체 영향 보기 |
| Retry | 마지막 확인 지점부터 다시 실행 |
| Escalate | 내 선택이 필요함 / 담당자에게 도움 요청 |

위험한 행동에서는 대상과 효과를 버튼에 포함한다.

```text
나쁜 예: 승인
좋은 예: 고객 128명에게 이메일 보내기
```

## 5. 상태 문장 예시

### 진행 중

```text
나쁜 예: Agent is working…
좋은 예: 결제 실패 원인 세 가지를 로그와 비교하고 있습니다. 다음에는 재현 테스트를 실행합니다.
```

### 막힘

```text
나쁜 예: 작업이 실패했습니다.
좋은 예: 운영 로그를 읽을 권한이 없어 원인 비교를 멈췄습니다. 로그 읽기만 허용하거나, 익명화한 로그를 제공할 수 있습니다.
```

### 선택 요청

```text
나쁜 예: A와 B 중 무엇을 원하시나요?
좋은 예: 데이터 이전 전에 호환 모드를 유지할지 정해야 합니다. 지금 선택하지 않으면 내일 배포 일정이 하루 밀립니다.
```

### 결과 제출

```text
나쁜 예: 모든 작업이 성공적으로 완료되었습니다.
좋은 예: 세 완료 기준 중 두 가지는 테스트로 확인했습니다. 모바일 환경의 복구 경로는 아직 확인하지 못했습니다.
```

## 6. 불확실성 표현

단일 confidence 숫자를 기본값으로 사용하지 않는다.

```text
피할 표현: 신뢰도 82%
권장 표현: 운영 로그와 같은 패턴이지만 모바일 환경은 확인하지 못했습니다. 모바일 재현 테스트가 통과하면 이 판단을 강화할 수 있습니다.
```

`모름`은 실패가 아니라 다음 확인 방법이 있는 정상 상태다.

## 7. Agent 표현

- agent 이름보다 역할과 맡긴 일을 먼저 표시한다.
- `생각`, `느낌`, `믿음`처럼 의식을 암시하는 표현을 피한다.
- `agent가 결정했습니다` 대신 `승인된 규칙에 따라 선택했습니다` 또는 `agent가 추천했습니다`를 사용한다.
- 법적·조직적 책임과 실행 주체를 혼동하지 않는다.

## 8. 알림 기준

알림 제목은 사용자가 해야 할 일과 마감 효과를 말한다.

```text
피할 표현: Helm notification
권장 표현: 배포 전 선택 필요 · 35분 뒤 자동 작업이 멈춥니다
```

단순 진행 Event는 알림으로 보내지 않는다. 낮은 우선순위 변화는 다음 복귀 요약에 묶는다.

## 9. 언어와 번역

- 사용자 화면의 기본 한국어는 이 문서의 용어를 따른다.
- 영어 UI에서도 Product Domain 이름을 사용한다: Goal, Focus, Problem view, Possibility, Finding, Choice, Work agreement, Allowed range, Result review, Whole update.
- 원론 용어는 개발자 inspector 또는 glossary에서만 괄호로 보조한다.
- 한 화면 안에서 `선택/Decision`, `초점/Concern`을 혼용하지 않는다.
