# Helm에서 일은 어떻게 흐르는가

## 1. 전체 흐름

Helm의 일은 task가 `할 일 → 진행 중 → 완료`로 이동하는 것보다 넓다.

```text
1. 돌아오기
2. 목표와 초점 정하기
3. 문제 관점과 가능성 살펴보기
4. 중요한 선택하기
5. 작업과 맡긴 범위 합의하기
6. 자율 진행과 필요한 방향 수정
7. 결과와 근거 확인하기
8. 전체에 반영하고 다음을 배우기
```

모든 작업이 여덟 단계를 무겁게 거칠 필요는 없다. 간단하고 되돌리기 쉬운 작업은 여러 단계를 자동으로 압축한다. 중요한 위험과 이견이 있는 작업만 깊게 보여준다.

## 2. 단계별 사용자 경험

### 1. 돌아오기

사용자는 raw log가 아니라 **복귀 요약**을 본다.

- 돌아온 뒤 달라진 점
- 왜 중요한지
- 그대로 두면 다음에 일어날 일
- 지금 선택이 필요한 항목
- 지금 읽지 않아도 되는 항목

가치: 과거를 다시 읽는 시간이 아니라 앞으로 올바르게 참여할 준비를 한다.

### 2. 목표와 초점 정하기

사용자는 자연어로 원하는 변화를 말한다. Helm은 다음을 짧게 정리한다.

- 목표
- 지금 풀 초점
- 완료 기준
- 지켜야 할 것
- 하지 않을 것

의미 있는 모호성이 있을 때만 확인한다.

가치: 처음 prompt가 잘못되었더라도 실행 전에 방향을 맞춘다.

### 3. 문제 관점과 가능성 살펴보기

Agent는 하나의 답만 내지 않고 중요한 가능성을 비교한다.

- 현재 문제 관점
- 다른 문제 관점
- 가능한 원인이나 해법
- 각 가능성을 지지·약화하는 근거
- 가장 적은 비용으로 가능성을 구분할 다음 확인

가치: 첫 번째 그럴듯한 답에 너무 빨리 수렴하지 않는다.

### 4. 중요한 선택하기

사람의 판단이 실제 경로를 바꿀 때만 **선택 요청**이 열린다.

- 지금 정할 것
- 왜 지금 정해야 하는지
- 선택지와 추천
- 가장 강한 다른 선택
- 아직 모르는 점
- 되돌릴 수 있는지
- 미뤘을 때의 영향
- 다시 볼 조건

가치: 승인 노동이 아니라 결과의 방향을 만드는 선택을 한다.

### 5. 작업과 맡긴 범위 합의하기

선택을 agent가 실행할 수 있는 **작업 합의**로 바꾼다.

- 왜 하는 일인지
- 어떤 결과를 내야 하는지
- 어디까지 스스로 해도 되는지
- 금지된 행동은 무엇인지
- 어떤 근거를 함께 제출해야 하는지
- 언제 멈추고 도움을 요청해야 하는지
- 다음 확인 시점은 언제인지

가치: 자세히 간섭하지 않으면서도 조용한 방향 이탈을 줄인다.

### 6. 자율 진행과 필요한 방향 수정

사용자는 모든 tool call을 보지 않는다. 각 진행 작업은 다음만 계속 보여준다.

- 지금 하는 일
- 그 일을 하는 이유
- 다음 단계
- 맡긴 범위
- 지켜보는 위험
- 마지막 중요한 변화

사용자는 언제든 목표, 기준, 우선순위, 맡긴 범위를 바꾸거나 안전하게 멈출 수 있다.

가치: 감시하지 않아도 예측하고 방향을 바꿀 수 있다.

### 7. 결과와 근거 확인하기

Agent가 결과를 제출하면 Helm은 완료 기준별 근거를 모은다.

- 확인된 것
- 확인하지 못한 것
- 반대 근거와 남은 제한
- 결과가 무효가 되는 조건
- 수정, 조건부 확인, 결과 확인 중 가능한 행동

가치: “문제없습니다”라는 말보다 구체적인 근거로 결과를 받아들인다.

### 8. 전체에 반영하고 다음을 배우기

결과가 다른 작업에 미치는 영향을 확인한다.

- 이전 선택이나 전제가 깨졌는지
- 문서, 규칙, 테스트, 실제 환경을 함께 갱신했는지
- 다른 진행 작업과 충돌하는지
- 되돌리거나 복구하는 방법이 있는지
- 다음 작업 합의와 자동화 규칙을 무엇을 바꿀지

가치: 지역적인 성공을 전체적인 진척으로 바꾼다.

## 3. 다시 열리는 것은 정상이다

다음 상황에서는 이전 단계로 돌아간다.

- 새 관찰이 현재 문제 관점과 맞지 않는다.
- 중요한 전제가 틀렸음이 확인된다.
- 사용자의 목표나 완료 기준이 바뀐다.
- agent가 맡긴 범위 밖의 문제를 발견한다.
- 결과 확인 중 근거가 부족하다.
- 전체 반영 중 다른 작업과 충돌한다.

Helm은 이 흐름을 실패로 숨기지 않고 `다시 열림`으로 기록한다.
