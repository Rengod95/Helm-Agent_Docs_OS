# 사람과 Agent가 함께 일하는 방법

## 1. 역할은 같지 않지만 함께 일한다

### 사람

- 목표와 지켜야 할 가치를 정한다.
- 중요한 문제 관점과 완료 기준을 바꾼다.
- 되돌리기 어렵거나 큰 영향을 주는 선택을 받아들인다.
- 결과를 확인하고 전체에 반영할지 정한다.

### Agent

- 넓게 조사하고 여러 가능성을 만든다.
- 근거를 수집하고 비교한다.
- 맡긴 범위 안에서 반복 실행과 초안을 수행한다.
- 반대 근거, 충돌, 맡긴 범위 밖의 문제를 알린다.
- 결과와 확인 근거를 함께 제출한다.

### 도구와 자동화 규칙

- 테스트, Git, CI, 배포처럼 신뢰 가능한 관찰을 만든다.
- 반복되는 선택을 정해진 범위 안에서 처리한다.
- 권한과 resource boundary를 실제로 집행한다.

Agent가 유능해져도 누가 목표와 위험을 받아들였는지는 남아야 한다.

## 2. 좋은 공동 작업의 네 조건

기술 문서의 OPD+C는 사용자 화면에서 다음 네 권리로 표현한다.

### 볼 수 있다

내 다음 판단에 필요한 상태, 근거, 예외를 볼 수 있다.

### 예상할 수 있다

Agent가 다음에 무엇을 하고 어떤 조건에서 멈출지 알 수 있다.

### 바로잡을 수 있다

낮은 비용으로 목표, 기준, 우선순위, 맡긴 범위를 바꿀 수 있다.

### 이의를 제기할 수 있다

Agent의 문제 관점, 판단, 추천에 반대하고 다른 근거나 확인을 요청할 수 있다.

설명만 볼 수 있고 방향을 바꿀 수 없다면 충분한 통제가 아니다.

## 3. 함께 일하는 리듬

```text
상황 이해
→ 목표·초점 함께 정리
→ 작업 합의
→ 자율 진행
→ 예정된 확인 또는 중요한 예외
→ 선택·방향 수정
→ 결과 확인
→ 전체 반영과 돌아보기
```

사람은 모든 구현 세부를 감시하지 않는다. 다음처럼 레버리지가 큰 순간에 참여한다.

- 목표와 문제 관점에 따라 경로가 크게 달라질 때
- 무엇이 좋은 결과인지 기술적으로만 정할 수 없을 때
- 비용이나 외부 영향이 크고 되돌리기 어려울 때
- 중요한 이견이나 반대 근거가 있을 때
- agent가 맡긴 범위를 벗어나야 할 때
- 결과와 전체 영향을 받아들일 때

## 4. 선택 요청을 만들지 않을 때

Helm은 다음 상황에서 사용자를 방해하지 않는다.

- 쉽게 되돌릴 수 있는 로컬 선택
- 자동 확인이 가능한 반복 행동
- 이미 합의된 규칙이 정확히 적용되는 경우
- 사용자의 답이 결과를 바꾸지 않는 질문
- agent가 스스로 조사해 해결할 수 있는 정보 부족
- 단순 진행 보고

## 5. 피해야 할 공동 작업

### 조용한 자율 실행

무엇을 왜 하는지, 다음에 무엇을 할지 알 수 없다.

### 보여주기식 승인

실질적인 선택 없이 계속/취소만 반복한다.

### 매끄러운 요약

불확실성과 이견을 지워 모든 것이 잘 진행되는 것처럼 보인다.

### 사람처럼 꾸민 Agent

감정, 책임, 의식을 암시해 capability보다 persona로 신뢰를 얻는다.

### 가장 어려울 때만 사람 부르기

평소에는 상황을 알 수 없고 실패 순간에만 복잡한 log를 넘긴다.

### 정보 전부 보여주기

중요도를 구분하지 않고 모든 message와 tool call을 화면에 쏟아낸다.
