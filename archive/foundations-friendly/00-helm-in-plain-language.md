# Helm을 쉬운 말로 설명하면

## 1. 우리가 해결하려는 문제

Agent는 사람보다 빠르게 많은 일을 동시에 수행할 수 있다. 문제는 일이 많아질수록 사람이 다음을 놓치기 쉽다는 것이다.

- 왜 이 일을 시작했는지
- 지금 무엇이 사실이고 무엇이 추측인지
- agent가 어디까지 해도 되는지
- 어떤 선택이 전체 방향을 바꾸는지
- 끝났다는 말이 정말 믿을 만한지
- 여러 결과가 서로 맞는지
- 하루 뒤 돌아왔을 때 어디서 다시 시작해야 하는지

Helm은 이 문제를 더 긴 채팅 기록이나 더 많은 알림으로 해결하지 않는다.

> 중요한 차이는 보여주고, 반복적인 실행은 조용히 맡기며, 사용자가 방향과 결과의 주인으로 남게 한다.

## 2. Helm이 제공하는 것

Helm은 사람, agent, 도구, 문서, 실제 결과를 하나의 작업 공간에서 연결한다.

사용자는 다음 흐름으로 일한다.

```text
현재 상황 이해
  → 목표와 초점 정하기
  → 가능한 설명·해법 비교
  → 중요한 선택하기
  → 할 일과 맡긴 범위 합의
  → agent가 자율적으로 진행
  → 필요한 순간에만 방향 수정
  → 결과와 근거 확인
  → 전체 작업에 반영
  → 다음 작업을 더 잘하도록 학습
```

이 흐름은 고정된 단계가 아니다. 새 근거가 나오면 문제를 보는 방식이나 이전 선택을 다시 열 수 있다.

## 3. Helm의 열 가지 쉬운 원칙

### 1. 할 일보다 목표를 먼저 본다

모든 작업은 “무엇을 할 것인가”뿐 아니라 “왜 필요한가”와 연결된다.

### 2. 많이 움직인 것이 진척은 아니다

파일 수, message 수, agent 실행 시간보다 실제로 무엇이 좋아졌고 그것을 왜 믿는지가 중요하다.

### 3. 처음 요청이 완성된 문제 정의는 아니다

조사 중 새로운 사실이 나오면 문제를 보는 방식과 성공 기준을 바꿀 수 있다.

### 4. 본 것, 해석한 것, 가능한 설명, 선택을 구분한다

직접 확인한 사실과 agent의 해석을 같은 문장에 섞지 않는다.

### 5. Agent에게는 일을 맡기고 사람은 방향을 정한다

반복 실행과 넓은 탐색은 agent에게 맡긴다. 목표, 중요한 기준, 큰 위험의 수락은 사람이 주도한다.

### 6. 자율성은 agent의 등급이 아니라 맡긴 범위다

같은 agent도 작업과 위험에 따라 읽기만 하거나, 로컬 변경을 하거나, 외부 행동 전에 멈출 수 있다.

### 7. 사소한 것은 묻지 않고 중요한 차이만 묻는다

쉽게 되돌릴 수 있고 자동 확인 가능한 선택은 맡긴다. 가치 충돌, 큰 영향, 낮은 복구 가능성이 있을 때만 사람을 부른다.

### 8. 끝냈다는 말과 결과 확인은 다르다

Agent가 결과를 제출하면 조건과 근거를 확인한다. 확인된 결과도 전체 작업에 반영되기 전에는 완전히 닫히지 않는다.

### 9. 요약은 중요한 이견을 지우면 안 된다

반대 근거, 아직 모르는 점, 실패 징후는 짧게 만들기 위해 삭제하지 않는다.

### 10. 자동화가 사람을 더 무력하게 만들면 실패다

사용자는 항상 현재 흐름을 이해하고, 예상하고, 바꾸고, 이의를 제기할 수 있어야 한다.

## 4. Helm이 아닌 것

Helm은 다음을 목표로 하지 않는다.

- 모든 일을 agent에게 넘기기
- 모든 실행을 실시간으로 감시하기
- 모든 선택에 승인 버튼 누르기
- 채팅 기록 전체를 장기 기억이라고 부르기
- agent를 사람처럼 꾸며 신뢰를 유도하기
- 프로젝트 관리 도구, IDE, agent runtime을 모두 대체하기
- 테스트 통과를 올바른 결과와 같다고 보기

## 5. 좋은 사용 경험

사용자는 Helm에서 다음 감각을 얻어야 한다.

- 흩어진 상황이 이해 가능한 모습으로 정리된다.
- 내가 바꾼 기준이 여러 agent의 방향을 실제로 바꾼다.
- 반복 작업을 보지 않아도 중요한 위험은 놓치지 않는다.
- 결과를 단순 승인한 것이 아니라 함께 만들었다고 느낀다.
- 시간이 지나도 다시 시작하는 비용이 낮다.
- 쓸수록 나의 위임 방식과 판단 규칙이 좋아진다.
