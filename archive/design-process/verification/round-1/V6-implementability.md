- 검증자: V6(구현 가능성). 설계 문서 작성에 참여하지 않았다.
- 날짜: 2026-10-12
- 대상: `docs/design/01~26`(2026-10-12 판), 브리프 `process/00-design-brief.md`, 판정 `process/rulings-stage2a.md`
- 행 번호 표기: `12:770`은 `docs/design/12-runtime-engine.md` 770행이다. `브리프 93`은 브리프 93행이다.
- 실험 산출물: `.helm-design-work/V6/` 아래(`compile/`, `pi/`, `ext/`, `wbs/`, `undef/`, 보조 검토 결과 `pkg-core/`, `pkg-runtime/`, `pkg-orch/`, `pkg-clients/`, `plan/`). 표의 [실험]은 이 폴더의 명령으로 재현할 수 있는 결과이고, [소스 대조]는 pi v1.1.0 태그 소스와 비교한 결과다.

## 1. 검토 범위와 방법

질문은 하나였다: 06의 패키지 목록대로 구현자가 이 문서들만 읽고 바로 코드를 쓸 수 있는가. 이를 위해 네 가지를 했다.

1. 패키지별 빈 곳 찾기. 문서가 약 5MB라 보조 검토자 다섯(Opus 5.5 medium)에게 패키지 묶음을 나눴다: 코어(domain·protocol·kernel·store·engine), 런타임(ai·agent·tools·runtime·observer·daemon), 오케스트레이션·탐구(14·15), 클라이언트(client·client-react·desktop·ui-language·ui-tokens·ui·mobile·cli·tui·testkit·vendor), 계획(22·23). 각 보조 결과의 주요 지적은 원문 행을 직접 열어 다시 확인했고, 확인한 것만 아래 표에 넣었다. 심각도는 보조 제안을 그대로 쓰지 않고 이 문서의 정의로 다시 매겼다.
2. 코드 블록 실험(보조 실험자 Sonnet 5.5 medium + 직접). 전 문서의 `ts`·`sql` 블록 324개를 뽑아 TypeBox 1.3.27(`typebox`), TypeScript 6.0.3, better-sqlite3 13.0.3, Node 24.19.0으로 컴파일·적용·실행했다. `npm install`은 `.helm-design-work/V6/compile` 안에서 `--no-workspaces`로 했다.
3. pi 소스 대조(보조 Opus 5.5 medium). 07·12·13·15의 행 번호 인용 105건과 식별자 1,601개를 `~/projects/_ref/pi-src` 태그 v1.1.0과 비교했다(읽기만). `.helm-design-work/P4/fork-proto`의 `tsc`와 테스트를 다시 돌렸다.
4. 외부 기술 주장과 23 의존 검사(직접). bubblewrap 비특권 실행, systemd 사용자 단위, Tauri·crate·npm 판, 23 WBS 의존 그래프·절 참조·테스트 ID를 스크립트로 검사했다.

하지 않은 것: Web Push on iOS 26(실기기 필요), cargo-xwin 교차 빌드(서버에 cargo 없음, 23 HT-06), macOS 키체인 확인 창과 Windows ssh 자식 프로세스(Mac·Windows 필요). 이 항목은 문서의 근거 표기만 읽었다.
