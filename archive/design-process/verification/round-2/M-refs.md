# 2차 검증 M-refs: 문서 간 참조 기계 검사

- 대상: `docs/design/01`~`26` 설계 문서 26개. 읽기만 했다. 설계 문서는 고치지 않았다.
- 기준 집합: 브리프 `docs/design/process/00-design-brief.md` §2 번호 항목 1~57, `docs/design/process/rulings-stage2a.md` J 행 J-01~J-240, 각 문서와 브리프·rulings의 `##`~`####` 제목 번호.
- 검사 수단: `python3 -I` 스크립트(저장소 밖 작업 폴더). git 명령, `.helm/private/` 읽기, 다른 에이전트 호출은 하지 않았다.
- 결과 요약: 실패 144건, 모호 480건, 제외 2,837건. 실패는 종류별로 7절에 있다.

## 0. 판정 규칙

- (1) `NN §x.y`(NN은 01~26): 대상 문서 NN에 같은 번호의 `##`~`####` 제목이 있는지 확인한다. `#####` 이하에만 있는 번호는 따로 표시한다.
- (2) 접두 없는 `§x.y`: 같은 문서에서 확인한다. 앞뒤 문맥이 외부 출처이면 제외한다.
- (3) `J-nn`, `J-nn~J-mm`: rulings 표의 J 행에 있는지 확인한다. 빠진 번호와 중복도 본다.
- (4) `결정 n`, `판정 44~46`: 브리프 §2 번호 1~57에 있는지 확인한다. `결정 1회`처럼 계수로 쓴 표현은 제외한다.
- (5) 문서 ID: ADR, UC, AC, SCR, OQ는 제목·표 첫 칸·목록 머리에 정의가 있는지 확인한다. `NN R-n` 인용은 NN 문서에 R-n 규칙이 정의되어 있는지 확인한다.
- 외부 원전 인용은 제외한다: `v0.3`, `canon`, `helm-canon`, `pi-facts`, `원전`, `감사 보고`, `조사`, `원천`, `foundations`, `friendly`, `docs/v0.3/` 파일 이름.
- 귀속 방식: 명시(`NN §`, 설계 문서 파일 이름), 표 열(머리글 `NN 절`), 추정(표 행 머리 번호, 근접 번호, 목록 `22·23`, 앞 참조 잇기). 추정 귀속이 실패하면 같은 문서에서 다시 본다. 같은 문서에서 통과하면 모호 통과로 낮춘다.
- 모호: 같은 줄에 외부 출처 표지(`canon`, `.md` 파일 이름, `원전` 등)가 있고 귀속이 실패한 항목이다. 실패로 세지 않고 6.2절과 부록 A에 적는다.
- 한계: 접두 없는 `§` 참조의 귀속은 문장 구조로 추정한다. 2절의 실패와 부록 A의 모호 목록은 사람이 한 번 더 확인한다.
