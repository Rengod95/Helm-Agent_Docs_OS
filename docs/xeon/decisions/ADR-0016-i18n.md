# ADR-0016 다국어와 로케일: FormatJS, ICU 메시지, 한국어·영어 기본

## 1. 상태와 날짜

- 상태: accepted
- 날짜: 2026-10-26
- [결정] UI 문자열은 메시지 키 카탈로그로 다루고 한국어와 영어를 기본으로 지원한다. 스택은 FormatJS(`@formatjs/intl`, `react-intl`)와 ICU MessageFormat이다. 모델용 도구 설명은 영어 원문을 쓴다(사용자 결정 2026-10-26, `review.m3-design-inputs` D-M3-27).
- 이 ADR은 `review.m3-plan` M3-39(접근성, i18n·로케일)의 i18n 부분과 `L4.settings-ui.spec`·`L2.workspace.spec`의 언어 방침 미결(수집 U-87, WS-08)을 닫는다.

## 2. 맥락

- M2까지 CLI, 호스트, 데스크톱의 사용자 문자열은 한국어를 코드에 직접 적었다. 영어 사용자를 받으려면 문자열을 코드에서 떼어야 한다.
- 문자열이 생기는 곳은 셋이다. 데스크톱 UI(React 19, ADR-0010), CLI 출력(Bun 프로세스), 호스트·엔진이 만드는 오류와 알림이다. 호스트는 서비스 모드에서 여러 클라이언트를 받으므로(ADR-0006) 호스트가 한 언어로 문장을 만들면 클라이언트마다 다른 로케일을 쓸 수 없다.
- 설정 화면 항목은 F5 설정 스키마 하나에서 생성된다(`F.wire-settings.spec` `SettingUi`). 라벨도 같은 스키마에서 나온다.
- 모델용 도구 설명은 pi 원문(영어)으로 동작이 검증되었고, 포크 diff를 작게 유지한다.
- CLI와 데스크톱이 함께 쓰는 클라이언트 코드는 `xeon/packages/client`에 둔다(ADR-0020). 카탈로그도 두 클라이언트가 함께 쓴다.

## 3. 결정

### 3.1 스택

1. [결정] 메시지 형식은 ICU MessageFormat이다. 복수형, 선택(`select`), 숫자·날짜 인자를 메시지 안에서 표현한다.
2. [결정] 런타임은 FormatJS다. 데스크톱 React 코드는 `react-intl`(`IntlProvider`, `useIntl`, `FormattedMessage`)을 쓰고, CLI와 React 밖 코드는 `@formatjs/intl`의 `createIntl`을 쓴다. 두 경로는 같은 카탈로그와 같은 메시지 형식을 쓴다.
3. [결정] 날짜, 시각, 숫자, 상대 시간은 `Intl` API(`Intl.DateTimeFormat`, `Intl.NumberFormat`, `Intl.RelativeTimeFormat`)로 표시한다. FormatJS의 `formatDate`·`formatNumber`가 같은 API를 감싼다.
4. [결정] 시각은 UTC로 저장하고 전송한다. 지역 시간대 변환은 표시 단계에서만 한다.

### 3.2 카탈로그

1. [결정] 기본 로케일은 한국어(`ko`)와 영어(`en`)다. 카탈로그는 로케일마다 JSON 파일 하나다.
2. [제안] 위치는 `xeon/packages/client/src/i18n/locales/ko.json`, `en.json`이다. 메시지 id는 점 표기(`settings.models.title`)이고, 빌드 단계가 JSON에서 TS id 상수와 인자 타입을 생성한다. 코드는 문자열 리터럴 id 대신 생성된 상수를 쓴다. 없는 id나 인자 불일치는 타입 검사에서 실패한다.
3. [제안] `en.json`이 id 집합의 정본이다. `ko.json`에 없는 id는 검사(`just check`의 카탈로그 대조)가 실패로 보고한다.
4. [결정] 설정 스키마의 `SettingUi.label`·설명은 메시지 키를 싣는다. 설정 화면과 `xeon config` 출력은 같은 키를 카탈로그에서 찾는다(`F.wire-settings.spec` 반영은 M3 F 작업).

### 3.3 로케일 선택

1. [결정] 설정 키 `ui.locale`의 기본값은 `auto`다. `auto`는 OS 로케일을 쓴다. 지원하지 않는 로케일이면 `en`으로 폴백한다.
2. [제안] OS 로케일 출처: 데스크톱은 WebView의 `navigator.languages`, CLI는 `Intl.DateTimeFormat().resolvedOptions().locale`과 `LC_ALL`·`LC_MESSAGES`·`LANG` 환경 변수다.
3. [제안] 메시지 단위 폴백도 `en`이다. 선택한 로케일 카탈로그에 id가 없으면 `en` 문장을 보인다.

### 3.4 호스트 오류와 알림

1. [결정] 호스트와 엔진은 사용자에게 보일 문장을 만들지 않는다. 오류와 알림은 `kind`와 인자(`args`)로 보내고 클라이언트가 카탈로그로 문장을 만든다.
2. [제안] wire 오류의 `message` 필드는 개발자용 영어 진단 문장으로 남긴다. 클라이언트는 `kind`에 맞는 카탈로그 메시지가 있으면 그것을 보이고, 없으면 `message`를 보인다.
3. [결정] 모델용 도구 설명, 시스템 프롬프트의 도구 사용 규칙은 영어로 둔다. 응답 언어 지시는 `M3-new-14`(기본 프롬프트 문안)가 정한다.

### 3.5 이전 작업

- [결정] CLI와 호스트 코드에 직접 적힌 한국어 문자열을 카탈로그로 옮기는 일은 M3 작업이다(`review.m3-plan` M3-39). 데스크톱 문자열도 같은 작업에서 옮긴다.

## 4. 결과

### 4.1 좋은 점

- 영어 추가가 카탈로그 파일 추가로 끝난다. 다른 로케일도 같은 방법으로 더한다.
- 서비스 모드에서 클라이언트마다 다른 로케일을 쓸 수 있다. 호스트 문장이 없기 때문이다.
- ICU 형식은 Crowdin, Lokalise 같은 번역 도구가 그대로 읽는다.
- 메시지 id가 생성 상수라 오타와 인자 누락이 컴파일 단계에서 드러난다.

### 4.2 감수할 점

- 런타임 의존이 늘어난다(`@formatjs/intl`, `react-intl`). 데스크톱 번들과 CLI 바이너리 크기가 커진다. 속도 영향은 M3-29 기준선에서 잰다(ADR-0012).
- 기존 문자열 이전 비용이 M3에 들어간다. 이전 중에는 하드코딩 문자열과 카탈로그 문자열이 섞인다.
- 호스트 오류의 `kind`마다 카탈로그 메시지를 두어야 한다. 새 오류 kind를 더하는 변경은 카탈로그 두 파일도 함께 고친다.

## 5. 대안

| 대안 | 내용 | 판정 | 이유 |
|---|---|---|---|
| 한국어 직접 표기 유지 | 문자열을 코드에 둔다 | 채택하지 않음 | 영어 지원이 코드 전체 수정이 된다 |
| i18next + react-i18next | 키 기반 카탈로그, 자체 보간 형식 | 채택하지 않음 | 기본 보간 형식이 ICU가 아니다. ICU를 쓰려면 플러그인을 더 둔다. 복수형 규칙을 메시지 안에 두는 ICU 방식이 번역 도구와 맞다 |
| Lingui | 매크로 기반 추출, ICU | 채택하지 않음 | 빌드 매크로(Babel·SWC 플러그인)가 Bun 빌드 경로에 하나 더 든다. 생성 id 상수 방식으로 같은 검사를 얻는다 |
| 호스트가 로케일별 문장 생성 | 호스트가 클라이언트 로케일을 받아 문장을 만든다 | 채택하지 않음 | 호스트에 카탈로그와 로케일 상태가 생기고, 한 연결의 로케일 변경이 다른 연결 출력과 섞인다 |

## 6. 미결 사항

- [미결] TUI 설정 화면을 나중에 만들 때 같은 카탈로그를 쓰는 방법(`review.m3-design-inputs` D-M3-30 행 3). 지금은 만들지 않는다.
- [가정] `react-intl`과 `@formatjs/intl`이 Bun `bun build --compile` 산출물과 Tauri WebView에서 추가 polyfill 없이 동작한다. macOS 14 이상 WebKit은 `Intl.PluralRules`, `Intl.RelativeTimeFormat`을 제공한다고 본다. M3 구현 첫 작업에서 확인한다.
- [미결] 카탈로그 생성 스크립트의 위치와 이름(`xeon/scripts/` 아래). M3 /plan에서 정한다.
