# 사용자 결정 기록 (2026-10-19 ~ 2026-10-21)

제품 방향 전환 이후 사용자가 내린 결정을 시간순으로 옮겨 둔 원문 메모다. ADR 작성의 근거로 쓴다.

2026-10-19 사용자가 학습 문서를 읽고 설계 방향이 의도와 다르다고 밝힘.
- 원하는 것: Codex 데스크톱·Claude Code 데스크톱처럼 자체 런타임 기반 에이전트 앱. 내부 계층을 나눠 CLI 버전도 가능하게.
- 사용감은 pi·Hermes Agent 같은 일반 대화형 에이전트와 같고, 탐구·작업 관리가 대화 안에 자연스럽게 섞이는 것이 차별점. oh-my-pi가 pi를 포크한 방식과 같은 맥락.
- Hermes처럼 세션이 쌓일수록 스킬 md, 반복 작업 스크립트, 정적 확장, 메타인지 피드백을 학습해 제안하는 기능 원함.
- 이견: "커널만 상태 변경", 탐구 모드 인라인 강결합, "채팅 기반 에이전트가 아니다", 나만 쓰는 로컬 홈서버 전제.
- 좋다고 한 것: 탐구, 루프 엔진, 런타임.
- 2026-10-19 답: 본인 우선 사용, 나중에 공개 릴리즈 예정(배포 가능한 설계 필요). 첫 지원 OS는 macOS, Linux(WSL 포함). Windows 네이티브는 나중.
- 확장 호스트 후보: Cordis core(npm 4.0.0-rc.11, API 불안정, 커밋 고정 vendoring 전제) 위에 pi 부품·Helm 기능을 서비스로 구성.
- 설계 규칙(사용자 지시): OS·환경마다 달라지는 내부 부분은 공통 인터페이스를 정의하고 OS·환경별로 구현만 바꾼다(소비자 코드에 OS 분기 금지).
- 2026-10-21 구상 변경: 의도를 런타임 1급 단위로 두는 안은 이점이 적다고 판단해 철회. 기능 중심 층(실행·통합·멀티에이전트·지식)은 거의 변하지 않는 코어 플러그인(펀더멘탈 층)으로 두고, Helm 같은 커스텀 기능·사상은 그 위에 '의도 중심 그룹' 플러그인으로 얹는다. 바닥의 태스크 엔진(단계 사이 마이크로태스크, 병렬·비동기, 서브에이전트 처리), 루프층, 단방향 의존 + continuation(replay·resume) 요구는 유지.
- 사용자 의중(2026-10-21): Helm(탐구·새 관점·모르는 분야 지식을 현재 작업에 적용하는 발견 지원)을 스킬·일반 플러그인으로 두면 모델에 강제력이 없어서, 코드 수준에서 루프를 제어하려는 것이 커스텀 루프의 이유. 제2의 Helm 같은 사상도 루프에 붙였다 뗐다(on/off) 할 수 있어야 함. 고민: 확장 지점 설계, 웹 탐색 같은 능력을 그룹 안에 둘지 코어 층에 둘지(그룹 간 강결합 우려).
- 2026-10-21 배포 단위 정정: 배포앱은 Helm 앱이 아니라 층(F~L3) 전체를 제공하는 에이전트 런타임 자체. 사용자가 층별 플러그인·그룹을 마음대로 추가·수정·교체할 수 있어야 함. Helm은 L3 의도 그룹으로 내장되거나 기본 플러그인으로 제공. F~L2는 바퀴 재발명 대신 검증된 오픈소스(pi, oh-my-pi, opencode, Claude Code, Hermes, pi durable)를 최대한 채택해 우리 펀더멘탈에 맞게 녹이고, 설계 노력은 L2·L3 자율 확장 시스템과 제2의 Helm을 쉽게 추가하는 펀더멘탈·스키마에 집중.
- 2026-10-21 결정: pi agent-core 루프는 고정 커밋으로 가져와 자체 유지. provider 위장 경로(pi-ai Anthropic OAuth)는 사용자 뜻으로 유지 — 별도 provider로 분리·기본 꺼짐 제안, 릴리즈 포함 여부는 미정. 웹 도구는 최신 provider 위주(Exa 기본, Parallel·Brave 대체, 로컬 fetch·Playwright). 레퍼런스 조사 아티팩트: https://claude.ai/artifact/6JP1JGeeGqU6wqfbpYh797 (188항목 카탈로그 포함).
- 2026-10-21 층 구성 계획(F 5, L0 6, L1 7, L2 5, X 3, L3 3 하위 층, 구성요소 163개): https://claude.ai/artifact/6Wre6DTnvJgiT4i7qYzbnc. 위장 경로는 "제거" 아님, 유지·분리·기본 꺼짐(사용자 재확인).
- 2026-10-21 결정(2차): 세션 저장 C안 확정(SQLite 이벤트 소싱+투영, 단일 DB, 확장 접두사 테이블). pi-ai provider는 그대로 사용, 부족분만 포크 커스텀(새로 만들지 않음) — 다른 층도 패키지 사용·포크를 적극 채택. 위장 provider는 릴리즈 제외, 별도 커스텀 플러그인으로 제공. 비밀 기본값은 SOPS(age) — 에이전트는 값을 모른 채 참조로 사용, 사용자는 키체인·Bitwarden식 목록/등록/열람/삭제. 웹 유료 API는 사용자가 플러그인으로 등록, 기본값은 브라우저 도구 조사(https://claude.ai/artifact/ULHAHyMTDNjZ3QPaU6okRP) 기반 로컬 도구. 추론 예산·라우팅·레이트 리밋·계정 회전 등은 L4 클라이언트 설정 화면에서 조작 가능해야 함. 확장 프로세스 격리는 기본값 아님 검토, X-b 지점은 pi처럼 단순하게 재설계. 확장 지점 목록(5)·Helm 내부 설계(6)는 층 구성 계획 보완·합의 뒤 착수.
- 2026-10-21 계획 v2(같은 URL): 확장 지점은 on(fold tap/first/chain)·post·drive(배타 임대)·scope 4연산. Hermes 학습 정책은 L3 학습 그룹(drive 미사용, Helm과 공존), 저장은 L2-d. 프로세스는 엔진 라이브러리+단일 호스트 계약+전송 교체(CLI in-process, 데스크톱 자식 엔진), 공유 서비스 모드 2차. 가드레일 보류, 예산은 pi 방식(기본 상한 없음). 남은 결정: pi durable 활용 범위(스파이크 여부), 예약·원격 범위, 데스크톱 셸, goal 판정, 질문·계획 승인 통합, 무료 검색 기본값.
- 데몬 필요 여부는 열려 있음. 제안안은 helm-server 내장/상주 두 모드.

**Why:** 기존 docs/design 01~26은 홈서버 데몬 + 커널 중심 전제라 대규모 재설계 필요.

- 2026-10-21 결정(3차): pi durable은 그대로 쓰지 않고 env·tools·images·truncate만 Chord 제거 포크, DI는 Cordis 하나. 예약·원격·알림 범위 포함(데몬 허용). 데스크톱은 메모리 우선 3플랫폼(Tauri 2). 목표 판정은 별도 판정 모델+상한. 질문 도구와 계획 승인은 승인 프로토콜 하나. 무료 검색 기본값은 foundation-plan.md 1절 6번. 런타임 Bun 1.4, 개별 도구 툴체인(oxlint·oxfmt·tsgo·bun test·turbo). 코드는 xeon/ 독립 워크스페이스, CI 파일 추가 허용. 제품 임시 이름 Xeon.
