## 1. 결론

- 판정: 방안 A는 기술적으로 가능하다. 다섯 요소 가운데 판별식 우회, 시스템 identity, beta 헤더, 도구명 치환 세 곳, 응답 역치환 모두 pi-ai가 공개한 경로로 표현된다. 조건이 세 가지 있다.
  1. 주입은 `stream`에서만 된다. `streamSimple`은 `buildBaseOptions`가 `client`를 버리므로 래퍼가 reasoning 매핑을 가진 자체 `streamSimple`을 둬야 한다 (§3.7).
  2. `onPayload`는 1.3.0에서 재시도 때 다시 호출된다 (`dist:434-470`). 변환은 같은 입력에 같은 출력을 내는 순수 함수여야 한다 (§3.9).
  3. `options.client` 경로는 `options.headers`, `options.fetch`, 세션 헤더를 무시한다 (`소스:610-637`의 else 분기에서만 쓰인다). 래퍼 클라이언트가 원본 OAuth 클라이언트의 헤더 세트를 직접 가져야 한다 (§3.2).
- 판별식 `isOAuthToken`(`소스:978-980`)은 `options.client` 경로에서 평가되지 않는다. 우회된다 (`소스:607-609`, `1014`).
- 방안 A의 분리는 래퍼 경로에만 적용된다. 기본 `anthropic-messages` 경로는 키 접두사만으로 같은 위장 분기에 들어간다 (`소스:1014`). 이 점은 분리의 전제를 바꾼다. Xeon 코어에 가드가 필요하다 (§3.1, §4, 미결 M-1).
- Api id를 새로 만들 필요는 없다고 본다. `createProvider`의 provider별 표로 `anthropic-messages`를 그대로 두고 provider id만 나누면 managed effort 이력(`소스:1456-1460`, `1524`)이 유지된다 [제안] (§3.8).
- 응답 역치환은 래퍼 스트림에서 가능하다. `toolcall_start`에서 블록 `name`을 한 번 되돌리면 같은 객체를 참조하는 후속 이벤트와 `done` 메시지에 반영된다 (§3.6).
- 원본 회귀 테스트 두 개는 위장 요청 형태를 검증하지 않는다. `anthropic-oauth.test.ts`는 로그인·갱신 흐름을, `anthropic-tool-name-normalization.test.ts`는 실 API 도구명 왕복을 본다 (§3.10). 요청 형태 검증은 M-8에서 새로 만들어야 한다. 네트워크 없이 원본 경로와 래퍼 경로의 요청 본문·헤더를 비교하는 테스트를 제안한다 (§5 S5).
- 서버 측 수용 여부와 이용 약관은 이 조사로 확인하지 않았다 ([미확인], §6).

## 3. 요소별 판정

### 3.1 판별식 우회 (`소스:607-609`, `978-980`, `1014`)

- `stream`은 `options.client`가 있으면 SDK 클라이언트를 만들지 않는다 (`소스:607-609`). `isOAuth`는 `false`로 고정된다 (`소스:609`).
- 판별식 `isOAuthToken(apiKey)`(`소스:978-980`, `apiKey.includes("sk-ant-oat")`)는 `createClient`의 OAuth 분기 조건(`소스:1014`)에서만 쓰인다. `createClient`는 `else` 분기(`소스:610-637`)에서만 호출된다(호출 위치 `소스:627`). 따라서 client 주입 경로에서 판별식은 평가되지 않는다. 우회된다.
- 같은 경로에서 `assertRequestAuth`(`소스:613`)도 생략된다. `options.apiKey`는 SDK로 전달되지 않는다.
- 래퍼 클라이언트 생성 규칙 (SDK 0.129.0 기준):
  - `apiKey: null`을 명시한다. 생성자는 `apiKey === undefined`일 때 `ANTHROPIC_API_KEY` 환경 변수를 읽는다 (`SDK:client.js:76-78`). 명시하지 않으면 환경 변수 키가 Bearer 토큰과 함께 나갈 수 있다 [제안].
  - `authToken`을 명시한다. 이 값이 있으면 자격 증명 체인 해석이 일어나지 않는다 (`SDK:client.js:147`, `163-168`). 원본의 `PiAnthropic` 하위 클래스(`소스:335-339`)는 두 값이 모두 null일 때만 필요하다. 래퍼는 항상 `authToken`을 넣으므로 하위 클래스가 필요 없다 [제안, 실측 확인 필요].
  - SDK 인스턴스는 pi-ai가 쓰는 0.129.0과 같은 모듈이어야 한다. 1.3.0은 재시도 판정에 `Anthropic.APIError`의 instanceof를 쓴다 (`dist:459`). 중복 설치가 있으면 판정이 달라진다 [제안].
- [제안] 기본 `anthropic-messages` 경로의 가드. `anthropic-messages` 공개 `stream`은 키 접두사만으로 위장 분기에 들어간다 (`소스:1014`, `dist:803`). 따라서 provider 분리만으로는 기본 경로의 위장이 막히지 않는다. Xeon 코어가 `anthropic-messages` provider 설정에서 `sk-ant-oat` 접두사 키를 거부하거나, pi-ai를 포크해 분기를 제거해야 한다. 기본 꺼짐과 릴리즈 제외([결정] `_research/decisions-log.md` 2026-10-21 결정 2차)는 이 가드가 있어야 실효가 난다. [미결 M-1]

### 3.2 `options.client` 경로에서 빠지는 옵션과 헤더

원본 `createClient`가 처리하던 항목은 client 분기에서 모두 빠진다.

| 항목 | 원본 처리 (소스) | client 경로 | 래퍼가 할 일 |
|---|---|---|---|
| `options.headers` | `createClient`에서 defaultHeaders 병합 (`627`, `mergeClientHeaders` `303-305`) | 무시. `getBetaFeatures`(`1087-1091`)만 `anthropic-beta` 값을 읽는다 | defaultHeaders에 `model.headers`, `options.headers` 순서로 병합. null 억제 규칙 (`types.ts:191-199`) 유지 |
| `options.fetch` | `createClient` 인자로 PiAnthropic에 전달 (`627`) | 무시 | 래퍼 클라이언트에 fetch 전달 |
| 세션 친화 헤더 | API 키 분기 `1038-1039` (`cacheSessionId` `625`) | 무시. 기본값은 OpenRouter 전용 (`소스:220`) | 대상 모델 compat이 요구할 때만 복제 |
| OAuth 클라이언트 헤더 | OAuth 분기 `1014-1033`: `user-agent: claude-cli/2.1.280`, `x-app: cli`, `accept`, `anthropic-dangerous-direct-browser-access` | 없음 | 래퍼 defaultHeaders에 같은 세트를 둔다 |
| `timeoutMs`, `signal`, `maxRetries` | `requestOptions`(`644-648`) | 유지 | 변경 없음 |

- User-Agent 주의: `mergeClientHeaders`는 pi UA(`User-Agent`, `소스:304`)를 먼저 넣고 OAuth UA(`user-agent`, `소스:1025`)를 나중에 넣는다. SDK `buildHeaders`는 객체의 키마다 clear 후 set하므로 뒤 키가 최종값이 된다 (`SDK:internal/headers.js:28-50`, `72-111`). 코드 읽기로 도출한 결과이며 실행하지 않았다 [미확인]. 래퍼는 `user-agent` 한 키만 두어 이 순서 의존을 없앤다 [제안].

### 3.3 시스템 프롬프트 identity (`소스:1167-1190` → onPayload)

- 원본 OAuth 분기 (`소스:1167-1181`): `params.system`을 `[identity, 원문]`으로 만든다. 두 블록 모두 `cache_control`을 가진다 (`1173`, `1180`).
- 원문만 있는 분기 (`소스:1182-1190`): `params.system = [원문(cache_control)]`. client 경로는 `isOAuth = false`이므로 이 분기가 실행된다.
- onPayload 변환:
  - `params.system`이 배열이면 맨 앞에 `{type: "text", text: "You are Claude Code, Anthropic's official CLI for Claude."}`를 넣는다. `cache_control`은 `system[0]`의 값을 복사한다. 원본이 identity 블록에도 `cache_control`을 붙이기 때문이다.
  - `params.system`이 없으면 identity 블록 하나만 두고 `cache_control`을 붙인다. 원본은 `cacheControl`이 있을 때만 붙인다 (`소스:1171-1175`). 래퍼는 `cacheControl`을 다시 계산해야 한다. `getCacheControl`(`소스:79-93`)과 `resolveCacheRetention`(`소스:69-77`)이 모듈 비공개이므로 같은 로직을 복제한다 (약 15줄).
- 판정: 가능하다.

### 3.4 beta 헤더 (`소스:1087-1106`, `1155-1165` → onPayload)

- 원본 `getBetaFeatures`는 `model.headers`와 `options.headers`의 `anthropic-beta`를 먼저 읽는다 (`소스:1087-1091`). 값이 `null`이면 빈 목록을 반환한다 (`소스:1093`). 값이 있으면 그 목록만 쓴다 (`소스:1094-1103`). 값이 없을 때만 기본 목록을 만들고, OAuth면 `claude-code-20250219`, `oauth-2025-04-20`을 맨 앞에 넣는다 (`소스:1106`).
- 결과는 `params.betas`에 들어간다 (`소스:1155-1165`). SDK `beta.messages.create`는 `betas`를 body에서 떼어 `anthropic-beta` 헤더로 보낸다 (`SDK:resources/beta/messages/messages.js:27`, `49`). 따라서 onPayload가 `params.betas`를 고치면 헤더에 반영된다.
- 래퍼: onPayload에서 같은 조건 분기를 복제한다. `anthropic-beta`가 설정된 호출에 OAuth 두 값을 무조건 넣으면 원본과 달라진다.
- 판정: 가능하다. 조건 분기 복제가 필요하다.

### 3.5 도구명 치환 세 곳 (`소스:1347`, `1443`, `1603` → onPayload)

- `toClaudeCodeName`을 쓰는 곳은 세 곳뿐이다 (grep 확인).
  - `1603`: `convertTools`(`소스:1578-1609`). `params.tools`를 만들고, native tool change에서 `tool_addition`의 definition도 이 함수를 거친다 (`소스:1149-1153`, `1213-1225`).
  - `1443`: assistant 이력의 `tool_use.name`.
  - `1347`: native tool change의 `tool_removal`에 든 `tool_reference.name`. 이 경로는 `supportsMidConvoSystemMessages`와 `supportsMidConvoToolChanges`가 모두 켜진 모델에서만 실행된다 (`소스:1140-1141`).
- tool_result에는 name 필드가 없다. 바꿀 곳은 세 종류다: `tools[].name`, `messages[].content[]`의 `tool_use.name`, system 메시지 내 `tool_removal`과 `tool_addition`의 이름 필드.
- 규칙: 17개 이름 표(`소스:101-119`)를 대소문자 무시로 찾아 정식 표기로 바꾼다 (`소스:121`, `124`). 표에 없는 이름은 그대로 둔다. `__pi_deferred_placeholder__`(`소스:204-208`)는 표에 없으므로 바뀌지 않는다.
- 1.3.0 확인: 같은 세 곳이 `dist:1078`, `1175`, `1323`에 있다.
- 판정: 가능하다. 표를 복제하고 CC 버전(2.1.280, `소스:96`)을 함께 고정한다.

### 3.6 응답 역치환 (`소스:727-729` → 래퍼 스트림)

- 원본: `content_block_start`의 tool_use 분기에서 `isOAuth`일 때만 `fromClaudeCodeName(name, currentTools)`를 쓴다 (`소스:727-729`). `currentTools`는 `getCurrentTools(normalizedContext.messages)`다 (`소스:578`, `utils/transcript.ts:58`).
- client 경로는 `isOAuth = false`이므로 역치환이 없다.
- 래퍼에서 가능한 이유: 내부 스트림 이벤트가 같은 `output` 객체와 같은 블록 객체를 참조한다. `toolcall_start`(`소스:735`, `partial: output`), `toolcall_end`(`소스:808-812`, `toolCall: block`), `done`(`소스:885`, `message: output`)이 모두 그렇다. 따라서 래퍼가 `toolcall_start`를 받을 때 `event.partial.content[event.contentIndex].name`을 되돌리면 후속 이벤트와 `result()`에 반영된다.
- 구현: 래퍼는 `AssistantMessageEventStream`(`utils/event-stream.ts:97`)을 새로 만든다. 내부 스트림을 `for await`로 읽어 이벤트를 전달하고, `toolcall_start`에서만 이름을 바꾼다. `done`/`error` 전달 뒤 `end()`를 호출한다 (`소스:885-886`, `895-896` 참조).
- 주의:
  - 역치환 입력 `tools`는 원본과 같은 전사 정규화 결과여야 한다. `resolveTranscript`(`utils/transcript.ts:115`)로 정규화한 뒤 `getCurrentTools`를 적용한다 [확인 필요].
  - `onProviderStreamEvent`의 데이터는 읽기 전용이다 (`types.ts:219-223` 주석). 이 훅에서 바꾸면 안 된다.
- 판정: 가능하다.

### 3.7 streamSimple 경로 (`소스:928-960`, `simple-options.ts:36-65`)

- 원본 `streamSimple`은 `buildBaseOptions`의 결과를 `stream`에 넘긴다. 반환 객체(`simple-options.ts:36-65`)에 `client`가 없다. 따라서 `streamSimple` 호출에서는 client 주입이 사라진다.
- 결과: `streamSimple`에 위임하면 판별식이 다시 평가된다(`소스:1014`). `apiKey`에 `sk-ant-oat`가 있으면 원본 OAuth 분기가 돌고, 래퍼 클라이언트는 쓰이지 않는다. 래퍼의 `streamSimple`은 원본에 위임하면 안 된다.
- 래퍼 `streamSimple`이 복제할 부분:
  - reasoning 매핑 (`소스:936-960`): `mapThinkingLevelToEffort`(`소스:908-925`, 비공개)를 복제한다. `adjustMaxTokensForThinking`(`simple-options.ts:92`)과 `clampMaxTokensToContext`(`simple-options.ts:18`)는 공개되어 있어 재사용한다.
  - `assertRequestAuth`(`소스:325-327`, 비공개)는 `authToken`이 있으면 통과하므로 래퍼에서 생략할 수 있다 [확인 필요].
  - 결과를 `stream`(`소스:571`, export)에 넘긴다. 래퍼 클라이언트를 `options.client`로 전달한다.
- 판정: 가능하다. 약 50줄 복제가 필요하다.

### 3.8 Api id 분리와 provider 분리

- 두 경로가 가능하다.
  - (a) 새 Api id: `registerApiProvider`(`compat.ts:128`, `./compat` 서브패스로 공개). 전역 레지스트리에 등록되며 `wrapStream`이 `model.api === api`를 강제한다 (`compat.ts:109-110`).
  - (b) provider별 표: `createProvider({ api: { "anthropic-messages": streams } })`(`models.ts:1041`). dispatch는 `byApi[model.api]`를 쓰며 전역 레지스트리를 거치지 않는다 (`models.ts:1070`). `providers/openrouter.ts:29`, `github-copilot.ts:29`, `opencode.ts:20`이 같은 방식을 쓴다.
- (a)를 쓰면 생기는 비용:
  - managed effort 이력: `assistantLevels`는 `msg.api === "anthropic-messages"`이고 `msg.provider === managedProvider`인 메시지만 기록한다 (`소스:1456-1460`). 새 Api id의 assistant 메시지는 기록되지 않아 `insertThinkingLevelMessages`(`소스:1524`)가 과거 effort 표식을 빠뜨린다. `supportsMidConvoEffort` 모델에서만 해당한다.
  - compat 스키마: 키가 `"anthropic-messages"`다(`providers/compat-schema.ts:594`). 새 Api id면 스키마를 따로 둬야 한다.
- 두 방식 모두 공통이다: `transform-messages`는 provider, api, model을 모두 비교한다 (`transform-messages.ts:96-98`). provider id를 나누면 교차 전사에서 thinking 서명이 처리되는 방식이 달라진다.
- [제안] (b)를 쓴다. Api id는 `anthropic-messages`로 두고 provider id(예: `anthropic-oauth`)만 나눈다. 전역 `stream(model)`로 래퍼의 Model을 넘기면 원본 레지스트리가 처리하므로, 래퍼 provider 객체만 공개 API로 노출한다. 이 점은 M-2에서 확정한다.

## 4. L1.models.spec 위장 provider 절에 넣을 문장 [제안]

- 위장 경로는 `anthropic-oauth` provider로 분리한다. Api id는 `anthropic-messages`를 그대로 쓰고, `createProvider`의 provider별 표로 연결한다 (§3.8 (b)).
- 위장 경로의 요청은 `options.client`로 주입된 SDK 클라이언트로만 보낸다. `streamSimple`은 원본에 위임하지 않고 자체 구현한다 (§3.7).
- 요청 변환(identity, beta 조건 분기, 도구명 세 곳)은 onPayload의 순수 함수로 구현한다. 재시도 두 번에도 같은 결과여야 한다 (§3.3-3.5, §3.9).
- 응답 역치환은 래퍼 스트림의 `toolcall_start`에서 한다 (§3.6).
- 기본 `anthropic-messages` provider에서 `sk-ant-oat` 접두사 키를 거부하는 가드를 Xeon 코어에 둔다 [제안, 미결 M-1]. 이 가드가 없으면 키만 바꿔 위장 분기에 들어갈 수 있다 (§3.1).
- 릴리즈 제외와 기본 꺼짐은 [결정]이다. 근거: `_research/decisions-log.md` 2026-10-21 결정 2차 ("위장 provider는 릴리즈 제외, 별도 커스텀 플러그인"), `_research/foundation-plan.md` §2 (`plugins/provider-anthropic-oauth/`, 배포 제외).

## 5. L1.models.plan M-8 스파이크 범위 [제안]

- S1. 클라이언트 생성: `apiKey: null`, `authToken`, 헤더 세트(§3.2 표), `model.headers`와 `options.headers` 병합 순서. `user-agent` 한 키만 둔다.
- S2. onPayload 변환기: identity(cache_control 복제와 재계산), beta 조건 분기, 도구명 표와 세 곳 순회. 재시도 두 번에도 같은 결과를 낸다.
- S3. 응답 래퍼: `toolcall_start`에서 역치환. `done`과 `error` 전달, `end()` 호출.
- S4. `streamSimple` 복제: reasoning 매핑, 공개 헬퍼(`adjustMaxTokensForThinking`, `clampMaxTokensToContext`) 재사용.
- S5. 와이어 동등성 테스트 (네트워크 없음): 가짜 `sk-ant-oat` 키로 원본 `stream`을 `options.fetch` 캡처와 함께 실행하고, 래퍼를 같은 컨텍스트로 실행한다. 두 요청의 URL, 헤더(`authorization` 값 제외, `user-agent`, `anthropic-beta`, `anthropic-version`, `x-app`, `accept`, `anthropic-dangerous-direct-browser-access`), 본문(JSON 구조 동등)을 비교한다. 캡처 fetch는 오류 응답을 준다. 원본 `requestOptions`의 `maxRetries: 0`(`소스:644-648`)이 재시도를 막는다.
- S6. 단위 테스트:
  - 도구명 표: 대소문자 변형, 표에 없는 이름, placeholder 이름 보존.
  - beta 조건 분기: `anthropic-beta` 값이 `null`, 값 있음, 없음의 세 경우.
  - identity cache_control: 원문이 있을 때와 없을 때.
  - 역치환: 이벤트 순서, `result()`에 반영되는지.
- S7. 실 토큰 스모크 (수동, 선택): `anthropic-tool-name-normalization.test.ts`의 `todowrite` 케이스를 래퍼 provider로 한 번 돌린다. [미확인] 서버 수용 여부.
- S8. 기준 버전은 1.3.0으로 고정한다. M-8 문서에 1.1.0 줄 번호를 쓰지 않는다.

## 6. [미확인] 과 미결 사항

[미확인]
- 서버 측 수용: OAuth 토큰 요청의 identity, beta, 도구명 조합을 Anthropic 서버가 받아들이는지. 실 토큰이 필요하므로 이 조사에서 실행하지 않았다.
- 이용 조건: Anthropic 공식 문서의 구독 OAuth 토큰 사용 조건을 확인하지 않았다. 릴리즈 포함 여부를 정하기 전에 확인이 필요하다.
- 1.3.0 `getBetaFeatures`의 `anthropic-beta` 조기 반환 세부 (`dist:856-870`)는 위치만 확인했다.
- 래퍼가 `resolveTranscript`로 만든 `tools`가 원본과 같은지.
- 래퍼 SDK 인스턴스와 pi-ai의 SDK 인스턴스가 같은 모듈인지. 중복 설치 여부.
- 헤더 최종값: `user-agent` 중복 키의 최종값은 SDK 읽기 결과다. 실행으로 확인하지 않았다.
- cache_control 블록 수: identity에 `cache_control`을 붙이면 system 쪽 breakpoint가 2개가 된다. 원본 OAuth와 같다. messages 쪽과 합산한 최대 breakpoint 수는 확인하지 않았다.

[미결]
- M-1: 기본 `anthropic-messages` 경로의 `sk-ant-oat` 자동 분기를 막는 가드를 Xeon 코어(provider 설정 단계)에 둘지, pi-ai를 포크해 분기를 제거할지. 정본 문서와 ADR 대상이다.
- M-2: provider 분리 방식. (a) 새 Api id, (b) provider별 표로 Api id 유지. 이 노트는 (b)를 제안한다.
- M-3: 위장 provider의 활성화 문구와 설정 노출(L4). 기본 꺼짐 상태에서 켜는 절차를 정한다.
