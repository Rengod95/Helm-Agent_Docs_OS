# L0-3 조사: SOPS_AGE_KEY_CMD 동작과 OS별 키체인 조회 수단

- 대상: sops 3.10 이상의 `SOPS_AGE_KEY_CMD`(호출 시점, 복호화마다 호출 여부, 출력 형식, 수신자 환경 변수), 3플랫폼 키체인 조회 수단, sops Windows 바이너리, `@napi-rs/keyring` 2.1.2의 Bun 로드 여부.
- 근거 계획: `_research/foundation-plan.md` §2 비밀 행(승인 계획), `_research/secrets.md` §3.2·§7, `_research/packages.md` §4.2 L0-c 행, `_research/decisions-log.md` 11행(첫 지원 OS).
- 성격: 조사 결과. 정본이 아니며 인용용이다. 소스는 태그별 raw 파일을 내려받아 읽었다. 패키지는 설치하지 않았고, 내려받은 코드는 실행하지 않았다. 키체인 조회도 하지 않았다.
- 표지: [결정] 승인 계획·사용자 결정 인용, [제안] 작성자 설계 선택, [가정] 확인하지 않은 전제, [미결] 사용자 확인 필요, [미확인] 확인하지 못한 것.
- 인용 약칭: `age@T`는 `https://raw.githubusercontent.com/getsops/sops/T/age/keysource.go`, `ks@T`는 `.../T/keyservice/server.go`, `sops@T`는 `.../T/sops.go`, `cmd@T`는 `.../T/cmd/sops/common/common.go`다. `T`는 태그이고, 숫자는 그 파일의 행이다.

## 0. 결론

1. `SOPS_AGE_KEY_CMD`는 3.10.0에서 처음 들어왔다. 커밋 eea4b7bb76(2025-03-24)은 v3.9.4에 없고 v3.10.0에 있다. 릴리스 노트 v3.10.0의 "Added SOPS_AGE_KEY_CMD option to age" 항목(PR #1811)이 근거다. 계획과 `secrets.md` §3.2의 "3.10.0 이상"은 맞다.
2. 명령은 복호화 경로에서만 실행되며, 복호화 요청마다 실행된다. 같은 파일의 age 수신자를 여러 개 시도하면 시도마다 다시 실행된다. 프로세스 사이에는 캐시가 없다.
3. 출력은 줄마다 identity 하나다. `AGE-SECRET-KEY-1…`을 받고, 3.12.0부터 `AGE-SECRET-KEY-PQ-1…`와 `AGE-PLUGIN-…`도 받는다. 빈 줄과 `#` 줄은 무시한다.
4. 수신자 환경 변수 `SOPS_AGE_RECIPIENT`는 3.10.0과 3.11.0에 없다. 3.12.0부터 명령에 전달된다. `secrets.md` §3.2의 "수신자는 SOPS_AGE_RECIPIENT로 전달된다"는 3.12.0 이상에서만 맞다.
5. 명령은 셸 없이 실행된다. 파이프, 리다이렉트, `~`, `$VAR`이 동작하지 않는다. 인자 분리기 google/shlex는 따옴표 밖과 큰따옴표 안의 `\`를 이스케이프로 읽는다. Windows 경로를 그대로 쓰면 백슬래시가 사라진다.
6. 3.10.x에서는 명령이 실패하면 `SOPS_AGE_KEY_FILE`이 유효해도 복호화가 즉시 실패한다. 실패를 모아 두고 복호화가 끝내 실패했을 때만 보고하는 동작은 3.11.0부터다.
7. macOS는 `security find-generic-password -s <서비스> -a <계정> -w`로 조회한다. Linux의 `secret-tool lookup`은 Secret Service를 요구하므로 WSL과 헤드리스에서는 쓸 수 없다고 봐야 한다. 이 환경에는 파일 키나 명시적 폴백이 필요하다.
8. `cmdkey`는 암호를 보여 주지 않는다. PowerShell 내장 cmdlet에는 자격 증명 읽기가 없다. 필요하면 Win32 `CredReadW`를 P/Invoke하거나 헬퍼 실행 파일을 둔다. Windows 네이티브는 2026-10-19 결정에 따라 후순위다.
9. sops Windows 바이너리(`.exe`, amd64·arm64)는 v3.10.0과 v3.13.3 릴리스에 있다.
10. `@napi-rs/keyring` 2.1.2의 Bun 로드는 [미확인]이다. Bun 문서는 대부분의 N-API 확장이 동작한다고만 말한다. napi.rs는 Bun을 best effort로 분류하고 Bun 테스트를 `continue-on-error`로 둔다. 내려받은 코드를 실행하지 않는다는 조건 때문에 실제 로드는 시험하지 못했다.
11. [제안] `packages.md` §4.2 L0-c 행의 "WSL·헤드리스는 파일 폴백"에는 조건이 붙어야 한다. `@napi-rs/keyring`은 Linux에서 Secret Service가 없으면 조용히 keyutils로 넘어간다. keyutils는 커널 메모리에만 있고 재부팅하면 사라진다. 스토어를 `secret-service`로 고정하고 실패를 직접 처리해야 한다.

## 1. 확인 범위와 방법

- 1차 자료: getsops/sops 태그 v3.10.0, v3.11.0, v3.12.0, v3.12.1, v3.13.0의 raw 소스(`age/keysource.go`, `keyservice/server.go`, `sops.go`, `cmd/sops/common/common.go`)와 main 브랜치의 같은 파일. 태그 포함 여부는 GitHub compare API로 확인했다. 릴리스 항목은 GitHub releases API로 확인했다.
- 공식 문서: `https://getsops.io/docs/usage/identities/age/`. WebFetch로 읽었다. 요약 도구의 결과라서 인용 문구는 원문 대조를 거치지 않았다 [미확인].
- README: getsops/sops 저장소의 `README.rst`는 문서를 getsops.io로 넘기는 짧은 파일이다. `SOPS_AGE_KEY_CMD`는 없다.
- 2차 자료: macOS `security` man 페이지는 미러(`keith.github.io/xcode-man-pages`)를 읽었다. `secret-tool`은 GNOME libsecret의 `tool/secret-tool.c` raw를 읽었다. `@napi-rs/keyring` README는 npm 레지스트리 메타데이터의 `readme` 필드와 GitHub 미러를 대조했다. Microsoft Learn(cmdkey, CredReadW)과 keyring-rs README는 원문을 가져왔다.
- 검색 결과만 확인한 항목: WSL·헤드리스의 Secret Service 상태, PowerShell의 CredentialManager 모듈과 P/Invoke 예제. 이 항목들은 [미확인]이다.
- 하지 않은 것: 패키지 설치, sops 실행, 키체인 조회, Bun 실행.

## 2. SOPS_AGE_KEY_CMD

### 2.1 도입 버전 (태그 포함 관계)

| 변경 | 커밋 | 포함 여부 |
|---|---|---|
| `SOPS_AGE_KEY_CMD` 도입 (PR #1811) | eea4b7bb76 (2025-03-24) | v3.9.4 미포함, v3.10.0 포함 |
| 명령 실패를 모아 두고, 복호화 실패 시에만 보고 | c122e0c1a7 (2025-08-06), e1995e1c78 (2025-09-11) | v3.10.2 미포함, v3.11.0 포함 |
| 명령에 `SOPS_AGE_RECIPIENT` 전달 | e86db7cf72 (2026-01-22) | v3.11.0 미포함, v3.12.0 포함 |
| 하이브리드(PQ) age identity 지원 | 2dc62b8182 (2026-01-11) | v3.12.0 포함 |

- v3.12.0은 태그만 있고 GitHub 릴리스 항목이 없다 [미확인: 릴리스 페이지 상태]. v3.12.1(2026-02-22)에는 포함된다.
- 최신 릴리스는 v3.13.3(2026-07-23)이다.
- 공식 age 문서 페이지는 `SOPS_AGE_KEY_CMD`의 버전 요구를 밝히지 않는다(WebFetch 요약 기준).

[제안] 최소 버전을 3.12.0으로 고정한다. 3.10.x와 3.11.x는 수신자 전달이 없고 실패 처리가 엄격하다. 실사용 기준은 3.13.3으로 둔다. [미결] 버전 고정은 사용자 확인이 필요하다.

### 2.2 호출 시점과 횟수

- 호출 지점은 복호화 경로뿐이다. `age@v3.10.0:201`(`Decrypt`)과 `age@v3.13.0:248`만 `loadIdentities()`를 부른다. 암호화 경로는 수신자 공개키만 쓴다.
- 복호화 흐름: `sops@v3.10.0:827-862`의 `GetDataKeyWithKeyServices`가 키 그룹을 순회한다. `decryptKeyGroup`(`sops@v3.10.0:867-880`)은 그룹 안의 키를 정렬된 순서로 시도하고, 첫 성공에서 멈춘다.
- 로컬 키서비스는 요청마다 새 `age.MasterKey`를 만든다(`ks@v3.10.0:135-142`, `ks@v3.13.0:161-167`). 이 객체의 `parsedIdentities`는 비어 있으므로 `loadIdentities()`가 다시 실행된다.
- 데이터 키는 `Metadata.DataKey`에 캐시된다(`sops@v3.10.0:828-830, 860`). 이 캐시는 한 파일을 처리하는 한 프로세스 안에서만 유효하다.
- 정리: 파일 하나를 수신자 하나로 복호화하면 프로세스당 1회 실행된다. 같은 파일에서 수신자 k개를 차례로 시도하면 최대 k회 실행된다. 파일 N개를 각각 처리하면 파일마다 실행된다.
- [가정] 키체인 조회가 호출마다 일어나므로 macOS에서는 호출마다 접근 승인 창이 뜰 수 있다. 확인하지 않았다 [미확인].

### 2.3 실행 방식

- 3.10.0: `shlex.Split` 뒤에 `exec.Command(args[0], args[1:]...).Output()`을 실행한다(`age@v3.10.0:318-327`). 환경은 부모로부터 그대로 상속된다.
- 3.12.0 이상: `getOutputFromCmd`가 `cmd.Env = append(os.Environ(), "SOPS_AGE_RECIPIENT=<수신자>")`를 설정한다(`age@v3.13.0:300-311, 440-445`; 3.12.0은 `age@v3.12.0:309, 430`).
- 셸을 거치지 않는다. 표준 출력 전체를 메모리에 모은 뒤 파싱한다(`cmd.Output()`).
- 인자 분리 규칙(google/shlex `shlex.go`):
  - 따옴표 밖의 `\`는 다음 글자를 문자 그대로 만든다(226-230행, 279-286행).
  - 큰따옴표 안에서도 `\`가 같은 역할을 한다(297-305행, 330-333행).
  - 작은따옴표 안은 이스케이프가 없다(340행).
  - 따라서 `C:\Users\me\key.exe`는 `C:Usersmekey.exe`가 된다. 작은따옴표로 감싸거나 `/`를 쓰면 된다. [가정] 상태 기계를 읽은 결과다. Windows에서 실행해 확인하지 않았다 [미확인].
- 셸 기능이 필요하면 실행 파일 하나를 두고 그 안에서 처리한다 [제안].

### 2.4 오류 처리

- 3.10.0: 명령 실패는 `loadIdentities`가 즉시 반환하는 오류다(`age@v3.10.0:323-325`). 이 함수는 키 파일을 읽기 전에 끝난다. 따라서 `SOPS_AGE_KEY_FILE`이 유효해도 복호화가 실패한다.
- 3.11.0 이상: 오류를 `errs`에 모은다(`age@v3.11.0:385-387`, `age@v3.13.0:443`). 다른 출처의 키가 맞으면 복호화가 성공한다. 실패 보고는 복호화가 끝내 실패했을 때만 낸다(c122e0c1a7, e1995e1c78).

### 2.5 출력 형식

- 줄마다 identity 하나다. 빈 줄과 `#`로 시작하는 줄은 건너뛴다(`age@v3.10.0:399`, `age@v3.13.0:535`).
- 허용 접두어는 `AGE-PLUGIN-`(플러그인 identity), `AGE-SECRET-KEY-PQ-1`(3.12.0 이상), `AGE-SECRET-KEY-1`(X25519)이다(`age@v3.13.0:562-570`, `age@v3.10.0:414-420`). 그 밖의 줄은 `unknown identity type` 오류다.
- `SOPS_AGE_KEY_CMD` 출력은 `allowMultipleKeysPerLine: false`로 읽는다(`age@v3.13.0:440-447`). 한 줄에 여러 키를 공백으로 구분하는 형식은 `SOPS_AGE_KEY`에만 쓴다. 이 기능은 커밋 ddeaad2c02(2026-05-03)에서 들어왔다.
- 줄 끝 공백은 제거되지 않는다. 키 줄 뒤에 공백이 붙으면 파싱이 실패할 수 있다. [가정] `parseIdentity`가 입력을 trim하지 않는 것은 소스로 읽었다. 실행 확인은 없다.

### 2.6 수신자 환경 변수 호환

- 3.12.0 이상: 명령은 `SOPS_AGE_RECIPIENT`(Bech32 공개키)에 맞는 키 하나만 출력할 수 있다.
- 3.10.0과 3.11.0: 변수가 없다. 명령은 가진 identity를 전부 출력해야 한다. age는 여러 identity 중 맞는 것을 고르므로(`age@v3.10.0:211`) 전부 출력해도 복호화된다.
- [제안] 명령은 변수가 있으면 그 키만, 없으면 전부 출력한다. 이 방식은 3.10.x와 3.11.x에서도 동작한다.

### 2.7 키 파일 기본 경로 (정정)

- 공식 문서: Linux는 `$XDG_CONFIG_HOME/sops/age/keys.txt`를 먼저 보고, 없으면 `$HOME/.config/sops/age/keys.txt`를 쓴다. macOS도 `$XDG_CONFIG_HOME`이 먼저이고, 없으면 `$HOME/Library/Application Support/sops/age/keys.txt`다.
- `secrets.md` §3.2는 macOS에서 XDG 우선순위를 빠뜨렸다. 근거는 커밋 a27ea2013e(2023-09-21, "On macOS, prefer XDG_CONFIG_HOME over os.UserConfigDir()")다.

## 3. 3플랫폼 키체인 조회 수단

| 플랫폼 | 조회 수단 | 확인 내용 | 한계 | 판정 |
|---|---|---|---|---|
| macOS | `security find-generic-password -s <서비스> -a <계정> -w` | `-w`는 "Display the password(only) for the item found."(man 미러). 줄바꿈 여부는 기재되지 않았다 | 키체인 접근 승인 창 여부 [미확인] | 사용 가능. 줄바꿈이 있어도 sops는 줄 단위로 읽으므로 영향이 없다 |
| Linux (WSL 포함, 첫 지원 OS) | `secret-tool lookup <속성> <값>` (libsecret) | 출력 끝 줄바꿈은 stdout이 tty일 때만 붙는다(`secret-tool.c:215-224`, 호출 247행) | Secret Service(D-Bus `org.freedesktop.secrets`)가 없으면 실패 | 데스크톱 Linux에서는 가능. WSL·헤드리스는 [미확인] |
| Linux 대안 | @napi-rs/keyring `Entry` + `{ linux: { store: 'secret-service' } }` | 자동 선택은 Secret Service → keyutils 순이다. 고정하면 Secret Service가 없을 때 생성자가 throw한다(README) | 자동 선택 시 keyutils는 메모리에만 있고 재부팅 후 사라진다(README) | 헬퍼 실행 파일에서 쓴다 [제안] |
| WSL·헤드리스 | 파일 폴백 (`SOPS_AGE_KEY_FILE` 또는 기본 `keys.txt`) | 파일 기반 키는 sops가 직접 읽는다 | 평문 키가 디스크에 놓인다. sops의 키 파일 권한 검사 여부 [미확인] | 명시 설정으로만 켠다 [제안] |
| Windows 네이티브 | §3.3 | 후순위 | — | §3.3 |

- WSL 기본 배포판에는 세션 버스와 Secret Service 공급자가 없는 것으로 알려졌다. 검색 결과에 근거한 내용이라 [미확인]이다.
- `age/encrypted_keys.go`(패스프레이즈로 보호된 identity 파일)가 v3.10.0에 있으나, `keysource.go`에서 참조되지 않는다(grep 기준). sops의 키 로딩 경로에 연결되는지는 [미확인]이다.

### 3.3 Windows 네이티브 (후순위)

- `cmdkey`는 암호를 읽을 수 없다. `/list`는 "Displays the list of stored user names and credentials"만 하고, 암호를 보여 주는 옵션은 없다(MS Learn cmdkey). 조회 수단으로 쓸 수 없다.
- PowerShell 내장 cmdlet에는 자격 증명 읽기가 없다. `Get-StoredCredential`은 CredentialManager 모듈(서드파티)의 함수다(검색 결과, [미확인]).
- Win32 `CredReadW(TargetName, Type, Flags, &Credential)`은 현재 로그온 세션의 자격 증명 집합에서 읽는다. 실패 코드로 `ERROR_NOT_FOUND` 등을 반환한다(MS Learn CredReadW). `Add-Type`으로 P/Invoke하는 방식은 검색 결과에만 있고 실행하지 않았다 [미확인].
- @napi-rs/keyring 2.1.2의 optional 의존성에는 `win32-x64-msvc`, `win32-ia32-msvc`, `win32-arm64-msvc`가 있다(npm 메타데이터). keyring-rs README는 Mac·Windows·\*nix 기본 저장소를 다룬다고 적는다. Windows 백엔드의 이름은 @napi-rs/keyring README에 없다 [미확인].
- [미결] 헬퍼를 PowerShell P/Invoke로 쓸지, Bun 컴파일 헬퍼와 @napi-rs/keyring으로 쓸지는 Windows 네이티브에 착수할 때 정한다. 2026-10-19 결정에 따라 지금은 정하지 않는다(`_research/decisions-log.md` 11행).

## 4. sops Windows 바이너리

- v3.10.0 릴리스에 `sops-v3.10.0.amd64.exe`, `sops-v3.10.0.arm64.exe`가 있다(releases API assets).
- v3.13.3(2026-07-23)에도 `sops-v3.13.3.amd64.exe`, `sops-v3.13.3.arm64.exe`가 있다.
- 서명 검증 절차(cosign, SLSA)는 릴리스 노트에 있다. Windows에서 실행하지 않았다 [미확인].

## 5. @napi-rs/keyring 2.1.2의 Bun 로드

- npm 메타데이터: 2.1.2는 2026-10-19T08:30:36Z에 게시되었다. MIT, `main: index.js`, `types: ./index.d.ts`, engines `node >= 10`이다. `napi.targets`에는 x86_64·aarch64 darwin, linux gnu·musl, windows msvc, freebsd x64, riscv64, armv7 등이 있다. optional 의존성은 플랫폼 패키지 12개다.
- N-API 빌드다. Bun 문서(`oven-sh/bun` `docs/runtime/node-api.mdx`)는 `require()`와 `process.dlopen()`으로 `.node` 파일을 읽는다고 적고, "most existing Node-API extensions work with Bun out of the box"라고만 말한다.
- napi.rs 지원 페이지는 Bun을 "Best effort"로 분류한다. napi-rs CI의 Bun 테스트 단계는 `continue-on-error`라서 Bun 실패가 릴리스를 막지 않는다. 페이지는 "Test your actual addon before claiming support."라고 적는다.
- 검색으로 찾은 Bun 관련 이슈는 오래된 것뿐이다(`oven-sh/bun` issue #158 등). 현재 상태는 [미확인]이다.
- 판정: Bun 로드 가능 여부는 [미확인]이다. 설치와 실행을 하지 않았다. [제안] 검증 절차: 격리된 디렉터리에서 `bun`으로 `require`를 시도하고, `Entry`의 set·get·delete를 Linux(Secret Service 있음·없음), WSL, macOS에서 각각 실행한다.
- [제안] `packages.md` §4.2 L0-c의 "그대로" 판정은 Bun 검증이 끝날 때까지 "조건부"로 바꾼다.

## 7. 설계에 주는 함의

- [제안] sops 최소 버전을 3.12.0으로 고정한다. 실사용 권고는 3.13.3이다. [미결] 사용자 확인.
- [제안] `SOPS_AGE_KEY_CMD`에는 xeon 헬퍼 실행 파일 하나를 지정한다. 헬퍼가 키체인을 조회하고, `SOPS_AGE_RECIPIENT`에 맞는 키만 출력한다. 키체인 조회 코드가 한 곳에 모인다.
- [제안] `SOPS_AGE_KEY`(키 값을 환경 변수로 전달)는 피한다. sops는 `os.Environ()`을 키 명령에 그대로 넘긴다(`age@v3.13.0:309`).
- [제안] 실패 경로 테스트를 둔다. 헬퍼 실패 후 파일 폴백으로 복호화가 되는지를 3.11 이상에서 확인한다.
- [가정] 복호화 한 번에 키체인 조회가 한 번 이상 일어난다. 호출 횟수와 지연은 §2.2 기준으로 설계한다.
