# X-3. pi 예제 확장의 API 사용 빈도와 어댑터 지원 범위

정본 아님. X 확장 체계의 어댑터 지원 표(지원·부분·비지원)를 정할 때 인용한다. 집계 대상은 pi 예제 확장 79개 단위다.

## 0. 조사 기준과 범위

- 질문: pi 예제 확장이 실제로 쓰는 ExtensionAPI·ExtensionContext 멤버와 import 지정자를 빈도로 집계하면 어댑터 지원 표의 범위가 어디까지인가. 특히 `event.input` 제자리 수정, `ctx.ui` 커스텀 컴포넌트, 명령 전용 세션 제어의 예제 수와 가상 모듈 목록을 확인한다.
- 기준 경로 `PI`는 `/home/user/projects/_ref/pi-src/packages/coding-agent`다. 본문의 `PI/...` 경로는 이 기준이다.
- 집계 단위: `PI/examples/extensions/`의 최상위 `.ts` 파일 또는 디렉터리 하나를 확장 단위로 쓴다. 단위는 79개이고 코드 파일은 86개(`.ts`·`.js`)다. `doom-overlay/doom/build/doom.js`(emscripten 산출물)는 파싱하지 않았다.
- 빈도는 멤버나 지정자를 한 번이라도 참조한 확장 단위 수다. 호출 횟수는 세지 않았다.
- 방법: 정적 텍스트 검색(Python 정규식, grep으로 교차 확인). 공장 함수의 인자 이름은 전부 `pi`다(`PI/examples/extensions/*`에서 `(pi: ExtensionAPI)` 80건). 핸들러의 컨텍스트 인자는 `ctx`, `_ctx`, `*Ctx`로 적는다. 옵셔널 체이닝(`ctx?.ui`)도 셌다. 대괄호 동적 접근(`pi[...]`, `ctx[...]`)은 0건이다.
- 실행: 예제를 실행하거나 빌드하거나 설치하지 않았다.
- 1차 자료: `PI/src/core/extensions/types.ts`, `PI/src/core/extensions/loader.ts`, `PI/src/core/extensions/virtual-modules.ts`, 공식 문서 `PI/docs/extensions.md`의 105·214–215·244–250행.
- 줄 범위(`types.ts`): ExtensionUIContext 149–300, ExtensionContext 325–365, ExtensionToolContext 383–395, ExtensionCommandContext 401–435, InputEventResult 1156–1159, ToolCallEventResult 1426–1435, ExtensionAPI 1564–1890.
- [가정] 예제 집합이 실제 사용 패턴을 대표한다고 본다. 예제는 교육용이므로 특정 기능을 과대 또는 과소하게 보일 수 있다.
- 재현 스크립트는 세션 임시 디렉터리에 있다: `/tmp/claude-1000/-home-user-projects-helm/18be0c42-9f6e-4c80-8aa6-91ac9c0b15e2/scratchpad/x3_count.py`, `x3_count2.py`. 저장소에는 넣지 않았다.

## 1. 요약

1. 확장 79개 단위가 모두 `@earendil-works/pi-coding-agent`를 import한다. 런타임 값을 가져오는 단위는 24개이고, 값 export는 33종이다. 이 표면이 어댑터의 가장 넓은 지원 범위다.
2. 이벤트는 41개 중 24개(59%)만 쓰인다. ExtensionAPI 메서드는 31개 중 23개만 쓰인다. 쓰이지 않는 항목은 공식 타입에 계약으로 남아 있으므로, 지원 표에서 "예제 근거 없음"과 "계약 없음"을 나눠 적어야 한다.
3. 명령 전용 세션 제어의 실제 호출은 2건이다. `newSession` 1건(handoff), `reload` 1건(reload-runtime)이다. `waitForIdle`, `fork`, `navigateTree`, `switchSession`, `getSystemPromptOptions`는 0건이다.
4. `event.input` 제자리 수정은 예제 0건이다. `tool_call` 핸들러 4건은 읽기와 `block: true`만 쓴다. 제자리 수정은 `types.ts:1427`과 `docs/extensions.md:105`에 계약으로 적혀 있다.
5. `ctx.ui.custom`은 15단위가 쓴다. TUI 컴포넌트 계열 6종 또는 `pi-tui` 값 import를 쓰는 단위는 합집합 32개(79단위의 40.5%)다. 공식 문서는 RPC 모드가 커스텀 터미널 컴포넌트를 전달하지 않는다고 적는다(`docs/extensions.md:250`).
6. 가상 모듈은 키 20개, 실체 모듈 9개다. 예제의 import 빈도는 `pi-coding-agent` 79, `pi-tui` 25, `pi-ai` 14, `typebox` 12, `pi-agent-core` 3 순이다. `@sinclair/typebox`와 `@mariozechner/*` 키는 예제에서 쓰이지 않는다.

- `newSession` 1단위: `handoff.ts:81`의 `pi.registerCommand("handoff", …)` 핸들러(`handoff.ts:83`) 안에서 `ctx.newSession({`(`handoff.ts:177`)를 부른다. 같은 핸들러는 `ctx.mode !== "tui"` 가드(`handoff.ts:84`)를 먼저 둔다.

## 4. 설계 시사 [제안]

- 지원 범위의 기준은 "예제 근거와 공식 타입 계약의 합집합"으로 잡는다. 예제만 쓰면 `event.input` 제자리 수정처럼 계약은 있으나 예제가 없는 항목이 빠진다. 계약만 쓰면 예제가 실제로 쓰는 가상 모듈 표면(§2.9)이 빠진다.
- 가상 모듈 표면은 메서드 표면보다 실사용 근거가 많다. 79단위 전부가 `pi-coding-agent`를 import하므로, 어댑터는 이 패키지가 내보내는 값 33종과 타입 목록을 먼저 확정해야 한다.
- TUI 의존(32단위, 40.5%)은 CLI와 데스크톱을 나누는 설계와 직접 관련된다. foundation 계획 §1 3번(데스크톱 Tauri 2, stdio JSON-RPC)과 함께 판단해야 한다.
- [결정] `docs/xeon/_research/decisions-log.md`의 2026-10-21 결정(2차)은 "X-b 지점은 pi처럼 단순하게 재설계"라고 적는다. 이 집계에서 pi 예제가 쓰는 이벤트는 41개 중 24개이므로, 지점 수를 줄이는 근거로 쓸 수 있다.
- 명령 전용 제어 5종이 예제에서 거의 쓰이지 않는 점은 명령 컨텍스트를 나누는 비용을 낮춰도 된다는 근거다. 다만 공식 문서는 그 이유를 교착 위험으로 적으므로(`docs/extensions.md:215`), Xeon의 drive와 scope가 같은 위험을 막는지 확인해야 한다 [미확인].

## 5. 미결 사항 [미결]

1. TUI 컴포넌트 계열(24단위)과 `pi-tui` 값 import(25단위)를 CLI 전용 호환 층으로 둘지, 비지원으로 둘지.
2. 명령 전용 제어 5종과 `newSession`·`reload`를 지원 범위에 넣을지, drive 설계로 대체할지.
3. `registerProvider` 2건이 foundation 계획의 위장 provider 분리 결정과 어떻게 연결되는지. 두 예제가 위장 경로와 관련되는지는 확인하지 않았다 [미확인].
4. pi-coding-agent 도구 팩토리 15종을 L2 workspace·tools 계약에 어떻게 대응할지.
5. `registerVirtualModel` 1단위(라우팅 예제)를 X 확장 지점 중 어디에 대응할지.

## 6. 확인하지 못한 것 [미확인]

- 예제의 실행 결과. 실행하지 않았다.
- 참조 빈도 기준의 한계. 단위 수는 참조 여부만 본다. 실행 경로, 조건부 분기, 죽은 코드는 구분하지 않는다.
- 외부 npm 패키지(`@anthropic-ai/sdk`, `ms`, `@earendil-works/gondolin`, `@anthropic-ai/sandbox-runtime`)의 설치 상태와 버전.
- `@mariozechner/*` 별칭의 용도. 소스에 설명이 없다.
- pi 쪽 typebox 1.3.27과 Xeon의 TypeBox 1.4 사이의 호환성.
- pi-src 체크아웃 자체의 버전. Xeon 계획의 pi-ai·pi-agent-core 1.3.0 고정이 체크아웃과 같은지는 확인하지 않았다.
- 공식 문서의 나머지 절. 이 노트는 105·214–215·244–250행만 읽었다.
- `input` 이벤트에 제자리 수정 계약이 없다는 판단은 `types.ts:1143–1159`의 타입 정의와 `docs/extensions.md`에 그런 문장이 없다는 확인에 근거한다.
