# L2-2 조사: playwright-core의 Bun 1.4 호환과 agent-browser JSON CLI 계약

- 대상 질문
  - (1) playwright-core 1.64.1이 Bun 1.4에서 브라우저 실행, CDP 연결, 접근성 스냅샷 호출까지 동작하는가. 불가하면 Node 자식 프로세스 우회가 필요한 범위는 어디인가.
  - (2) agent-browser 0.39.1이 외부 프로세스 provider로 쓸 수 있는 JSON CLI 계약(snapshot, delta, ref 조작, allowed-domains 옵션)을 문서화하는가.
- 근거 문서: `_research/foundation-plan.md` §1 표 "런타임" 행(Bun 1.4 [결정]), §2 웹 행, §7 위험("Playwright가 Bun에서 호환되지 않으면 Node 자식 프로세스로 우회"). `_research/packages.md` L2-c 행. `_research/browser-tools.md` agent-browser 절(480-491행, 선행 조사). `_research/web-tools.md` 279-284행(web.browse 계약 초안).
- 조사 방법: 1차 자료만 읽었다. Bun 공식 문서(bun.com), Bun 소스(oven-sh/bun 태그 bun-v1.4.3), 두 저장소의 이슈 본문과 댓글(gh CLI로 읽기), npm 패키지 tarball(`npm pack --ignore-scripts`로 받아 풀어서 읽기)을 사용했다. 받은 코드는 실행하지 않았다. 바이너리는 `file` 명령으로 종류만 확인했다.
- 조사 일자: 2026-10-21. 대상 버전: playwright-core 1.64.1, agent-browser 0.39.1, Bun 1.4.x. [가정] Bun 소스는 태그 bun-v1.4.3을 설치 버전과 같은 것으로 본다.
- 성격: 조사 결과. 정본이 아니다. 인용용이다.

## 1. 결론

- [제안] playwright-core 1.64.1은 Bun 1.4에서 브라우저 실행과 CDP 연결을 시도할 근거가 있다. 실행 검증은 하지 않았으므로 "동작한다"는 판정은 [미확인]이다. 근거는 세 가지다. 첫째, 크로미움 실행 경로의 추가 stdio 파이프(fd 3, 4)를 Bun 1.4.3 child_process가 지원한다(§2.1). 둘째, Bun 1.4 공식 블로그가 Playwright의 `connectOverCDP()`와 테스트 러너를 지원 항목으로 적는다(§2.1). 셋째, playwright-core 1.64.1 번들에 Bun 전용 분기나 Bun 전용 의존이 없다(§2.2).
- [제안] 공식 지원은 아니다. Playwright 메인테이너는 Bun을 테스트하지 않으며 "using it will be at your risk"라고 밝혔다(microsoft/playwright#38095, 2025-11-05, 종료 사유 NOT_PLANNED). Bun 블로그의 Playwright 항목은 launch를 Windows에서만 명시한다. Linux와 macOS의 launch는 명시하지 않는다.
- [제안] 열린 결함이 두 가지 있다. `recordHar`를 설정하면 Bun 이벤트 루프가 교착한다(oven-sh/bun#30652, 열림, 1.4.x에서도 재현 보고). 클라이언트 인증서(mTLS) 테스트는 `ERR_SOCKET_NOT_CONNECTED`로 실패한다(oven-sh/bun#44523, 열림). 두 기능은 Bun 직접 경로에서 쓰지 않는다.
- [제안] Node 자식 프로세스 우회 범위는 실측 전에 확정할 수 없다. 후보는 두 단계다. 1단계는 실패한 경로(launch 또는 CDP 연결)만 우회한다. 2단계는 playwright-core 전체를 Node 24 자식에 두고 JSON-RPC로 중계한다(§4).
- [제안] agent-browser 0.39.1은 JSON CLI 계약을 README와 skill-data 문서로 제공한다. 제공 항목은 `--json` 출력, `snapshot --delta`(응답 종류와 적용 규칙), `@eN` ref 조작 명령군, `--allowed-domains` 옵션이다. 정식 응답 JSON 스키마, 종료 코드 전체 표, 실패 응답 형식은 문서에 없다([미확인]).
- [제안] npm 래퍼(`bin/agent-browser.js`)는 `engines`에 Node 24를 적지만 래퍼는 네이티브 바이너리를 `spawn`할 뿐이다. README는 Node 24가 "소스 빌드에만 필요"하다고 적는다(README:86). 따라서 provider는 네이티브 바이너리를 직접 호출할 수 있다. 바이너리는 동적 링크 ELF이며 Node에 의존하지 않는다는 것이 README의 설명이다(README:1710). 실행은 하지 않았다.

## 2. 확인한 사실

### 2.1 Bun 1.4 측

- Node 호환 표 (https://bun.com/docs/runtime/nodejs-apis)
  - child_process: 🟡. 확인한 항목은 다음과 같다. IPC로 소켓 핸들을 넘길 수 있으나 HTTP 서버 소켓은 안 된다. `subprocess.channel.ref()`와 `unref()`가 없다. 자식의 stdout·stderr를 다른 자식의 stdio로 넘길 수 없다. `spawnSync`의 `output`은 추가 stdio 파이프를 돌려주지 않는다. spawn, exec, detached, kill에 대한 별도 메모는 없다.
  - net: 🟢 "Fully implemented". Unix 도메인 소켓과 `server.listen({ fd })`를 포함한다. `new net.Socket({ fd })`는 읽기 fd에 쓸 수 없고 쓰기 전용 래핑만 된다.
  - 전역 WebSocket: 🟢 "Fully implemented". `ws` 패키지 상태는 이 표에 없다.
  - worker_threads: 🟡. process: 🟡(`process.title` 설정은 macOS와 Linux에서 no-op).
- child_process 레퍼런스 색인 (https://bun.com/reference/node/child_process): "Works in Bun", 비고 "Core functionality works". `stdio` 세부는 spawn 페이지에 있으나 이번에 확인하지 못했다([미확인]).
- Bun 1.4 블로그 (https://bun.com/blog/bun-v1.4#playwright, 표지 "Shipped in Bun v1.4.0"). 원문은 다음과 같다.
  - "Playwright now runs on Bun: drive a browser with `connectOverCDP()`"
  - "run your suite with `playwright test` and a `playwright.config.ts`, open `--ui`, and launch Chromium on Windows."
  - 기재된 버전은 Bun 1.4.0뿐이다. Playwright 버전과 제한 사항은 없다.
  - 같은 블로그의 Node 호환 항목은 `ws`의 'upgrade', 'unexpected-response' 이벤트를 신규 지원으로 적는다. 이는 요약 도구로 읽은 내용이므로 원문 대조는 [미확인]이다. playwright-core의 CDP 전송이 'upgrade' 이벤트를 쓴다(§2.2).
- Bun 소스 (oven-sh/bun, 태그 bun-v1.4.3, `src/js/node/child_process.ts`)
  - 1416-1417행: `for (let i = 3; i < bunStdio.length; i++) if (bunStdio[i] === "pipe") bunStdio[i] = "socket-fd";`. win32는 제외된다. 1405-1414행 주석은 추가 "pipe" 슬롯을 `#getBunSpawnIo`가 `net.Socket`으로 감싼다고 설명한다.
  - 1322-1324행: `socket-fd`인 경우 부모 측 fd를 `handle.stdio[i]`에서 받아 `net.connect({ fd })`로 감싼다.
  - 1895행: stdio 배열 길이가 3 이상이면 그대로 통과시킨다(`normalizeStdio`).
  - 634행: `spawnSync`는 추가 파이프를 노출하지 않는다는 TODO가 있다.
  - 해석: playwright-core의 크로미움 launch는 비동기 `spawn`을 쓰므로 이 경로에 해당한다(§2.2).

### 2.2 playwright-core 1.64.1 측 (npm tarball `package/`, 읽기만)

- package.json: `engines.node >=20`. `dependencies` 필드가 없다. 라이선스 Apache-2.0. bin은 `playwright-core: cli.js`.
- 번들 구조: `lib/coreBundle.js`(약 3.5MB) 한 파일이 본체다. `lib/utilsBundle.js`가 `ws` 등 의존을 번들한다.
- Bun 분기: `lib/`(vite 제외)에서 `process.versions.bun`과 `Bun.` 참조는 0건이다(grep).
- 프로세스 실행: `coreBundle.js:10023-10036`의 `launchProcess`. `stdio: "pipe"`이면 `["ignore","pipe","pipe","pipe","pipe"]`(10024). `detached`는 win32가 아니면 true(10030). 강제 종료는 `process.kill(-pid, "SIGKILL")`(10115).
- 크로미움 인자: `--remote-debugging-pipe`(coreBundle.js:44741). 파이프 전송은 `new PipeTransport2(stdio[3], stdio[4])`(41282-41283).
- CDP WebSocket 전송: `ws = require("./utilsBundle").ws`(40896), `WebSocketTransport` 클래스(40907), `this._ws.on("upgrade")`(40920). 공개 API는 `connectOverCDP`(types/types.d.ts:17476).
- 접근성 스냅샷: 공개 API는 `page.ariaSnapshot`(types/types.d.ts:2101)과 `locator.ariaSnapshot`(14608)이다. 구현은 `init_ariaSnapshot`(coreBundle.js:298)이며 페이지 DOM을 순회한다. 번들에 `getFullAXTree` 문자열이 없다(grep). 따라서 CDP 접근성 도메인에 의존하지 않는다. 이 판단은 grep 결과에 근거한다.
- chromium-bidi: `coreBundle.js:44829-44830`에 정적 `require("chromium-bidi/...")`가 있다. 호출은 `init_bidiOverCdp`(44897)에서 일어난다. `dependencies`에 없으므로 번들러가 해석에 실패한다(microsoft/playwright#43190).
- browsers.json 경로 require: `coreBundle.js:35124`, `35215`. microsoft/playwright#43140이 가리킨 항목이다. 빌드 위험으로 본다.

### 2.4 agent-browser 0.39.1 (npm tarball, 읽기만)

- 패키지: bin은 `bin/agent-browser.js`다. `engines`는 node >=24, pnpm >=11이다. 라이선스 Apache-2.0. 포함 파일은 `bin`, `scripts`, `skill-data`, `skills`다.
- 래퍼: `main()`(bin/agent-browser.js:78)이 플랫폼에 맞는 바이너리를 고르고, 115행에서 `spawn(binaryPath, process.argv.slice(2), { stdio: 'inherit' })`로 실행한다. 래퍼 주석은 Bun이 lifecycle 스크립트를 기본으로 막는 경우를 언급한다.
- 네이티브 바이너리 7종: linux-x64, linux-arm64, linux-musl-x64, linux-musl-arm64, darwin-x64, darwin-arm64, win32-x64.exe. 풀었을 때 합계는 119,447,219바이트다. linux-x64는 `ELF 64-bit LSB pie executable, x86-64, dynamically linked`다(`file`로 확인, 실행하지 않음).
- Node 요구: README:51 "Requires Node.js 24+, pnpm 11+, and Rust." README:86 "Node.js 24+ and pnpm 11+ - Only needed when building from source." README:1710 "Pure Rust daemon ... no Node.js required".
- 설치: README:17-20은 "Installs the native Rust binary"와 `npm install -g agent-browser`를 적는다. `agent-browser install`(README:21, 560)은 Chrome for Testing을 내려받는다. Chrome은 Playwright 번들이 아니다.
- JSON 출력: 전역 `--json`(README:1066 "JSON output (for agents)"). 예시는 README:1311에 있다: `{"success":true,"data":{"snapshot":"...","refs":{"e1":{"role":"heading","name":"Title"},...}}}`.
- snapshot 옵션: `-i`, `-c`, `-d N`, `-s SELECTOR`, `--delta`, `--full`(README:989-997, 옵션표 1007-1008). `--delta`는 "Full state once, then bounded structural deltas"(README:996).
- delta 응답 규칙 (skill-data/core/references/commands.md:43-55)
  - 응답 종류는 `full`, `unchanged`, `delta`다. 이력은 탭별, 옵션 조합별이다. URL이 바뀌거나 델타가 크면 `full`을 준다.
  - 델타 적용: `changes`의 `add`, `remove`, `replace`를 ref 메타데이터에 적용한다. 이전 트리를 줄 단위로 나누고, `treeChange.lines`를 0-based `startLine`부터 `deleteCount`만큼 바꿔 넣은 뒤 줄바꿈으로 합친다. `baseRevision`에 적용한 뒤 `revision`으로 올린다. 기준이 없으면 `--full`을 쓴다.
- ref 수명 (skill-data/core/references/snapshot-refs.md "Ref Lifecycle", 81행~)
  - 같은 문서 안의 갱신은 생존한 요소의 ref를 유지한다(README:984도 같은 내용).
  - 교체된 요소와 페이지 또는 iframe 문서의 교체는 해당 ref를 무효화한다.
  - 무효화된 ID는 브라우저 세션 안에서 재사용하지 않는다.
  - JSON snapshot 응답은 사라진 ref를 `removedRefs`로 적는다.
- ref 조작 명령 (commands.md:57-79): click, dblclick, focus, fill, type, press, hover, check, uncheck, select, scrollintoview, drag, upload가 `@eN`을 받는다. 읽기는 commands.md:85-97의 `get text|html|value|attr|box|styles @eN`이다.
- 실패 신호: 클릭 대상을 다른 요소가 덮고 있으면 발사 전에 실패하고, 덮는 요소를 이름으로 알린다(commands.md:83, README:101). `tab_gone`은 종료 코드 1과 JSON `code`로 알린다(README:773).
- batch: `batch --json`이 stdin으로 JSON 배열을 받는다(README:286-301).
- MCP 대안: `agent-browser mcp`가 stdio에서 개행 구분 JSON-RPC를 제공한다(README:593). 기본 프로파일은 `core`다. 도구는 `agent_browser_snapshot`, `agent_browser_click`, `agent_browser_fill` 등이고, `allowedDomains` 필드가 `--allowed-domains`에 대응한다(README:612-623).
- 도메인 제한
  - 옵션: `--allowed-domains <list>`(README:1084). 환경 변수 `AGENT_BROWSER_ALLOWED_DOMAINS`(README:886). 쉼표 목록이며 `*.example.com`은 apex 도메인도 포함한다(README:877).
  - 차단 범위: 허용 밖 HTTP 요청, WebSocket과 EventSource 연결, sendBeacon(README:877, skill-data/core/references/trust-boundaries.md:48). 지원되는 Chromium 세션에서는 RTCPeerConnection을 끈다. 워커는 부트스트랩 래퍼로 가드하며, 페이지 CSP가 막으면 실패로 닫는다(fail closed).
  - 거부 조건: 기존 CDP 세션, auto-connect, Chrome 프로필, restore와 state 재생, 직접 페이지 provider 플러그인, 프로필을 고르는 raw Chrome 인자, iOS, Safari는 이 옵션과 함께 쓰면 거부된다(README:1084, trust-boundaries.md:48).
  - 정책 파일: `--action-policy`(README:878, 1085).
- 선행 조사와의 차이: browser-tools.md:485는 "Playwright식 auto-wait·settle이 없고 자동 스냅샷도 붙이지 않는다"고 적는다. 이번 조사는 README에서 이를 확인하지 못했다. 선행 조사의 코드 읽기 결과로만 두고 [미확인]으로 둔다.

## 4. Node 자식 프로세스 우회 범위

- [제안] 우회 판정은 M2 스모크 하나로 한다. 스모크는 두 경로다. 첫째는 `chromium.launch` → `page.goto` → `ariaSnapshot` → `close`다. 둘째는 로컬 Chrome 원격 디버깅 포트에 대한 `connectOverCDP` → `ariaSnapshot`이다.
- [제안] 1단계(부분 우회): 실패한 경로만 Node 24 자식 프로세스로 넘긴다. 예를 들어 launch만 실패하면 launch만 자식에서 실행하고, 이후 조작은 Bun에서 CDP로 연결한다. 이 경우 Chrome 프로세스의 정리(종료 신호)가 두 프로세스에 걸친다.
- [제안] 2단계(전체 우회): playwright-core 전체를 Node 24 자식에서 실행하고, §5의 provider 계약과 같은 형태의 JSON-RPC를 stdio로 중계한다. Bun 쪽은 일반 stdio(0, 1, 2)만 쓰며 추가 파이프(3, 4)를 쓰지 않는다.
- [제안] 공통 조건: playwright-core 버전을 1.64.1로 고정한다. Node 자식은 Node 24 이상을 쓴다. playwright-core의 engines는 >=20이라 하한만 적혀 있다.
- [미결] 실측 전에는 1단계와 2단계 중 어느 쪽을 기본 경로로 둘지 정할 수 없다. 사용자 확인이 필요하다.

## 5. agent-browser provider 계약 판정

- 문서로 확인된 항목: `--json` 응답 예시, `snapshot --delta`의 응답 종류와 적용 규칙, `@eN` ref 수명과 조작 명령, `--allowed-domains` 옵션과 차단 범위, `mcp` 서버 대안.
- 문서로 확인되지 않은 항목 [미확인]: 응답 JSON의 정식 스키마, 실패 응답(`success: false`) 형식, 종료 코드 전체 표(알려진 것은 1뿐), delta의 `revision`과 `baseRevision` 외 필드 전체, 클릭 후 자동 대기 규칙.
- [제안] provider 계약 초안
  - 호출: `<agent-browser 바이너리> --json --session <id> [--allowed-domains <목록>] <명령…>`. 바이너리 경로는 설정으로 받는다. npm 래퍼는 쓰지 않는다.
  - 세션: 세션 id로 탭을 묶는다. `--pin-tab`은 공유 CDP 연결에서만 필요하다(README:760-781).
  - 정규화: 응답을 TypeBox 스키마로 감싼다. 정식 스키마가 없으므로 버전을 고정한 픽스처 테스트로 형식을 확인한다.
  - ref: 같은 세션에서 ref를 다음 턴까지 유지한다. `removedRefs`가 오거나 `full` 응답이 오면 ref 맵을 교체한다.
- [제안] 설치 단계에 `agent-browser install`(Chrome for Testing 다운로드)이 추가된다. 사용자 확인 뒤에 실행한다.
- [제안] 호출은 Bun의 일반 `spawn`(stdio 0, 1, 2)으로 충분하다. 추가 파이프는 필요 없다.

## 6. 미결 사항

- [미결] 기본 provider를 playwright-local로 둘지 agent-browser로 둘지. foundation-plan §2는 기본을 playwright-core로 둔다. 실측 결과에 따라 바꿀지 사용자 확인이 필요하다.
- [미결] Node 자식 우회를 1단계(부분)로 시작할지 2단계(전체)로 시작할지.
- [미결] `allowedDomains`를 playwright-local에서 구현하는 방식. web-tools.md:381은 네트워크 계층 강제를 요구한다. playwright-core 1.64.1에서 이를 구현하는 방법은 이번 조사에서 확인하지 못했다.

## 7. 확인하지 못한 것 ([미확인] 모음)

1. Bun 1.4.x에서 playwright-core의 launch, connectOverCDP, ariaSnapshot 실행. 내려받은 코드는 실행하지 않는다는 규칙 때문이다.
2. Bun child_process의 파이프 3, 4가 Chromium `--remote-debugging-pipe`와 실제로 통신하는지. 소스에서 socket-fd 지원만 확인했다.
3. Bun 블로그가 Linux와 macOS의 launch를 지원하는지. 명시가 없다.
4. `ws` 패키지의 Bun 상태. Node 호환 표에 항목이 없다.
5. 블로그의 `ws` 'upgrade' 이벤트 신규 지원 문구의 원문 대조.
6. agent-browser 응답 JSON의 정식 스키마, 실패 응답 형식, 종료 코드 전체 표.
7. agent-browser의 자동 대기 규칙(선행 조사 browser-tools.md:485의 주장).
8. 네이티브 바이너리의 Node 없는 직접 실행과 Bun에서의 호출.
9. 이슈 #42801과 #27139의 해결 주장. 사용자 보고만 확인했다.

## 8. spec.md의 browse 절 초안 (대상: docs/xeon/L2/web/spec.md)

- 상태: 대상 파일과 `docs/xeon/L2/web/` 디렉터리가 현재 저장소에 없다. 파일을 새로 만들지 않고 초안만 둔다. L2 작성자가 파일을 만든 뒤 옮긴다.
- 목적: 웹 브라우저 조작(접근성 스냅샷 기반 상호작용) 능력이다. 서비스 API는 `web.browse`이며 web-tools.md:279-284 계약을 따른다.
- provider 후보: `playwright-local`(기본 후보), `agent-browser`(네이티브 바이너리 직접 호출), `playwright-node`(Node 자식 우회. 실측에서 실패할 때만 쓴다). [제안]
- 계약 초안: `open`, `snapshot`(mode는 `snapshot|text|find|screenshot`, delta 옵션), `act`(ref 기준), `close`. 출력에는 `snapshot`과 ref 목록을 넣고, 필요하면 `removedRefs`를 넣는다. [제안]
- 도메인 제한: `allowedDomains` 필드. agent-browser는 `--allowed-domains`로 전달한다. playwright 경로의 구현 방식은 [미결]이다.
- 실패 경계: 덮는 요소 때문에 클릭이 실패하면 덮는 요소 정보를 담은 `covered` 오류를 낸다. 무효화된 ref로 조작하면 `ref_invalid` 오류를 낸다. 오류 이름은 [제안]이다.
- 우회 금지: Bun 직접 경로에서 `recordHar`, 클라이언트 인증서를 쓰지 않는다. [제안]
- 수용 기준 초안: 세 가지 스모크가 자동 테스트로 통과해야 한다. (a) launch, snapshot, close (b) connectOverCDP, snapshot (c) agent-browser `snapshot --delta` 적용 뒤 ref 일치. Playwright 쪽 테스트 세부는 실측 뒤에 확정한다. [제안]
