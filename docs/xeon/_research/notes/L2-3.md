## 0. 결론

1. Linux(WSL2 포함)의 bun:sqlite 1.4.3은 FTS5를 기본 포함한다. Bun 빌드 스크립트가 `SQLITE_ENABLE_FTS5`를 켠다. 번들 SQLite는 3.53.4다. macOS의 FTS5 포함 여부는 [미확인]이다. Bun은 macOS에서 시스템 SQLite를 쓰고, 그 빌드의 옵션은 확인하지 못했다.
2. 한국어 대화 검색에는 trigram이 맞다. unicode61은 조사가 붙은 어절에서 `검색`으로 `검색을`을 찾지 못한다. [측정]
3. trigram은 SQLite 3.34.0(2020-12-01)부터 쓸 수 있다. 3글자 미만 질의는 MATCH에서 오류 없이 0건을 낸다. 한국어 2글자 명사가 많으므로 짧은 질의에는 LIKE 경로를 따로 둬야 한다. [측정]
4. BM25 `bm25()`는 trigram 테이블에서 동작한다. [측정] 인덱스 크기에 대한 공식 수치는 없다. 합성 데이터에서 인덱스 부분은 unicode61의 약 3배였다. 실제 대화 코퍼스로 다시 재야 한다. [측정, 합성 데이터]
5. 두 가지 전제를 바로잡는다.
   - (a) `foundation-plan.md`의 "macOS에서 FTS5 유무가 다르다"는 전제를 1차 자료로 확인하지 못했다. `packages.md` §5의 "FTS5 유무가 빌드마다 다르다"는 `node:sqlite` 보고다. bun:sqlite 근거가 아니다.
   - (b) Bun 문서의 `setCustomSQLite`는 비macOS에서 `false`를 반환한다고 적는다. 1.4.3 Linux에서는 `true`를 반환한다. 소스와 실측이 일치한다. 따라서 시작 시 검사는 반환값에 기대지 말고 FTS5 기능 프로브로 해야 한다.

## 2. bun:sqlite에서 FTS5 기본 포함 여부

### 2.1 Linux

- 빌드 플래그: `SQLITE_ENABLE_FTS3: 1`(`scripts/build/deps/sqlite.ts:36`), `SQLITE_ENABLE_FTS5: 1`(같은 파일 :38). 이 빌드는 `cfg.staticSqlite`일 때 쓰이고, 주석은 Linux와 Windows의 기본값이라고 적는다(:7-8, :21).
- 번들 버전: `#define SQLITE_VERSION "3.53.4"`(`src/jsc/bindings/sqlite/sqlite3.c:472`, 태그 `bun-v1.4.3`, 내려받은 앞 400KB 범위).
- 실측: `pragma compile_options`에 `ENABLE_FTS5`가 있다. `CREATE VIRTUAL TABLE ... USING fts5(..., tokenize='trigram')`이 성공한다. [측정]
- 참고 문서: FTS5를 SQLite amalgamation으로 빌드하면 3.9.0부터 기본 포함이다. 직접 컴파일하면 `SQLITE_ENABLE_FTS5` 정의가 필요하다(fts5.html §2.1, 줄 246 부근).

### 2.2 macOS

- Bun은 macOS에서 시스템 `libsqlite3.dylib`를 런타임에 dlopen한다(`sqlite.ts:7-10`, `LAZY_LOAD_SQLITE=1`).
- 주석은 Apple 빌드에서 빠지는 기능으로 `load_extension`, `percentile()`, geopoly, rbu를 들고, 구버전 macOS에서는 session 확장도 든다(`sqlite.ts:10-12`). FTS5는 이 목록에 없다.
- Bun 문서는 macOS에서 Apple의 SQLite를 쓰며 확장 로딩이 안 된다고만 적는다(`bun.sh/docs/runtime/sqlite`, `loadExtension` 절). FTS5 누락은 적지 않는다.
- 판정: macOS에서 FTS5가 있다는 것은 [추정]이다. 1차 근거는 Bun 주석의 목록에 FTS5가 없다는 점뿐이다. 실측은 하지 못했다. [미확인]
- [제안] 시작 시 프로브를 유지한다. 프로브는 `pragma compile_options`에서 `ENABLE_FTS5`를 찾고, 실제로 trigram 테이블을 만들어 본다. 실패하면 사용자에게 Homebrew SQLite 경로를 지정하도록 안내한다. 이 경로의 FTS5 옵션도 [미확인]이다.

### 2.3 Database.setCustomSQLite의 실제 동작

- 문서 문장: "On other operating systems, SQLite is statically linked: the call does nothing and returns `false`." (`bun.sh/docs/runtime/sqlite`, `setCustomSQLite` 절)
- 소스: `JSSQLStatement.cpp`에서 `#if LAZY_LOAD_SQLITE`는 :66에서 시작하고, `#else` 분기는 :69 이후다. `jsSQLStatementSetCustomSQLite`는 :1202-1256에 있다. 경로를 로드하는 코드는 :1225-1251의 LAZY 분기 안에만 있다. 공통 경로는 `Bun__initializeSQLite()`(:1253) 뒤에 `jsBoolean(true)`를 반환한다(:1255).
- 실측: Linux에서 `Database.setCustomSQLite("/nonexistent/libsqlite3.so")`가 `true`를 반환했다. 존재하지 않는 경로도 통과한다. [측정]
- 판정: 문서와 소스가 다르다. Linux에서 반환값은 경로가 유효하다는 증거가 아니다. [제안] 시작 시 검사는 반환값에 기대지 않고 기능 프로브로 한다.
- Bun 문서의 "Bun rejects a different path after SQLite loads"는 LAZY 분기 안의 경로 불일치 오류(:1236 부근)에 대응한다. Linux에서는 이 분기가 없으므로 해당하지 않는다.

## 3. 토크나이저 선택

### 3.1 unicode61

- 규칙: 공백과 문장부호는 구분자, 범주 `L*`·`N*`·`Co` 문자는 토큰 문자다(fts5.html §4.3.1, 줄 553-560). 한국어 어절은 조사를 포함한 한 토큰이 된다.
- 기본 `remove_diacritics`는 1이다(§4.3.1 옵션 표). 한국어 음절에는 영향이 없다.
- 형태소 분석기는 없다. FTS5에는 ICU 토크나이저도 없다. FTS3/4 이관 안내 절에 `The ICU tokenizer is not available.`이라고 적혀 있다(fts5.html 줄 2873).
- 실측: 본문 "지난번에 검색을 했다"에서 `MATCH '검색'`은 0건, `MATCH '검색을'`은 1건이다. [측정, probe4]
- 판정: 조사가 붙은 한국어 어절을 부분 매칭하지 못하므로 대화 검색에 부적합하다.

### 3.2 trigram

- 규칙: 연속된 세 문자를 토큰으로 본다. 질의는 부분 문자열로 매칭한다(fts5.html §4.3.4, 줄 647-660).
- 옵션: `case_sensitive` 기본 0, `remove_diacritics` 기본 0. `case_sensitive=1`이면 LIKE 인덱스를 쓰지 못하고 GLOB만 쓴다(§4.3.4).
- LIKE·GLOB 인덱스: `remove_diacritics`를 설정하지 않으면 LIKE와 GLOB도 인덱스로 처리한다(§4.3.4).
- 3글자 미만 질의: "Substrings consisting of fewer than 3 unicode characters do not match any rows when used with a full-text query." (§4.3.4 Notes). LIKE·GLOB 패턴에 3글자 미만 구간만 있으면 전체 선형 스캔으로 되돌아간다(같은 절).
- 실측:
  - `MATCH '검색'`(2글자)은 0건이다. 오류는 없다. [측정, probe2·probe4]
  - `MATCH '검색을'`(3글자)은 1건이다. [측정, probe4]
  - `LIKE '%검색%'`은 1건이다. 질의 계획은 `SCAN tri VIRTUAL TABLE INDEX 0:L0`이다. MATCH 3글자 질의는 `INDEX 0:M1`이다. [측정, probe3]
- 여러 토큰 질의: 따옴표 없는 `대화 검색`은 두 토큰이 AND로 묶인다. 두 토큰이 모두 2글자라 0건이다. 따옴표로 묶은 `"대화 검색"`은 5글자 구절로 매칭되어 1건이다. [측정, probe2] 3글자 미만 규칙은 토큰과 구절 단위로 적용된다.
- NFC·NFD: 저장 텍스트가 NFD(자모 분해)이면 NFC 질의가 MATCH와 LIKE 모두에서 0건이다. NFC 사본을 추가하면 1건이 된다. [측정, probe3] 인덱싱과 질의 양쪽에 NFC 정규화를 걸어야 한다. [제안]
- detail 옵션 제약: `detail=none` 또는 `detail=column`이면 전문 질의에 3글자를 넘는 토큰을 쓸 수 없다(§4.3.4 Notes, fts5.html 줄 682-687). [제안] 세션 검색 테이블은 기본 `detail=full`로 둔다.
- 인덱스 크기: FTS5 문서에 trigram 인덱스 크기 수치는 없다. §4.6의 수치(이메일 1,636MiB 원본, 인덱스 full 743MiB, column 340MiB, none 134MiB)는 detail 옵션의 예시이며 trigram 수치가 아니다(fts5.html 줄 975-976).
- 합성 데이터 실측: 4,000행, 213,820자, 어휘 20개를 조합한 텍스트다. `dbstat` 가상 테이블(Bun 빌드에 `SQLITE_ENABLE_DBSTAT_VTAB: 1`, `sqlite.ts:49`)로 쟀다. [측정, 합성 데이터, probe4]
  - 인덱스 부분(`_data`, `_idx`, `_docsize`): trigram 548,864B, unicode61 184,320B. 비율 약 2.98배다.
  - 본문 테이블(`_content`): 두 방식 모두 598,016B로 같다.
  - 실제 대화 텍스트의 비율은 다를 수 있다. [미확인]

### 3.3 최소 SQLite 버전

- trigram은 SQLite 3.34.0에서 들어왔다. 릴리스 노트의 문장은 "Enhanced FTS5 to support trigram indexes."다(`https://www.sqlite.org/releaselog/3_34_0.html`, 본문 118행, 릴리스일 2020-12-01). FTS5 문서 본문에는 버전이 적히지 않는다.
- Bun 1.4.3의 번들 3.53.4는 3.34.0 이상이므로 충족한다. [측정 및 소스 확인]

### 3.4 BM25

- `bm25()`는 FTS5 보조 함수다(fts5.html §5.1.1, 줄 1102-1151). 더 좋은 매칭일수록 값이 작다. FTS5 구현은 결과에 -1을 곱한다(§5.1.1).
- 열별 가중치 인자를 받는다. 예: `bm25(email, 10.0, 5.0)`(§5.1.1).
- 문서에 토크나이저별 제한은 적혀 있지 않다. [미확인: 토크나이저 전체에 대한 명시 문장은 확인하지 못했다.]
- 실측: trigram 테이블의 `ORDER BY bm25(tri)`가 동작하고, 구절 `"대화 검색"`에 -0.439를 반환했다. [측정, probe2] 코퍼스가 3문서뿐이라 IDF 값 자체는 의미가 없다.
- 판정: trigram에서 BM25 정렬을 쓸 수 있다.

## 4. 판정과 설계 반영 [제안]

1. 세션 검색 토크나이저는 trigram으로 한다. 옵션은 `case_sensitive=0`, `remove_diacritics=0`, `detail=full`(모두 기본값)을 쓴다.
2. 인덱싱과 질의 양쪽에 NFC 정규화를 적용한다. [측정, probe3]
3. 질의 길이 분기 규칙을 spec에 적는다.
   - 질의를 NFC로 정규화하고 코드 포인트 수를 센다. 구절 하나 또는 토큰 하나가 3글자 미만이면 LIKE 선형 스캔 경로를 쓴다.
   - 여러 토큰은 구절로 묶어 MATCH에 넣는다. 토큰별 길이 검사는 그 뒤에 한다.
   - 2글자 질의가 0건인 것은 규칙에 따른 결과다. spec에 그렇게 적는다.
4. 시작 시 프로브를 둔다. `ENABLE_FTS5` 확인과 trigram 테이블 생성 시도를 한다. `setCustomSQLite`의 반환값에 기대지 않는다. [§2.3 근거]
5. 정렬은 `bm25()` 오름차순에 최신순을 보조 정렬로 붙인다.
6. 테이블 구성은 SQLite 외부 콘텐츠(`content=`) 방식을 검토한다. 그러면 본문을 중복 저장하지 않는다. 대신 투영 테이블과 트리거를 같은 트랜잭션에서 관리해야 한다(fts5.html §4.4.3). [미결]
7. 테이블 이름에는 확장 접두사를 붙인다(`architecture/overview/spec.md:28`, ADR-0004). 접두사 규칙은 저장소에서 찾지 못했다. [미결]

## 5. 미결과 미확인

- [미확인] macOS의 FTS5 옵션. Apple 시스템 SQLite와 Homebrew SQLite 모두 해당한다. 사용자 Mac에서 `pragma compile_options`를 확인해야 한다.
- [미확인] Bun 1.4.x 다른 패치 버전의 번들 SQLite 버전. 1.4.3만 확인했다.
- [미확인] 실제 대화 코퍼스 기준 인덱스 크기. 합성 데이터만 쟀다.
- [미확인] 소규모 코퍼스의 BM25 IDF 품질.
- [미결] 2글자 질의의 LIKE 선형 스캔 허용 범위. 세션 수 상한과 성능 목표가 필요하다. 사용자 확인이 필요하다.
- [미결] 확장 접두사 테이블 이름 규칙. ADR-0004와 `architecture/overview/spec.md`에 규칙 명시가 있는지 확인이 필요하다.
- [가정] 세션 본문은 한국어와 영어가 섞인다. 영어 2글자 단어 검색도 LIKE 경로로 처리된다.

## 6. spec·plan 반영 초안

- 대상 파일 `docs/xeon/L2/knowledge/spec.md`와 `docs/xeon/L2/knowledge/plan.md`는 저장소에 없다(`docs/xeon/L2/` 디렉터리 부재 확인, 2026-10-21). 지정 경로 규칙에 따라 이 노트에만 쓴다. 아래 초안을 소유자가 붙여 넣는다.
- spec의 세션 검색 절 초안:
  - 검색은 FTS5 `trigram` 토크나이저로 한다. 최소 SQLite 3.34.0을 요구한다. Bun 1.4.3 번들 3.53.4는 충족한다.
  - 인덱싱과 질의 모두 NFC로 정규화한다.
  - 3글자 미만 질의는 LIKE 선형 스캔으로 처리한다. 질의가 MATCH로 0건일 때 빈 결과를 반환하지 않는다.
  - 정렬은 `bm25()` 오름차순이다. 동점은 최신순으로 정한다.
  - 시작 시 FTS5 기능 프로브가 실패하면 세션 검색 기능을 끄고 원인을 보고한다.
- plan의 K8 작업 초안:
  - trigram FTS5 테이블을 만든다. `detail=full`을 쓴다.
  - NFC 정규화 함수를 인덱싱과 질의에 함께 건다.
  - 질의 길이 분기(MATCH와 LIKE)를 구현한다.
  - 테스트: 2글자 한국어 질의가 0건을 내고 LIKE 경로에서 1건을 내는지, 조사가 붙은 어절을 3글자 질의로 찾는지, NFD 저장 텍스트를 NFC 질의로 찾는지, `bm25()` 정렬이 음수 값으로 정렬되는지, 시작 프로브가 `ENABLE_FTS5` 없는 빌드에서 실패하는지.
  - 완료 기준: 실제 대화 코퍼스로 인덱스 크기를 다시 잰다.

## 7. 재현 SQL

```sql
CREATE VIRTUAL TABLE tri USING fts5(body, tokenize='trigram');
CREATE VIRTUAL TABLE uni USING fts5(body, tokenize='unicode61');
INSERT INTO tri(body) VALUES ('지난번에 검색을 했다');
INSERT INTO uni(body) VALUES ('지난번에 검색을 했다');
SELECT count(*) FROM uni WHERE uni MATCH '검색';     -- 0
SELECT count(*) FROM uni WHERE uni MATCH '검색을';   -- 1
SELECT count(*) FROM tri WHERE tri MATCH '검색';     -- 0 (2글자)
SELECT count(*) FROM tri WHERE tri MATCH '검색을';   -- 1
SELECT count(*) FROM tri WHERE body LIKE '%검색%';   -- 1 (선형 스캔)
```
