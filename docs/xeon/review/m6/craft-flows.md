## 읽는 법

이 문서는 Craft 흐름(옛 `craft-flow`, 제1부)과 화면 요구(옛 `spec/m6-craft-flows`, 제2부)를 하나로 합친 것이다. 절 번호는 각 부 안에서만 센다: 제1부는 "흐름 n", 제2부는 "화면 n"으로 인용한다. 옛 흐름 문서의 "화면 간 이동"(§4) 표는 제2부 화면 5.2의 이동표가 같은 행에 행을 더한 것이라 따로 두지 않는다. 옛 흐름 문서 표지 `[안]`은 `[제안]`으로 읽고 `[열림]`은 모두 닫혔다(2026-11-17 밤 사용자 결정, ADR-0023). 화면 문구 예시는 라벨의 뜻을 보이려는 것이다.

## 제1부. 흐름

디자인 전에 흐름을 정하는 문서다. 사용자가 플러그인을 만들고, 검토하고, 프로필에 넣고, 대화에서 쓰고, 관찰하고, 고치는 순환을 단계별로 적는다. 개념은 `docs/xeon/decisions/ADR-0023-plugin-profile-core.md`(특히 §3.1~§3.8, §3.14), 엔진 쪽은 `docs/xeon/review/m5/drive-isolation.md`. 이 문서는 `craft-plan.md`의 정보 구조(3절)와 화면 목록(4절)을 대체한다.

표기: [결정] 사용자가 정한 것(날짜를 적는다), [안] 메인 에이전트의 제안, [권고: 메인 세션, 확인 대기] 메인 세션이 권하고 사용자가 아직 정하지 않은 것(작업 기본값), [확인 대기] 사용자 확인이 남은 것. 엔진 열: 있음 / 일부 / 없음. 이 표들의 "엔진 열"은 2026-11-17 초안 1 기준이다. 현재 상태는 M5c §4.8·§4.9, M5d §3.8, `m5-plan.md` §7이 정본이다.

초안 2는 같은 날 뒤에 붙었던 결정 절(옛 8절)을 본문으로 합쳤다. 이름: Craft 전용 AI 대화 = **테스트 대화**, 초안을 얹어 실제처럼 돌리는 일 = **테스트 실행** [결정: 2026-11-17 사용자], 그 장소 = **테스트** [결정: 2026-11-17 사용자]. 옛 이름(시험장 등)은 쓰지 않는다. 구현 스펙은 `docs/xeon/review/m5/profile-project-loader.md`, `docs/xeon/review/m5/turn-record-metrics.md`, `docs/xeon/review/m5/hooks-core-boundary.md`, 화면 스펙은 `docs/xeon/review/m6/craft-flows.md`다.

### 흐름 1. 순환과 장소

```
            ┌──────────────── 고치기 ◀───────────────┐
            ▼                                        │
  만들기 ─▶ 테스트 ─▶ 검토 ─▶ 프로필에 넣기 ─▶ 대화에서 쓰기 ─▶ 관찰
  (대화 또는 Craft)                         (프로젝트 › 대화)
```

| 장소 | 역할 |
|---|---|
| 대화 | 만들기의 입구(80~90%), 쓰는 중의 흔적, 프로필 칩(고르기와 탈출) |
| 테스트 대화 창 | 테스트 대화: Craft 어디서나 떠 있는 전용 AI 대화. 플러그인 상세에서 연다. 지금 보고 있는 것을 맥락으로 들고 시작한다. 플러그인의 생성과 수정은 여기(와 대화의 빌더)로만 한다 [결정: 2026-11-16, 2026-11-17 사용자] |
| Craft 개요 | 지금 상태 한 장: 플러그인 그래프, 검토 대기, 살펴볼 것 |
| 플러그인 상세 | 한 플러그인의 모든 것: 공통 스키마, 하는 일(루프 위의 자리), 지표, 버전과 검토 이력, 만든 대화 |
| 테스트 | 초안을 써 보고(테스트 실행), 한 일을 그 자리에서 보고, 바로 고친다. 지금의 "테스트" 화면을 바꾼 것 [결정: 2026-11-16, 2026-11-17 사용자] |
| 검토함 | 새 버전의 승인과 배치. 모든 생성과 변경이 지나는 한 곳 [결정: 2026-11-16, 2026-11-17 사용자] |
| 프로필 | 넣고 빼기, 비용과 충돌, 권한, 시작할 때 Drive |
| 턴 기록, 지표 | 무슨 일이 있었나, 무엇을 고칠까 |
| 프로젝트 | 대화를 묶는 그룹. 루트 작업 폴더 하나, 대화는 그 안의 하위 폴더(대화 폴더)에서 시작하고 쓰기 허용은 루트 전체다. 프로젝트가 없는 대화는 전용 기본 폴더에서 관리한다. 프로젝트 폴더에 든 플러그인은 허용하고 열 때 검토함에 올라오며 승인 전에는 실행되지 않는다. 플러그인과 프로필은 프로젝트가 아니라 대화 단위이고 프로젝트는 기본 프로필을 갖지 않는다 [결정: 2026-11-17] |

### 흐름 2. 규칙

- R1. 플러그인의 원본은 폴더다. 앱은 검토된 사본만 실행한다. 손으로 고치는 것은 허용하지 않는다. 수정은 담당 AI(테스트 대화 창, 대화의 빌더)로만 한다. [결정: 2026-11-16, 2026-11-17 사용자] 프로필 화면의 "지침 추가"는 예외가 아니다: 사용자가 쓴 한 줄이 지침만 든 플러그인 초안이 되어 검토함을 한 번 지난다(사용자가 쓴 것이라 한 번의 확인) [결정: 2026-11-17 사용자].
- R2. 초안은 테스트과 사용자가 명시한 덧씌우기(초안 표지, 지표 제외)에서만 검토 없이 돈다. 실제 프로필에 들어가려면 검토함을 지난다. 검토는 그때 한 번이고 테스트 중의 수정은 검토 없이 반복한다. [결정: 2026-11-16, 2026-11-17 사용자] 초안이 `bypass` 대화에서 실제 작업에 이를 때의 안전(카드와 "초안" 표시)은 [결정: 2026-11-17 사용자, U2]: 모드와 무관하게 항상 카드를 띄운다.
- R3. 모든 플러그인은 같은 스키마로 보인다(5절). 하는 일의 이름은 Inject / Hook / Drive. [결정: 2026-11-16, 2026-11-17 사용자]
- R4. 대화는 프로필 하나를 따른다. 대화마다 고를 수 있다. 개별 스위치는 없다. [결정: 2026-11-16, 2026-11-17 사용자]
- R5. 탈출구는 프로필 칩이다(기본 프로필로 전환). 특정 플러그인을 프로필에서 빼는 것은 명령이나 다른 UI로 한다. 막은 카드에 빼기 단추를 두지 않는다. [결정: 2026-11-16, 2026-11-17 사용자]
- R6. 프로필에 없는 검토된 플러그인을 사용자가 직접 부르면 그 턴에만 적용된다(일회 사용). 스킬만이 아니라 **모든 플러그인 유형**(Inject, Hook, Drive, 도구)에 허용한다. [결정: 2026-11-16, 2026-11-17 사용자] 구현은 "이번 턴에만 얹는 프로필 덧씌우기"다. Drive는 "한 턴"이 아니라 "주도권을 내려놓을 때까지"다. 입구는 입력창의 `/`이고 모든 유형이 같다(명령 없는 Hook 전용·도구 전용은 `/<플러그인 이름>`, 이름 해석 규칙은 M5c §4.3.10) [결정: 2026-11-17 사용자]. 스킬·명령·Drive 시작이 없는 Hook 전용·도구 전용 플러그인은 이름으로 얹는다. 도구를 얹으면 그 턴의 도구 목록이 바뀌어 프롬프트 캐시가 한 번 깨진다. 검토된 플러그인만 얹을 수 있다.
- R7. 관찰 화면의 모든 발견에는 다음 걸음이 붙는다(고치기, 올리기, 빼기). [안]

### 흐름 3. 단계별 흐름과 기능

#### 3.1 만들기

| 입구 | 흐름 | 엔진 |
|---|---|---|
| 대화의 턴이나 도구 호출 | 줄을 고름 → "여기서 플러그인 만들기" → 한마디("다음부터 물어봐") → 빌더가 그 대화에서 Drive → 초안 → 대화에 초안 카드 | 일부(빌더 있음. 턴을 근거로 넘기는 길 없음) |
| 대화에서 말로 | "X 하는 플러그인 만들어 줘" → 빌더 Drive → 초안 카드 | 있음 |
| Craft | 개요나 플러그인 목록의 "새 플러그인", 또는 테스트 대화 창에 바로 말함 → 초안 → 테스트 | 일부(테스트 대화 창은 m6C7, 2026-11-22. 초안에서 테스트로 바로 잇는 길은 없음) |
| 기존 플러그인 고치기 | 플러그인 상세나 지표의 한 줄에서 테스트 대화 창을 엶(근거가 맥락으로 들어감) → 새 초안 버전 | 있음(m6C7, 2026-11-22) |

- 초안 카드(대화)와 초안 머리(Craft)는 같은 것을 보인다: 공통 스키마 요약, "테스트에서 써 보기", "검토함으로 보내기".
- 테스트 대화는 플러그인에 묶여 남고 플러그인 상세에서 연다. 일반 대화 목록에 섞지 않는다. [안: 보관 방식] 이 대화를 "이 플러그인을 만들고 고친 대화"라고 부르지 않는다 [결정: 2026-11-16, 2026-11-17 사용자].
- 플러그인의 "목적" 한 문장은 만들 때의 사용자 말에서 나온다. 빌더가 쓰고 사용자가 고칠 수 있다. [안]

#### 3.2 테스트

| 기능 | 내용 | 엔진 |
|---|---|---|
| 테스트 실행 | 기준 프로필에 초안을 더한 임시 구성으로 대화한다. 테스트 실행의 기록은 지표에 섞이지 않는다 [결정: 2026-11-16, 2026-11-17 사용자] | 일부(기존 Test run 통로 있음) |
| 그 자리 관찰 | 턴이 돌 때 이 플러그인이 일한 자리와 결과(통과, 고침, 물음, 막음, 고장), 실린 양, 걸린 시간을 바로 보인다 | 없음(턴 기록 저장 필요) |
| 지난 턴에 돌려 보기 | 기록된 도구 호출에 Hook을 다시 적용한다. 걸렸을 것, 못 잡는 것 | 없음 |
| 바로 고치기 | 관찰한 줄을 테스트 대화 창에 넘김 → 새 초안 버전 → 같은 입력으로 다시 테스트 | 없음 |
| 초안 버전 비교 | 초안 1, 2, 3의 하는 일과 테스트 결과를 나란히 | 없음 |

- 초안은 격리된 프로세스와 샌드박스에서 돈다. 격리 1단계(P1)가 테스트의 전제이고 그 전에는 초안을 돌리지 않는다. 격리는 파일 읽기·쓰기 범위를 막을 뿐 네트워크는 전체 허용이 기본이라(엔진 설계 §3.4) 초안이 받은 대화 내용을 밖으로 보낼 수 있다. "R2가 안전하다"는 이 범위에 한정된 말이다.
- Inject만 하는 초안(지침, 스킬)은 "돌려 보기"가 통하지 않는다. 테스트 실행에서 "실렸나, 읽혔나"를 본다. "따랐나"는 기록만으로 판정할 수 없다.
- **대화에서 만든 초안을 그 대화에서 바로 써 본다** [결정: 좋다고 봄(사용자)]. 구현은 일회 사용과 같은 덧씌우기다. 충돌은 둘이다: 검토 전 코드가 실제 작업에 이른다([결정: 2026-11-17 사용자, U2]), 기록에 초안 활동이 섞인다("초안" 표시와 지표 제외로 다룬다). 초안은 격리 프로세스에서 돌고 P1 전에는 거부한다. 덧씌우기 방식의 세부는 [확인 대기].

#### 3.3 검토

| 기능 | 내용 | 엔진 |
|---|---|---|
| 들어오는 것 | 새 플러그인, 새 버전(담당 AI가 만든 것), 원본 폴더가 검토본과 달라진 것, 지우기 | 없음(검토본 고정과 원본 비교) |
| 보이는 것 | 공통 스키마 카드, 이전 버전과의 "하는 일의 차이", 증거(테스트 실행 기록, 돌려 본 결과), 코드(접혀 있음) | 일부 |
| 결정 | 승인과 넣을 프로필 고르기(기본: 만든 대화의 프로필. 보관만도 가능) / 돌려보내기(사유가 테스트 대화 창으로) / 버리기 | 없음 |

- 원본 폴더를 손으로 고친 경우: 실행되지 않는다. "원본이 검토본과 달라요"가 뜨고 되돌리기 또는 담당 AI에게 넘겨 새 버전으로 들여오기. [안]
- 승인 전에는 이전 버전이 계속 돈다.

#### 3.4 프로필에 넣기

| 기능 | 내용 | 엔진 |
|---|---|---|
| 프로필 만들기, 복제, 지우기 | 내장 기본 프로필은 지울 수 없다 | 일부 |
| 넣기 | 넣기 전에 비용, 충돌(같은 도구를 대체, 시작 Drive 겹침), 필요한 설정 값을 보이고 받는다 | 일부 |
| 빼기 | 프로필 화면과 명령으로 | 일부 |
| 플러그인 설정 값 | 프로필마다. 정하지 않으면 플러그인 기본값. 시크릿 값은 시크릿 저장소 | 없음 |
| 코어 설정 | 권한 모드, 모델 등 블록별 설정 | 일부 |
| 시작할 때 Drive | 없음(기본) 또는 플러그인 하나 | 없음 |
| Hook 순서 | 같은 자리에 여럿이면 프로필에 든 순서가 기본. 블록 상세에서 바꾼다 [안] | 일부 |
| 적용 범위 알림 | "쓰는 대화 N개에 다음 단계부터 적용". Drive 중인 플러그인을 빼거나 권한이 넓어지면 한 줄로 | 없음(참조 방식 필요) |

#### 3.5 대화에서 쓰기

| 기능 | 내용 | 엔진 |
|---|---|---|
| 프로필 칩 | 새 대화는 프로필이 골라진 채 열린다. 선택기의 기본값은 같은 폴더에서 마지막에 쓴 프로필이다([결정: 2026-11-17 사용자, U5]. 프로젝트의 기본 프로필은 없다). 대화마다, 도중에도 바꾼다. 권한 칩을 흡수한다 | 없음 |
| 탈출 | 칩에서 "기본 프로필로 전환" 한 번 | 없음 |
| 흔적 | Hook이 묻거나 막으면 카드, 조용히 고치면 작은 흔적, Drive 중이면 `기본 › Helm › 검증` 표시 | 일부 |
| 흔적에서 이동 | 흔적 → 이 턴의 기록(레일) → Craft 턴 기록 → 플러그인 상세 | 없음 |
| 일회 사용 | 프로필에 없는 검토된 플러그인(모든 종류)을 입력창의 `/`로 부르면 그 턴에만 얹힌다(Drive는 반납까지). 명령이 없는 플러그인은 `/<플러그인 이름>`이다. 흔적에 "이 턴에만" | 없음 |
| 프로필에서 빼기 | 명령(예: 프로필에서 빼기 명령) 또는 칩 메뉴의 "이 프로필 편집"으로 Craft 프로필 화면 | 없음 |
| 플러그인 명령 | 플러그인이 등록한 명령. Drive 시작 명령 포함 | 있음 |

#### 3.6 관찰과 고치기

| 발견하는 곳 | 발견 | 다음 걸음 | 돌아가는 단계 |
|---|---|---|---|
| 대화의 흔적, 턴 기록 | 이 턴에 왜 이랬나 | 플러그인 상세로 | 관찰 |
| 턴 기록 | 지침이 실렸는데 안 지켜짐 | "Hook으로 올리기" → 테스트 대화 창 | 만들기 |
| 지표: 살펴볼 것 | 물음이 늘 거부됨 | "막기로 올리기" → 테스트 대화 창 | 만들기 |
| 지표 | Hook이 자주 시간 초과 | "고치기" → 테스트 대화 창(근거 포함) | 만들기 |
| 지표 | 안 쓰는 도구가 토큰을 차지 | "프로필에서 빼기" | 프로필 |
| 지표 | 모델이 바뀐 뒤 스킬이 안 읽힘 | "설명 고치기" → 테스트 대화 창 | 만들기 |
| 플러그인 상세 | 고친 뒤 나아졌나 | 버전 전후 비교 | 관찰 |

- "고치기"는 근거(어느 턴에서 무슨 일이 있었는지)를 들고 테스트 대화 창이 열리는 것이다. 사용자가 문제를 다시 설명하지 않는다.
- 고친 결과는 초안이 되어 테스트 → 검토함으로 간다.

#### 3.7 수명

| 일 | 처리 |
|---|---|
| 원본이 검토본과 달라짐 | 3.3 |
| 오류로 멈춤 | 스위치가 아니라 상태. 플러그인 상세에 원인과 "고치기", "프로필에서 빼기" |
| 지우기 | 검토함을 지난다. 무엇이 같이 지워지는지(상태, 기록)와 어느 프로필에서 빠지는지 미리 보인다 |

### 흐름 5. 플러그인 공통 스키마

| 층 | 항목 | 모든 플러그인이 같은 자리에 |
|---|---|---|
| 1 | 이름, 목적 | 왜 만들어졌나 한 문장 |
| 1 | 하는 일 | Inject · Hook · Drive 세 칸 중 채워진 것 |
| 1 | 강제력 | 권고 / 강제 |
| 2 | 실행 | 코드가 도는지, 격리됐는지 |
| 2 | 비용 | 컨텍스트에 싣는 양(항상 / Drive 중 / 필요할 때) |
| 2 | 건강 | 최근에 일했나, 오류가 있나 |
| 3 | 출처와 검토 | 누가 어느 대화에서 만들었나, 버전, 검토 상태 |
| 3 | 쓰는 곳 | 든 프로필 |

차이는 "하는 일" 칸을 펼쳤을 때만 나온다: Inject는 무엇을 언제 싣나, Hook은 어느 블록의 앞뒤에서 어떤 조건에 무엇을 하나, Drive는 어떤 단계와 한도로 누구에게 맡기나.

"종류"는 고정 분류가 아니라 세 칸 중 어디가 채워졌나로 보인다(한 플러그인이 여럿을 할 수 있다). [안]

## 제2부. 화면, 이동, 정보 위계, 데이터, 수용 기준

**M6 Craft: 흐름과 화면의 요구 (초안 2, 2026-11-17 마지막 맞춤)**

표기: [결정] 사용자가 정한 것(출처 표기), [권고] 이 문서나 메인의 추천, [제안] 이 문서의 선택과 기본값, [확인 대기] 사용자 확인이 필요한 것, [요청] 다른 스펙에 하는 요구. 이 문서는 흐름과 정보의 스펙이다. 색, 모양, 배치 기하는 정하지 않는다(시각 시안은 사용자가 반려했고 시각 방향은 1.3의 메모대로 앱 안의 대안으로 정한다). 각 장소가 무엇을 하게 해야 하고, 무엇을 어느 우선순위로 보여야 하며, 어디로 이어지고, 엔진에서 무엇을 받는지를 정한다. UI 문구 예시는 라벨의 뜻을 보이려는 것이고 문구는 메시지 키로 따로 정한다.

**마지막 맞춤(2026-11-17 밤, `_notes/design/lc/spec/consolidation-log.md` "마지막 맞춤").** 이 문서는 통합 정리보다 먼저 써졌다. 이제 통합된 어휘(Hook 표시값 여섯, 플러그인·버전 정체, 덧씌우기 수명 `turn | release`, 블록 여섯과 기록 블록은 이벤트 구독만, `pluginReview.*` 이름과 오류 코드 범위, 프레임 종료 사유, 대화, 설정 범위, 프로젝트 기본 프로필 없음)를 따른다. 이 문서가 엔진 스펙에 한 요청은 처리됐다(8절): 테스트 대화의 엔진 쪽은 M5c §4.8이 유일한 소유자이고 이 문서는 창과 흐름만 정한다. 사용자 결정(밤): "지침 추가"는 허용된다(R33), "시험장"이라는 이름은 반려됐고 그 자리는 "테스트"다 [결정: 2026-11-17 사용자], 사용자 중지는 백그라운드 서브에이전트도 멈춘다, worktree는 플러그인이다. U1~U6은 모두 사용자가 정했다(U6: 코어는 알리기만, 대화 시작 훅이 폴더 경로 하나를 돌려주고, worktree는 그 위의 플러그인). 일회 사용의 입구는 입력창의 `/`이고 모든 유형이 같다(M5c §4.3.10).

### 화면 1. 목적과 범위

#### 1.1 왜 쓰는가

커버리지 점검(`_notes/design/lc/spec/crosscheck-1-coverage.md`)이 M6에 스펙이 없음을 확인했다. M5c, M5d, M5e와 엔진 설계가 UI 몫으로 넘긴 것이 갈 곳이 없고, 테스트 대화(Craft 전용 AI 대화)의 엔진 쪽 소유자도 없었다. 이 문서는 화면 쪽을 메우고, 엔진 쪽은 M5c §4.8이 소유한다(8절).

#### 1.2 정하는 것

| # | 내용 | 절 |
|---|---|---|
| 1 | 장소 목록과 각 장소의 일, 정보 위계, 상태, 데이터 | 3, 6, 7, 10 |
| 2 | 테스트 대화의 창과 흐름(엔진 쪽은 M5c §4.8) | 4 |
| 3 | 이동표와 근거를 실은 깊은 링크 | 5 |
| 4 | 엔진 스펙에 한 요청과 처리 결과 | 8 |
| 5 | 오늘의 앱에서 없애거나 바꾸는 것 | 9 |
| 6 | 수용 기준, 단계 나눔, 미결, 요구 추적 | 11~14 |

#### 1.3 정하지 않는 것

시각 디자인의 확정(색, 모양, 배치 기하), 문구 최종본, 엔진 내부 구현(M5c~M5e와 엔진 설계가 정한다), 플러그인 마켓과 내보내기, 격리 3단계, 다른 하네스 형식의 마이그레이션 기능(로드맵 M5g), worktree 분리(플러그인이 한다 [결정: 2026-11-17 사용자]), 플러그인 화면 배치를 사용자가 옮기는 일(P2).

**시각 방향 메모** [결정: 2026-11-17 사용자]. 이것은 시각 스펙이 아니라 방향이다. 사용자는 앱 안의 두 번째 시도(레일, 정거장, 조각)를 보고 방향은 나쁘지 않으나 완성도가 낮다고 했다. 그래프와 차트를 훨씬 적극적으로 쓰고, 외부 차트 라이브러리와 최신 사례를 조사해 쓰며, 여러 대안을 한 빌드에서 바꿔 볼 수 있게 나란히 만든다. 그래서 첫 걸음(M6-0)은 "개요와 플러그인 상세의 대안 셋을 앱 안에 만들기"다(`m6-plan.md` W15, AC-52). 이 문서의 정보 위계는 대안과 무관하게 그대로다.

#### 1.4 지키는 규칙

- 모델 컨텍스트에는 이 문서의 어떤 규칙도 줄을 더하지 않는다. 화면용 데이터는 기록과 화면에만 간다 [결정: 2026-11-12 사용자, 하네스 최소 원칙, M5e §1.3].
- 설명 글은 한 번의 조작 뒤에 둔다(정보 아이콘, 펼침). 경고는 항상 보인다 [결정: 사용자 규칙]. 화면은 글 벽이 아니다.
- 화면 용어는 2절의 어휘만 쓴다. 플러그인마다의 켜기·끄기 조작은 어디에도 없다 [결정: plugin-concept §6, PRD R2].

### 화면 3. 장소와 그 일

장소 번호는 이 문서가 정한 것이다. T는 대화 안의 접점, C는 Craft 영역이다.

#### 3.1 대화 쪽 접점

| 번호 | 장소 | 사용자가 할 수 있어야 하는 일 | 데이터 근거 |
|---|---|---|---|
| T1 | 프로필 칩 | 이 대화의 프로필을 본다. 도중에도 다른 프로필로 바꾼다. 권한 모드를 본다(권한 칩을 흡수). 한 번에 기본 프로필로 탈출한다(`default`가 오염됐으면 `profile.default.reset`, M5c §3.6). "이 프로필 편집"으로 C3에 간다. 새 대화는 기본값이 골라진 채 열린다 | M5c §3.4 `thread.setProfile`, `profile.defaultFor`, `ThreadProfileView` |
| T2 | Drive 표시 | 지금 누가 주도하는지(`기본 › Helm › 검증`)를 본다. 언제든 멈춘다. 중지는 스택 전체와 백그라운드 서브에이전트를 함께 멈춘다 [결정: 2026-11-17] | 엔진 설계 §2.6 `drive.frames`, M5d §4.9 규칙 58 `FrameMark` |
| T3 | 흔적 | Hook이 묻거나 막으면 카드, 고장이면 구별되는 카드, 조용히 고치면 작은 흔적. 흔적에서 이 턴의 기록과 원인 플러그인으로 간다 | M5d §4.9, M5e §4.2 `askedBy` |
| T4 | 일회 사용 입구(입력창의 `/`) | 프로필에 없는 검토된 플러그인을 모든 유형에 대해 이 턴에만 얹는다. 스킬, 명령, Drive, Hook 전용, 도구 전용 모두 `/`로 부르고 명령이 없는 플러그인은 `/<플러그인 이름>`이 전체를 얹는다. 이름 충돌 규칙은 M5c §4.3.10 [결정: 2026-11-17 사용자] | M5c §4.3, `plugin.invocables` |
| T5 | 프로필에서 빼기 명령 | 이 대화의 프로필에서 플러그인 하나를 뺀다(대화 안의 명령 `/profile remove <플러그인 이름>` [제안: 이름은 C0에서 확정]). 막은 카드에는 이 단추가 없다 | M5c `profile.put`, `profile.preview` |
| T6 | 초안 카드 | 빌더가 만든 초안을 보고 "이 대화에서 써 보기", "테스트에서 써 보기", "검토함으로 보내기"를 고른다 | M5c `plugin.draft.*`, `pluginReview.submitDraft` |
| T7 | 같은 폴더 경고와 승인 전 플러그인 알림 | 같은 폴더에서 다른 대화가 돌고 있음을 알고, 프로젝트 동반 플러그인이 승인 전이라 실행되지 않음을 안다 | `thread.create.sameFolder`, `project.get.pendingReview` |

T1의 [제안] 규칙: 탈출은 칩 메뉴의 맨 위 항목 하나다. 그 항목은 `thread.setProfile { profileId: "default" }`를 부른다. 현재 프로필이 이미 `default`이면 같은 자리가 "기본 프로필을 공장 값으로 되돌리기"(`profile.default.reset`, 미리 보기 뒤 확인)가 된다(M5c-7 적용, 8절). Drive가 도는 중이면 칩 메뉴에 "주도 중지"를 같이 둔다. 프로필 전환은 Drive를 멈추지 않기 때문이다(M5c §4.1.13은 플러그인이 목록에서 빠질 때만 프레임을 내린다).

T3의 흔적 종류 [제안]:

| 종류 | 뜻 | 형태 | 원천 | 기록이 꺼져 있을 때 |
|---|---|---|---|---|
| 묻음 | Hook이 승인 카드를 띄움 | 카드. "어느 플러그인이 물었나"와 사유 | `ToolApprovalBody.askedBy` | 그대로 보임 |
| 막음(의도) | Hook이 뜻을 가지고 막음 | 카드. 사유 | toolResult `details`, `Verdict: blocked_hook·blocked_guard` | 그대로 보임 |
| 고장 | Hook이 던짐, 시간 초과, 스키마 위반으로 거부가 대체됨 | 막음과 다른 종류의 카드. "고장"이라고 말한다 | `blocked_hook_fault`, `blocked_guard_fault` | 던짐과 시간 초과를 가르지 못하고 "고장"으로만 보인다(M5d §4.9 규칙 55) |
| 고침 | Hook이 조용히 결과를 고침 | 작은 흔적(턴 줄 아래). 무엇이 바뀌었는지 차이는 없고 크기만 | `HookRun.result=modified`, `size` | 보이지 않는다. 상태 "기록 꺼짐" |
| 이 턴에만 | 덧씌우기 | 흔적에 "이 턴에만". 도구를 얹었으면 "캐시가 한 번 새로 쓰여요"(정보 뒤) | `profile.applied.overlay`, `turn.start.cacheImpact` | 그대로 보임(로그) |
| 프로필 전환 | 프로필이 바뀜 | 구분선에 이전과 이후 이름. 권한 모드가 넓어졌으면 표시만 하고 묻지 않는다 | `profile.applied.permission` | 그대로 보임 |
| 초안 | 초안이 얹힌 턴 | "초안" 표시. 지표에 안 들어간다 | `OverlayMark.draft`, `TurnFlags.draftActive` | |

#### 3.2 Craft 영역

| 번호 | 장소 | 사용자가 할 수 있어야 하는 일 |
|---|---|---|
| C1 | 개요 [내비] | 지금 상태를 한 장으로 본다: 플러그인 그래프(어느 플러그인이 어느 블록에 이르나), 검토 대기 수, 살펴볼 것. 새 플러그인을 시작한다 |
| C12 | 플러그인 [내비] | 플러그인 목록: 모든 플러그인을 한 줄씩 보고(이름, 목적, 하는 일, 권고·강제, 건강, 쓰는 프로필) 줄에서 C2로 간다. 새 플러그인을 시작한다 |
| C2 | 플러그인 상세 [목적 화면] | 한 플러그인의 모든 것: 공통 스키마, 블록별 자리, 프로필별 설정 값, 지표, 버전과 검토 이력, 화면 칸, 테스트 대화, 시험하기 |
| C3 | 프로필 [내비] | 만들기, 복제, 지우기. 플러그인을 넣고 뺀다(비용, 충돌, 필요한 설정 값을 미리 본다). 권한과 코어 설정, 시작 Drive, 적용 범위 알림. "지침 추가": 한 줄을 쓰면 지침 플러그인 초안이 되어 검토함으로 간다(M5c §4.10) |
| C4 | 블록 상세 [목적 화면: 프로필 안에서 연다] | 한 블록의 네 겹(설정, Inject, 부품 교체, 앞뒤 Hook)과 잠긴 보장을 본다. 설정 값을 고친다. Hook 순서를 바꾼다 |
| C5 | 검토함 [내비] | 새 플러그인, 새 버전, 원본 변경, 삭제, 프로젝트 동반 플러그인을 승인, 돌려보내기, 버리기 한다 |
| C6 | 테스트 [내비] | 초안을 얹어 테스트 실행을 하고, 한 일을 그 자리에서 보고, 지난 턴에 돌려 보고, 테스트 대화로 고치고, 초안 버전을 비교한다 |
| C7 | 테스트 대화 창 [떠 있는 창] | Craft 어디서나 떠 있는 AI 대화. 보고 있는 것을 맥락으로 들고 시작한다 |

**Craft 내비 [결정: 2026-11-17 사용자]: 여섯 항목.** 개요(플러그인 그래프), 프로필, 검토함(대기 수 배지), 테스트, 지표, 플러그인(목록). 플러그인 목록은 독립 항목이고 플러그인 그래프는 개요에 둔다. 플러그인 상세(C2)와 턴 기록(C8)은 내비 항목이 아니라 다른 곳에서 이어지는 목적 화면이다(그래프의 노드, 목록의 줄, 흔적, 지표의 증거 줄, 테스트의 관찰 줄). 엔진 설정(오늘의 "엔진" 항목, 엔진 상태와 진단 P-15)을 Craft에서 설정 화면으로 옮기는 것은 [제안]이다. 오늘의 "성능 측정"의 운명은 [권고: 메인 세션, 확인 대기]다: 9.2에 코드 확인 결과와 권고가 있다. 옛 내비 여섯(개요, 확장, 테스트, 성능 측정, 구성, 엔진)의 대체 대응은 9.2.

### 화면 4. 테스트 대화 (창과 흐름)

#### 4.1 무엇인가

플러그인을 만들고 고치는 AI와 하는 대화다. **엔진 쪽 전부(표지, 목록·프로젝트에서 제외, 플러그인에 묶임, 숨은 `craft` 프로필, 쓰기 범위, 맥락 참조, 기록 범위, 보관, wire)는 M5c §3.6, §4.8, §4.9가 유일한 소유자다.** 이 절은 창과 흐름, 그리고 그 요구가 나온 오늘의 빌더 사실만 적는다. 오늘의 빌더(`xeon/packages/plugin-builder`)는 일반 대화 안에서 모델이 `authoring_start`를 부르면 시작하는 Drive 그룹이다.

#### 4.3 종류와 표지

엔진 쪽 규칙은 M5c §4.8이 정한다(요약: 표지 `thread.started.craftChat`, 목록·프로젝트·선택기 기본값 계산에서 제외, 플러그인 원본 폴더가 작업 폴더이자 쓰기 범위, 숨은 `craft` 프로필과 빌더 시작 Drive 상주, 턴은 `scope: craft`). 화면이 지킬 것: C2의 "테스트 대화" 단추가 그 플러그인의 가장 최근 테스트 대화를 열고 이전 대화 목록은 한 단계 안쪽에 둔다(`craftChat.open { reuse: "last" }`, O-10). 이 대화에는 프로필 칩(T1)이 없다.

#### 4.4 맥락을 들고 시작하는 법

규칙: 모델 컨텍스트에 줄을 더하지 않는다. 참조만 대화에 기록하고 모델은 도구로 필요한 만큼 읽는다 [결정: 2026-11-12 사용자, 하네스 최소 원칙]. `ContextRef`의 정의와 기록(`craft.context`), 읽는 도구(`authoring_context`)는 M5c §3.6, §4.8.8이 소유한다. 흐름:

| 단계 | 내용 |
|---|---|
| 1 | 사용자가 "고치기"나 "올리기"를 누른다. 화면은 `craftChat.open`에 `ContextRef`와 한 줄 의도를 준다 |
| 2 | 호스트가 테스트 대화를 만들거나 다시 연다. 참조가 대화 기록에 남는다 |
| 3 | 첫 사용자 입력은 한 줄 문장이다. 살펴볼 것에서 왔으면 그 발견의 `next.label`, 턴에서 왔으면 사용자가 쓴 한마디("다음부터 물어봐")다. 사용자에게 보이는 입력이다 |
| 4 | 빌더가 참조를 필요한 만큼 읽는다(발견이면 근거 묶음 `findings.bundle`) |
| 5 | 사용자는 문제를 다시 설명하지 않는다(craft-flow §3.6) |

기록되는 것(표지, 맥락, 초안, 검토 결정, 테스트 실행, 지표 제외)과 wire(`craftChat.open`, `craftChat.list`, `thread.list { include: "craft" }`, `craftChat.changed`)는 M5c §3.6, §4.8, §4.9, M5d §3.2·§4.6 규칙 36이 정한다. 이 문서는 정의를 되풀이하지 않는다.

#### 4.7 빌더가 새로 해야 하는 일의 대응

B-1~B-9는 엔진 설계 §1.4(재구현)와 M5c §4.9(초안·제출 경로)가 소유한다. 화면에 보이는 것: 기존 플러그인 고치기(C2의 "고치기"), 세 방식 모두 만들기(C1의 "새 플러그인"), 설치 단추 없이 초안 카드와 "검토함으로 보내기", 종류 선택에 "플러그인 그룹"이 없음, 초안 목적 한 문장을 검토함에서 고침.

### 화면 5. 이동

#### 5.1 이동 위치 값

화면 위치는 하나의 값으로 표현해 깊은 링크가 된다 [제안].

```ts
type CraftLocation = {
  place: "overview" | "plugins" | "plugin" | "profile" | "block" | "review" | "test" | "turn" | "metrics";   // 내비 여섯(overview, profile, review, test, metrics, plugins)과 목적 화면(plugin 상세, block, turn)
  id?: string;                // plugin 이름, profile id, block id, review itemId, runId
  tab?: string;
  focus?: EvidenceRef | { findingId: string };  // 근거 한 줄을 강조
  returnTo?: { threadId: string; turnId?: string } | CraftLocation;  // 뒤로 가기
};
```

근거는 id로만 싣는다. 내용은 도착한 화면이 `turnRecord.get`, `findings.evidence`로 읽는다.

#### 5.3 규칙

- 대화에서 Craft로 간 이동은 `returnTo`를 가진다. Craft의 모든 화면에는 "대화로 돌아가기"가 한 번에 있다.
- C7은 한 번 열리면 Craft 안의 다른 화면으로 이동해도 떠 있다. 이동하면 화면 맥락이 새 참조로 제안되지만 사용자가 보내기 전에는 대화에 기록되지 않는다 [제안].
- 막은 카드(T3)에는 "프로필에서 빼기" 단추가 없다. 길은 T5 명령과 T1의 "이 프로필 편집"이다 [결정: craft-flow R5].

[구현: cv9, 2026-11-22, AGE-31·AGE-34] 데스크톱의 C3은 크래프트 내비 맨 위 "프로필"(화면 id `profile`, 크래프트 영역의 처음 화면)이고 화면은 프로필 캔버스(G5) 하나다. 시안 전환기는 없다.
- 읽기: 화면을 열 때마다 `profile.list`(프로필과 공통 묶음), `plugin.list {}`(카드 전부), `blocks.describe`(Hook 이름마다의 자리)를 읽고, 보고 있는 프로필의 `blocks.applied { profileId }`와 `profile.preview { id }`를 읽는다. 공통 묶음은 베이스로 앞에 선다. 내부 부품(`internal`)은 어떤 프로필이나 공통 묶음에 들었을 때만 캔버스와 목록에 선다(프로필에 든 이름은 다 보인다).
- 판의 종류와 자리는 카드에서 정한다: Drive 칸이 있으면 Drive, Hook이 있으면 Hook(자리는 첫 Hook 이름의 계약 위치), 도구나 MCP 서버를 주면 도구, 나머지는 Inject. 카드에 없는 값(작성자, 라이선스, 기능 requires·provides, 묶음)은 그리지 않는다.
- 순서 바꾸기: 같은 자리의 다른 판 위에 끌어 놓거나, 판에서 Alt+↑↓, 상세와 블록 상세의 앞·뒤 단추. 바꾸면 바로 그리고 `profile.put { profile, baseRev: rev }`로 쓴다. 이름과 설정은 저장된 값 그대로이고 플러그인 순서와 시작 Drive만 바뀐다. 거절되면 저장된 모양으로 돌아가고 까닭이 한 줄로 보인다(`rev`가 달라 거절되면 목록을 다시 읽는다). 저장 뒤 적용 블록과 이슈를 다시 읽는다.
- 미리 잠금: 카드에 `requiredByCore`가 있는 플러그인은 프로필에서 빼는 단추, Delete, 목록으로 끌어 빼기가 모두 막히고 "뺄 수 없음"과 기대는 코어 부분의 이름이 보인다. 엔진은 이 플러그인을 프로필보다 먼저 정해진 차례로 싣는다(호스트 `forcedPlugins`). 그래서 순서 바꾸기(끌기, Alt+↑↓, 앞·뒤 단추)도 막고 그 까닭을 한 줄로 말한다. 엔진의 `plugin.requiredByCore` 거절(3626)은 그대로 둔다(뒤늦은 거절도 같은 글로 보인다).

#### 9.3 이 문서가 확인하지 못한 것

스위치 위치와 내비 여섯은 코드에서 확인했다(`WORKBENCH_NAV`의 id: `overview, extensions, tests, metrics, compose, engine`, 라벨 키 `desktop.shell.nav.*`: 개요, 확장, 테스트, 성능 측정, 구성, 엔진. 성능 측정 화면의 내용은 9.2에 적었다. 데스크톱 스펙은 "시험 실행"이라 적어 코드와도 다르다). 구성기(`views/compose/`)와 `views/tests/`, `views/measure/`의 세부 기능은 줄 단위로 읽지 않았다. 구현 트랙의 첫 일로 해당 줄을 다시 읽고 이 절의 처리 표를 고친다. 이 문서의 화면 문구는 대화 쪽 접점(T)에서 `terms-rules.ts`의 chat 금지어(루프, 코어, 컴팩션, 단계 경계 등)를 쓰지 않는다.

### 화면 10. 상태

데스크톱 스펙 §6.0의 여섯 상태는 빈, 읽는 중, 오류, 오프라인, 권한 필요, 긴 내용이다. 이 문서는 하나를 더한다: 엔진 미준비.
