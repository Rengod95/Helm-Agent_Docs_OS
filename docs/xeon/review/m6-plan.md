# M6 구현 계획 (크래프트)

- 기준: 브랜치 `m4/cyP`와 ADR-0023. 이 마일스톤은 M4에서 Craft에 묶인 종료 조건(Y2~Y5, Y8~Y10)을 옮겨 받아 새 개념(플러그인과 프로필, 검토함, 테스트 대화)으로 다시 정한다(`product.scope.spec`의 2026-11-17 항목).
- 원천: 화면 스펙 `docs/xeon/review/m6/craft-flows.md`(흐름 제1부와 화면 제2부), 엔진 계획 `docs/xeon/review/m5-plan.md`(Z1~Z16), 엔진 스펙 `docs/xeon/review/m5/*`, `review.m4-plan`(이월된 Y 조건), `L4.desktop-ux.spec`(§4.9 Craft 절을 이 계획이 대체한다).
- 종료 조건 번호는 **W1…**이다(M3는 X, M4는 Y, M5는 Z). 각 조건은 요구(`m5-plan.md` §5의 R번호)와 화면 수용 기준(`craft-flows.md` 화면 11의 AC 번호)에 묶는다.
- 디자인은 앱 안에 직접 만들고 Craft v2 HTML 시안은 반려됐다 [결정]. 이 계획과 화면 스펙은 흐름과 정보의 구조까지 정하고 색, 모양, 배치 기하, 그림 언어는 사용자 판단 뒤로 미룬다. 화면은 caustic 부품과 토큰을 쓴다. 화면 트랙은 Opus 리드가 맡는다(Sonnet·Haiku의 디자인 트랙은 반려된 적이 있다).
- 기간은 지금의 리드 병렬 방식 기준 어림이고 측정한 값이 아니다. 전체 검사와 CI는 병합 직전에만 돈다.

## 1. 범위

M6은 Craft(흐름과 화면)다. 사용자가 플러그인을 만들고, 검토하고, 프로필에 넣고, 대화에서 쓰고, 관찰하고, 고치는 순환(`craft-flows.md` 흐름 1)을 화면으로 만든다.

| 묶음 | 내용 |
|---|---|
| 대화 쪽 접점 | 프로필 칩(권한 칩 흡수, 탈출), Drive 표시(`기본 › Helm › 검증`, 중지), 흔적(묻음, 막음, 고장, 고침, 이 턴에만, 프로필 전환, 초안), 일회 사용(입력창의 `/`), 프로필에서 빼기 명령, 초안 카드, 같은 폴더 알림과 승인 전 알림 |
| Craft 영역 | 개요(플러그인 그래프와 목록), 플러그인 상세(공통 스키마, 화면 칸), 프로필("지침 추가" 포함)과 블록 상세, 검토함, 테스트(테스트 실행, 그 자리 관찰, 지난 턴에 돌려 보기, 초안 비교), 테스트 대화 창, 턴 기록, 지표, 프로젝트 |
| 정리 | 오늘의 앱에서 없애거나 바꾸는 것(플러그인별 스위치, 이 대화의 프로필 칸, 권한 칩, 맥락 칸과 "이긴 범위" 표지, 구성기의 "새 그룹", 설치·제거 대화 상자, 옛 내비) |

**Craft 내비 [권고, 확인 대기]:** 다섯 항목(개요, 프로필, 검토함, 테스트, 지표). 플러그인 상세와 턴 기록은 다른 곳에서 이어지는 목적 화면이고 엔진 설정(오늘의 "엔진" 항목)은 Craft에서 설정 화면으로 옮긴다. 장소 이름 "테스트"는 사용자의 "시험장" 반려에 대한 권고이고 사용자의 다른 안은 "실험실"이다 [확인 대기]. 오늘의 "성능 측정" 화면의 운명은 [미결]이다. 코드를 읽어 보니 이 화면은 평가 비교가 아니라 열린 대화의 최근 턴으로 만든 성능 첫 화면(최근 달라진 것, 이상 신호, 읽어 볼 턴, 플러그인 부담 표, 턴 번호 곡선), "Turn 다시 보기", 승격 보고(`group.promotion`)다. 권고는 앞의 둘을 지표(W9)와 턴 기록으로 흡수하고 승격 보고는 따로 결정하는 것이다.

## 2. 단계와 의존

화면은 엔진이 그 데이터를 줄 수 있게 된 뒤에 만든다. 엔진 의존은 `m5-plan.md`의 Z번호로 적는다. 화면은 메서드의 존재로 준비 여부를 판단하고 준비되지 않은 데이터는 가짜 0이나 빈 목록으로 그리지 않는다(`craft-flows.md` 화면 10.3의 NR 코드).

## 3. M4에서 옮겨 받은 조건 (Y2~Y5, Y8~Y10)

`review.m4-plan` §2의 Y 조건 가운데 Craft에 묶인 것은 M4 종료 조건에서 빠졌다(번호는 다시 쓰지 않고, 이미 켜진 시험 줄 Y4·Y10의 host 쪽은 계속 돈다). 각 조건을 새 개념에 어떻게 대응하는지 적는다. 근거 표시: "대응"은 새 종료 조건으로 이어지는 것, "삭제"는 새 개념에서 의미가 없어 뺀 것이다.

|---|---|---|---|
| Y2 | 크래프트 P-13, P-15~P-21이 가짜 엔진 위에서 여섯 상태를 보이고 대화 ↔ 크래프트를 오가면 같은 대화·스크롤·오른쪽 탭으로 돌아옴 | 대응. 장소 목록이 새 장소(T1~T7, C1~C11)로 바뀌고 상태는 여섯에 "엔진 미준비"를 더한 일곱이다. "오가면 돌아옴"은 모든 Craft 화면의 `returnTo`와 "대화로 돌아가기"로 일반화한다 | W11, W12 |

## 4. 종료 조건 (W1~W14)

각 줄은 시험 하나 이상에 묶는다(시험 이름은 [제안]이고 트랙이 확정한다). 화면 수용 기준 AC는 `craft-flows.md` 화면 11이다. 서버 렌더 시험, 가짜 엔진 위의 여섯 상태 시험, 화면 점검 스크린숏, Linux e2e를 쓴다. 장소마다 일곱 상태(빈, 읽는 중, 오류, 오프라인, 권한 필요, 긴 내용, 엔진 미준비)를 정의하고 해당 없음도 명시한다(AC-45).
