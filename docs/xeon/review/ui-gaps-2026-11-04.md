# 시안에 없지만 구현에 필요한 화면 (2026-11-04)

사용자 지시(2026-11-04): 시안에 없어도 실제 구현에 필요한 화면과 UX는 설계해 구현에 반영한다. 다시 묻지 않는다. 이 문서는 조사와 설계까지이고 제품 코드는 바꾸지 않았습니다. 구현은 메인 세션이 §4 묶음으로 나눕니다.

## 1. 방법과 한계

- 와이어 메서드 165개 이름을 `packages/contracts/src/wire-settings/wire/*.ts`에서 뽑아 `apps/desktop/src`와 `packages/client/src`의 호출과 대조했습니다(테스트 파일 제외). 호출이 0인 것만 후보로 삼고, 오류 이름은 뺐습니다.
- 내비 표(`views/shell/nav.ts`)와 등록(`views/desktop-registry.tsx`, `views/workbench/index.tsx`)을 대조했습니다.
- 시안은 현행 폴더(a·b·c·d·e·f 계열, `p01`~`p15`, `o02`~`o09`, `s04`)의 `NOTES.md`와 키워드 grep으로 봤습니다. `wb-*`, `wb2-opus`처럼 `Xeon` 시절 낡은 폴더는 근거로 쓰지 않았습니다.
- 한계: 시안 대조는 `NOTES.md`와 grep이라 시안 안의 세부 상태는 직접 열어 보지 않았습니다. 와이어 결과 모양(`group.promotion`, `notify.list` 등)은 이름과 스키마 머리만 봤고 화면 설계 전에 구현자가 다시 읽어야 합니다. 맥에서 화면을 띄워 보지 않았습니다.

## 3. 설계 (종류 A, 그리고 B 중 구현 입구가 없는 U-06, U-07)

공통: 부품은 caustic(`Alert`, `Button`, `Dialog`, `Popover`, `ListDescription`, `InfoTip`), 아이콘은 `@caustic/react/icons`, 문구는 `packages/client/src/i18n/locales/ko.json`과 `en.json` 둘 다. 경고(건너뛰기, 실패, 자동 꺼짐 질문)는 화면에 바로 보이고, 동작 방식 설명은 정보 아이콘 뒤입니다(DP-58). 실패 `Alert`는 목록 바로 위입니다(DP-28). 크래프트는 전역만 다룹니다.

### U-01 외부 훅 자동 꺼짐 질문

**왜 필요한가.** 사용자 결정(2026-11-04): 연속 5회 실패면 끄기 전에 사용자에게 묻는다. 확장은 구현됐다. 외부 훅(`hook:<이름>`)은 호스트가 같은 질문을 만들어 `asked`에 넣고 휘발 이벤트 `scope.handler_failed { asksDisable: true }`까지 보내지만, 화면이 읽을 값도 답할 wire도 없다. 질문은 `canAsk`(연결된 클라이언트가 있을 때)가 참이므로 만들어지고, 답이 없으면 훅은 켜진 채 계속 실패한다(같은 주체에 겹쳐 묻지 않음).

**자리.**
1. 크래프트 개요(`craft/selection-panel.tsx`)에서 `hook:` 슬롯을 고르면 보이는 훅 상세 위에 `Alert tone="warning"` 질문을 둔다(확장의 `KeepOffAlert`와 같은 모양 재사용).
2. 대화 영역 "런타임" 탭 맨 위에, 질문이 있으면 같은 `Alert`를 확장 질문과 한 목록으로 모은다. 탭 이름 옆에 질문 수 배지(DP-27: 0이면 숨김).
3. 크래프트 확장 목록 위 danger `Alert`(DP-28)의 개수에 훅 질문을 더한다. 누르면 해당 훅으로 간다.

**사용자가 하는 일.** "끄기" 또는 "켜 두기"를 고른다. 질문 문장은 어느 훅이 몇 번 연속 실패했는지, 마지막 실패 메시지 한 줄을 보인다. "왜 5번인가", "켜 두면 어떻게 되나"는 정보 아이콘 뒤다.

**상태.**
- 읽는 중: 훅 상세 Skeleton, 질문 자리는 비워 둔다.
- 질문 있음: warning `Alert` + 두 버튼. 질문이 켜 둔 채라는 사실("지금은 켜져 있어요")을 문장에 넣는다.
- 답하는 중: 두 버튼 잠금.
- "끄기" 뒤: 결과 한 줄 `role="status"`와 "다시 켜기" 버튼(`KeepOffAlert`의 kept-off와 같다).
- "켜 두기" 뒤: 결과 한 줄. 실패 장부가 비워지므로 다시 5번 실패하면 또 묻는다고 정보 아이콘에 적는다.
- 이미 꺼짐(`autoDisabled`): danger 아이콘 면 + "다시 켜기".
- 답 실패(`hooks.notFound`, 연결 끊김, 안전 모드): 한 줄 오류와 "다시 시도". 안전 모드면 훅이 실리지 않으므로 질문 자체를 숨긴다.
- 연결 끊김: 버튼 잠금, 마지막으로 읽은 질문은 흐리게(§6.0 오프라인 규칙).
- 다른 클라이언트가 먼저 답함: 다음 목록 읽기에서 질문이 사라지면 "다른 곳에서 답했어요" 한 줄.

**쓰는 와이어(없는 것은 새로 필요).**
- `hooks.list`의 `HookEntry`에 선택 필드 `keepOffQuestion?: { rule: "consecutive" | "rate"; consecutive; windowFailures }`와 `autoDisabled?: boolean` 추가([제안], `ExtKeepOffQuestion`과 같은 모양 재사용). 호스트는 `autoDisabler.questions()`와 `disabled()`에서 `hook:` 키로 채운다(`ext-read-sources.ts:358`과 같은 방식).
- 새 메서드 `hooks.disableConfirm { hook }`(끄기)와 `hooks.reenable { hook }`(켜 두기·다시 켜기) [제안]. 호스트는 `autoDisabler.answer("hook:<hook>", true)`와 `reenable("hook:<hook>")`를 부른다. 없는 훅은 이미 있는 `hooks.notFound`를 돌려준다. 결과는 `ExtAppliedResult`와 같은 `{ appliesAt, diagnostics }`.
- 갱신 신호는 이미 있다. 데스크톱 `asksDisable`이 `stream.chunk`에서 목록 다시 읽기를 부른다(`app/workbench-commands.ts:33`). 훅 쪽도 이 경로를 쓴다. 훅 소유자는 이벤트에 `owner: "hook:<이름>"`로 실린다.
- 다음 시작에도 꺼진 채로 둘지: 확장은 먼저 설정 `ext.<이름>.enabled=false`를 쓴다(`workbench-commands.ts:110`). 외부 훅의 설정 키가 있는지 이 조사에서 확인하지 못했다. 구현자가 먼저 확인한다. 없으면 "이번 실행에서만 꺼요" 한 줄을 결과에 보이고 영속은 §5 결정 D-2로 올린다.

**caustic.** `Alert`, `Button`, `InfoTip`(`craft/info-tip.tsx`), `Badge`.

**문구(ko).**
- 제목: "{훅} 훅이 {n}번 연속 실패했어요"
- 본문: "지금은 켜져 있어요. 끌까요?"
- 버튼: "끄기", "켜 두기"
- 결과: "껐어요. 다시 켜려면 아래 버튼을 눌러 주세요." / "계속 켜 둘게요. 또 {n}번 실패하면 다시 물어볼게요."
- 정보 아이콘: "연속 5번 실패하거나 최근 50번 중 절반 이상 실패하면 물어봐요. 답하기 전에는 끄지 않아요."
- 실패: "답을 보내지 못했어요. 다시 시도해 주세요."

**크기** M(와이어 3개 + 호스트 2 + 화면 3자리). **겹치는 파일:** `packages/contracts/src/wire-settings/wire/ext-read.ts`, `ext-read-methods.ts`, `apps/host/src/handlers/m4/ext-read.ts`, `apps/host/src/assembly/m4/ext-read-port.ts`, `ext-read-sources.ts`, `craft/selection-panel.tsx`, `workbench/craft-parts.tsx`, `runtime/runtime-tab.tsx`, `app/workbench-commands.ts`, `views/commands.ts`, ko/en 카탈로그. **먼저:** 위 영속 확인. 스펙 `desktop-ux` §10.1에 W-36 옆 새 행과 `X.operations` §4.3 질문 절에 훅 답 경로를 같은 커밋에 쓴다.

### U-05 훅이 꺼진 뒤 되짚기

U-01에 포함. 꺼진 훅 상세에 최근 실패 세 줄(시간, 지점, 메시지)과 "다시 켜기". 실패 기록은 데스크톱이 이미 받는다(`EngineMirror.handlerFailures`, 상한 500, `owner`가 `hook:`로 시작). 새 wire 없음. S.

### U-02 재시작이 필요한 일 뒤 "지금 다시 시작"

**왜 필요한가.** 설치 결과가 `appliesAt: restart`이면 "앱을 다시 시작하면 목록에 나타나요"라고만 알린다(`install-dialog.tsx`). 버전 되돌리기도 재시작 뒤에 돈다. 사용자는 앱을 직접 끄고 켜야 한다. 안전 모드 진입·해제(U-06)도 같은 동작이 필요하다.

**자리.** 상태 표시줄 엔진 칸 Popover(`d02`가 이미 정한 자리)에 "다시 시작이 필요해요" 줄 + "지금 다시 시작". 설치 결과 화면과 되돌리기 결과 화면에는 같은 단추를 한 줄 아래에 둔다. 창 위 띠는 만들지 않는다(DP-05).

**사용자가 하는 일.** 단추를 누른다. 진행 중 턴이나 승인 대기가 있으면 확인 `Dialog`(영향 목록: 진행 중 턴 n, 대기 승인 n)가 먼저 뜨고 기본 초점은 "나중에".

**상태.** 필요 없음(단추 없음) / 필요함(단추 + 이유 목록) / 확인 중 / 다시 시작 중(엔진 칸이 이미 `restarting` 표시, 쓰기 명령은 앱이 `switching`처럼 거절) / 돌아옴(토스트 "다시 시작했어요") / 실패(`failed` 상태의 기존 "엔진 다시 시작"과 "진단 복사"로 이어진다) / 웹(단추 없음, "서비스를 다시 시작해야 해요" 한 줄).

**쓰는 와이어.** 셸 명령 `engine_restart`를 `engine_restart { safeMode?: boolean }`로 넓히고 `failed`가 아니어도 되게 한다(Rust `relay.rs`, `transport/ipc.ts`). `NotFailed` 거절은 "정상 상태에서는 확인된 요청만"으로 바꾼다. 재시작 필요 목록은 데스크톱 로컬 상태(설치 결과의 `appliesAt`, 되돌린 이름)로 모으고 엔진이 `running`으로 돌아오면 비운다. 호스트 wire 변경 없음. 맥에서 동작을 확인해야 한다.

**문구.** "다시 시작이 필요해요" / "{n}개 변경이 다시 시작한 뒤에 적용돼요" / "지금 다시 시작" / "나중에" / 확인: "진행 중인 턴 {n}개가 멈춰요. 그래도 다시 시작할까요?".

**크기** M. **겹치는 파일:** `src-tauri/src/relay.rs`(와 supervisor), `transport/ipc.ts`, `views/status-bar.tsx`, `views/workbench/install-dialog.tsx`, `rollback-dialog.tsx`, `views/commands.ts`. **먼저:** 없음. 스펙 §10.1 W-35 행을 같은 커밋에 고친다.

### U-06 안전 모드 제안과 진입

시안은 `d02-shell-life`와 `f03`에 있다. 구현 입구만 없어 U-02와 한 묶음이다. `host.status.suggestSafeMode`와 `startupFailures`를 `app/setup.ts` 읽기에 더해 `d02` 카드(입력창 자리)와 칩을 그린다. 확정 버튼 "안전 모드로 시작"은 `engine_restart { safeMode: true }`. 해제는 "안전 모드 끄고 다시 시작". 웹은 단추 없음.

### U-03 입력창 첨부

**왜 필요한가.** 호스트에 `attachments.add`(소스: 경로, 붙여넣은 바이트와 mime, URL; `contracts/capabilities/defs/dialog.ts:850`)가 있다. 사용자가 이미지를 붙여넣거나 파일을 끌어 놓을 길이 없다.

**자리.** 입력창(`views/composer.tsx`): 입력 줄 왼쪽에 `IconButton`(클립) "첨부", 입력 위에 첨부 칩 줄. 입력창 전체가 끌어놓기 영역이다.

**사용자가 하는 일.** 단추로 파일 고르기(셸 `pick_folder`와 같은 방식의 파일 고르기가 없다. 아래 참고), 파일 끌어놓기, 클립보드 이미지 붙여넣기, `@경로` 입력. 칩의 x로 보내기 전에 뺀다.

**상태.** 없음 / 올리는 중(칩 `Progress`) / 올림(이름, 크기, 이미지는 썸네일 자리 아이콘) / 실패(칩에 danger 아이콘 면 + 한 줄 이유, "다시 시도"와 "빼기") / 너무 큼 / 지원 안 하는 형식 / 열린 대화 없음(단추 잠금) / 턴 진행 중(큐에 넣는 입력과 같은 규칙을 따른다) / 연결 끊김(잠금) / 웹(파일 선택 `<input>`, 경로 입력은 없음).

**쓰는 와이어.** `attachments.add { threadId, source }`. 경로 소스는 이 컴퓨터의 경로만 되므로 원격 대상이면 `data` 소스로 보내거나 단추를 숨긴다. 대화에 붙은 첨부를 입력과 함께 보내는 방법(턴 시작 인자 `attachments`인지 먼저 `attachments.add`를 부르는지)은 구현자가 `thread` 시작 스키마에서 확인한다. 파일 고르기는 `tauri-plugin-dialog`(승인됨)로 `pick_file` 셸 명령을 더하면 된다: 새 의존성은 아니다.

**caustic.** `IconButton`, `Chip`, `Progress`, `Alert`, 끌어놓기 영역 강조는 토큰만.

**문구.** "첨부" / "파일을 놓으면 첨부해요" / "{이름} 올리는 중" / "올리지 못했어요: {이유}" / "{크기}를 넘는 파일은 붙일 수 없어요" / 정보 아이콘: "이미지와 텍스트 파일은 모델에 그대로 전달돼요. 시크릿이 든 파일은 붙이지 마세요."

**크기** M. **겹치는 파일:** `views/composer.tsx`, `composer-model.ts`, `app/session.ts`(보내기), `src-tauri`의 파일 고르기 명령, 카탈로그. **먼저:** 시작 스키마의 첨부 필드 확인. 크기 상한은 호스트 값을 읽는다(없으면 §5 D-3).

### U-04 승격 보고 읽기

### U-07 구성 내비 항목의 화면 없음

## 5. 사용자 결정이 필요한 것

결정 기록(`_notes/m4-decisions.md`)과 스펙을 grep해 답이 없음을 확인한 것만 적는다.

- **D-1 작업대 내비의 구성 항목.** 구성기가 들어오기 전 `compose` 항목을 숨길지(내비 5개) 둘지. 기록에는 "구성" 항목을 둔다는 결정(Q1 B)만 있고 미구현 동안의 모양은 없다. 추천: 그대로 두고 빈 상태에 "곧 들어와요"를 쓴다.
- **D-2 외부 훅을 끈 뒤 다음 시작에도 꺼 둘지.** 확장은 설정에 꺼짐을 써서 유지한다. 훅의 설정 키가 확인되지 않았다. 추천: 확장과 같게 영속한다(키가 없으면 이번 실행에서만 끄고 그 사실을 문구에 쓴다).
- **D-3 첨부 크기 상한과 형식.** 결정 기록에 없고 스펙에서 grep한 `attachments` 상한도 확인하지 못했다. 추천: 호스트가 정한 값을 읽어 쓰고 화면은 값을 새로 만들지 않는다.
- **D-4 의존성 승인.** 앱 업데이트·트레이·OS 알림(B-10)은 `tauri-plugin-updater`, `tauri-plugin-notification`, 트레이 기능이 필요하고 승인 목록(`Stagehand`, `objc2-local-authentication`, `tauri-plugin-dialog`, `gitleaks`)에 없다. 추천: 승인 전에는 시안(`d02`)대로 구현하지 않고 상태 표시줄 Popover의 앱 안 알림(토스트)만 둔다.
