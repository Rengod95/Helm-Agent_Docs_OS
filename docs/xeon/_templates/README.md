# 문서 템플릿과 작성 규칙

## 프런트매터

```yaml
---
id: L1.loop.spec            # <층>.<도메인>.<종류>. engineering은 eng.<도메인>.<종류>, ADR은 adr.NNNN
layer: L1                   # F | X | L0 | L1 | L2 | L3 | L4 | product | architecture | eng | adr | meta
domain: loop
kind: spec                  # readme | spec | design | plan | guide | adr | review
status: draft               # draft | review | accepted
depends_on: [F.extensions.spec, eng.events.design]   # 이 문서가 전제하는 문서 id
binds: [xeon/packages/core-loop/**]                  # 이 문서가 구속하는 코드 경로 glob
---
```

- `id`는 저장소 전체에서 유일하다.
- `depends_on`은 실제로 내용을 가져다 쓰는 문서만 적는다.
- `binds`는 이 문서를 근거로 구현되는 코드 경로다. 라우팅이 이 값으로 문서를 고른다.

## 문체 규칙

- 한국어 한다체로 쓴다.
- '축', '박다', '가른다', '닿다'를 쓰지 않는다. '장면' 대신 '유즈케이스'를 쓴다.
- 사물과 개념을 사람처럼 쓰지 않는다. 예: "모듈이 원한다", "이벤트가 기다린다".
- "A가 아니라 B" 형태의 구호 문장을 쓰지 않는다.
- 표지 태그는 다음 네 가지를 쓴다.
  - `[결정]`: 사용자 결정. `_research/decisions-log.md`나 ADR을 근거로 단다.
  - `[제안]`: 작성자의 설계 선택.
  - `[가정]`: 확인하지 않은 전제.
  - `[미결]`: 사용자 확인이 필요한 항목. 문서 끝 "미결 사항" 절에도 모은다.
- 조사 근거는 `_research/` 파일과 절, 또는 원문 URL·소스 경로로 단다.
- 코드 식별자, 타입, 패키지 이름은 문서 사이에서 같은 문자열로 쓴다. 이름은 F 문서가 정한 것을 따른다.

## spec.md 골격

1. 목적과 범위: 정하는 것, 다루지 않는 것
2. 용어
3. 인터페이스: TypeBox 스키마나 TypeScript 시그니처. 서비스 API, 모델 도구, 이벤트, 레코드
4. 동작 규칙: 상태, 순서, 원자성, 재생 규칙
5. 실패와 경계 사례
6. 설정 노출: F5 설정 스키마 키, 범위, L4 노출(화면, 명령, 파일)
7. 확장 지점: on 지점(fold), post, drive와의 관계
8. 다른 문서와의 인터페이스: 제공, 요구
9. 수용 기준: 테스트로 확인할 수 있는 문장
10. 미결 사항

## plan.md 골격

1. 목표와 마일스톤 배치: M0, M1, M2 이후
2. 패키지와 파일 배치
3. 작업 분해: 작업 id, 내용, 선행 작업, 예상 규모
4. 채택 코드: 그대로 쓰는 패키지와 정확한 버전, 포크 원본 경로와 바꿀 점
5. 단위 테스트 목록: 테스트 이름과 확인할 동작
6. 완료 기준
7. 위험과 대응

## design.md 골격

1. 문제
2. 선택지 비교(표)
3. 선택과 근거
4. 구조와 흐름(필요하면 Mermaid)
5. 결과로 생기는 제약

- 구조와 흐름의 세부 주제(투영, 재생, 버전 등)가 길면 4절과 "결과로 생기는 제약" 사이에 주제별 절로 나눠 둘 수 있다. 순서는 위 다섯 항목 순서를 지킨다.
- 구속 문서(`engineering/`)의 design은 "결과로 생기는 제약" 뒤에 구현 작업자 규칙(`<접두>-NN`), 수용 기준, 미결 사항 절을 둔다. 규칙 항목은 guide의 규칙 형식(이유, 강제, 좋은 예, 나쁜 예)을 따른다.

## guide.md 골격

1. 적용 범위: 어떤 코드와 작업에 적용되는가
2. 규칙: 번호를 붙이고, 각 규칙에 이유와 예시(좋은 예, 나쁜 예)를 단다
3. 강제 수단: 린트 규칙, 검사 스크립트, 리뷰 항목
4. 예외와 승인 절차

## ADR 골격

1. 상태와 날짜
2. 맥락
3. 결정
4. 결과: 좋은 점, 감수할 점
5. 대안
