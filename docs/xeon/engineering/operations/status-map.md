# 구현 상태 지도

이 문서는 M3에서 구현하기로 정한 기능이 지금 어디까지 왔는지 층별로 보여 줍니다. 판단의 근거는 요구 장부(`review.m3-lower-requirements` §3), M3b 트랙 계획(`review.m3b-plan` §2), 스펙의 구현 표기, 이월 목록입니다. 근거가 없는 항목은 "확인 안 됨"으로 적었습니다. 이 문서는 소스를 다시 읽어 완료를 확인한 결과가 아닙니다.

## 1. 읽는 법

### 1.1 장부 상태 칸

`review.m3-lower-requirements` §3의 상태 칸은 그 행을 누가 맡았는지를 가리킵니다.

| 값 | 뜻 |
|---|---|
| `M3a` | M3a에서 끝난 행입니다. |
| `M3b:<트랙>` | 그 행을 맡은 M3b 트랙입니다. 완료를 뜻하지 않습니다. 완료된 행도 B6 판정 전까지 이 값이 그대로 남습니다. 그래서 장부 숫자만으로는 M3b 트랙이 끝났는지 알 수 없습니다. |
| `M4` | M4로 옮긴 행입니다. 이 판에는 행 전체가 M4인 요구가 없습니다. 화면과 외부 훅 부분은 행 본문에 M4로 적었습니다. |

### 1.2 장부 집계

`cd xeon && bun scripts/req-ledger.ts`를 2026-10-29에 실행한 결과입니다.

- 이월 목록(`review.m3-lower-requirements` §9 표)은 37개이고, 장부 검사 실패는 0건입니다.
- 트랙 가운데 `B4-DSK`, `B5-REL`, `B5-CLN`은 장부 행이 없습니다. 이 트랙들은 이월 목록 항목으로만 추적합니다.

### 1.3 상태 어휘

| 상태 | 판정 기준 |
|---|---|
| 구현됨 | 장부 `M3a` 행이거나, 스펙에 "구현됨" 또는 "[구현: …]" 표기가 있고 소관 트랙에 이월 항목이 없습니다. |
| 부분 | 소관 트랙의 이월 목록에 미완 항목이 남아 있습니다. 구현 표기가 있어도 이월이 있으면 "부분"입니다. |
| 확인 안 됨 | 장부가 M3b 트랙에 배정했으나, 구현 표기도 이월 항목도 찾지 못했습니다. 완료인지 미완인지 이 문서로는 알 수 없습니다. 이월 항목이 없다는 사실이 완료를 뜻하지는 않습니다. |
| M4 이월 | `review.m3b-plan` §1.2, 장부 본문, 이월 목록이 M4로 옮긴 항목입니다. |

- "부분"은 트랙 단위로 판정했습니다. 이월 항목이 행 하나의 기능과 정확히 맞는지는 항목마다 다릅니다. 항목별 내용은 §5에 있습니다.
- 이 문서에서 "M3b 트랙 완료"라는 말은 장부 칸이나 스펙 표기로 확인된 경우에만 씁니다.

### 1.4 근거 요구 id

- 근거 요구 id는 `M3-REQ-NN`의 `NN`입니다. 예를 들어 `01`은 M3-REQ-01입니다.
- M2에서 끝난 항목(예: `xeon secret`, `xeon config`)은 M3 장부에 없으므로 이 표에 넣지 않았습니다.

- 제품 이름에 묶인 값(앱 디렉터리 이름, 설정 파일 이름, 대행 UA)의 소유 문서는 아직 정하지 않았습니다. M3 값은 `xeon`입니다. M4 전 개명 작업 전에 정합니다(M3-REQ-54 `[미결]`).

## 5. 알려진 한계 (이월 목록 요약)

이월 목록은 작업 메모이고 저장소 밖에 있습니다. 아래 내용은 그 목록을 주제별로 줄인 것입니다. 항목의 완료 여부는 이 문서가 확인하지 않았습니다.

**서비스·원격 (B1-SVC, B2-RMT)**
- 터널이 끊긴 뒤 재연결해도 구독 재전송(replay)이 없습니다. replay 배선(`createReplayResolver`, `modelRequestResendOf`의 호스트 연결)이 끝나지 않았습니다.
- 서비스에 붙은 연결에서 `xeon secret add`, `set`, `rotate`, `reveal`은 값 입력 창이 없어 두 줄 오류로 끝납니다(`L4.cli.spec` §10 22번).
- 비루프백 리스너 정책(`--listen-tcp`)은 사용자 결정 대기입니다.
- SSH 터널 강제 종료 시험이 없고, IPv6 리터럴 주소는 거부합니다.
- 서비스 모드의 프로젝트 확장은 적재되지 않습니다. 관리 설정 파일 위치는 정해지지 않았습니다.

**예약 (B1-SCH)**
- 모델이 쓰는 예약 조회·취소 도구가 없습니다.
- `schedule.create`에 `requestId` 멱등이 없습니다. `cron` 식과 시간대는 이월 목록의 항목입니다.
- 예약 틱 실행권(`scheduler` 임대)을 아무도 잡지 않습니다(HS-102, HS-40).
- `--auto-approve`는 도구 승인만 허용합니다. 질문과 계획 승인은 거부합니다.

**알림과 목표 판정 (B1-NTF)**
- `handler_failed`와 `dialog.status`의 계수가 따로 집계됩니다.
- 종료 직전에 도착한 알림은 전달되지 않을 수 있습니다.
- 목표 판정의 `judgeMaxRuns`가 호스트 조립에 넘어가지 않았고, 실제 core-loop 통합 시험이 없습니다.

**쓰기 도구와 파일 (B1-WS, 로그)**
- 원자적 쓰기는 실행 권한과 하드 링크를 잃을 수 있습니다. 실패로 남은 임시 파일을 정리하지 않습니다.
- 동시 변경 감지는 설계상 없습니다.
- 로그 회전 sink가 호스트에 연결되지 않아 로그가 한 파일에 계속 쌓입니다(`eng.operations.runbook` §3.1).

**산출물 (B2-ART)**
- 리뷰 승인 카드의 `ReviewAnswer` 흐름이 거부로 처리됩니다.
- 산출물 wire 메서드가 없고, 제목 출처가 기록되지 않습니다. `retentionDays`, 내보내기, 핸드오프도 없습니다.

**모델 계정과 웹 (B2-MDL, B2-WEB)**
- 계정 회전 상태는 메모리에만 있고 `reservePct`를 쓰지 않습니다.
- 위장 provider의 와이어 동등 래퍼(M-8)를 쓸지 정하지 않았습니다. 고지 동의가 없을 때의 진단 경로가 없습니다.
- Playwright MCP 도구 이름과 응답 구조는 `[가정]`이라서 실제 서버 확인이 필요합니다.
- 바이너리 응답 본문은 에코 검사를 받지 않습니다. 첫 사용 고지는 호출 뒤 경고로 나갑니다.

**보안 (B3-SEC, B3-SEC2)**
- 시작 승인 증거는 메모리에만 있어서 재시작이나 다른 thread에서 다시 묻습니다.
- 새 MCP 도구는 한 단계 뒤에 보입니다.
- 차단된 MCP 서버는 샌드박스 설정을 바꾼다고 풀리지 않습니다. 샌드박스 위반 수집이 없습니다.
- macOS Seatbelt는 실기 확인 전입니다.

**데이터 (B3-DATA)**
- 블롭 GC는 기본 꺼짐이고, 켜려면 넓은 감사와 장시간 시험이 필요합니다. GC는 서비스 모드에서만 돕니다.
- 자동 제목의 출처 정보는 메모리에만 있습니다.
- 진단 배열을 읽는 wire가 없습니다.
- `L0.store`의 S-13, S-14 항목과 DB 내보내기의 `ENOENT` 경쟁이 남아 있습니다.

**설정과 L1 잔여 (B3-SET, B3-L1M)**
- 쓰는 곳이 없는 설정 키가 26개입니다(전체 242개 중). 탭 수는 13개로 스펙의 12개와 다릅니다. 사용자 결정 대기입니다.
- 관리 설정 파일은 읽기만 되고 내용이 비어 있습니다. 프로젝트와 로컬 설정 파일은 감시하지 않습니다.
- 컴팩션 뒤 스킬 본문을 다시 넣지 않습니다.
- 검토 포크의 사용량 귀속과 캐시 접두 공유 조건이 남아 있습니다.

**성능과 측정 (B5-PERF)**
- 서버 측정의 예산 6개는 사용자 결정 대기입니다. macOS 기준선이 없습니다.
- 측정은 다른 작업이 함께 돌던 기기 부하 아래에서 했습니다. 꼬리 값은 기준선이 아닙니다.
- 반복 감지 임계는 실제 provider 녹화(`just tape-record --yes`) 뒤에 조정합니다.

**릴리즈와 데스크톱 (B5-REL, B4-DSK, B4-I18N)**
- macOS 릴리즈 경로는 아직 실행하지 않았습니다. B6에서 실행합니다.
- `SHA256SUMS`는 서명하지 않았고, 워크플로에 gitleaks 단계가 없습니다.
- Linux arm64 아카이브는 빌드 대상이지만 스모크 검사가 없습니다.
- 트레이 아이콘과 메뉴가 없고, Mac 확인 항목(트레이 닫기, 재실행 뒤 창 복귀, `RunEvent::Reopen`)이 남아 있습니다.
- i18n 이전 중 하위 층의 문장 통과(약 198줄)와 데스크톱 오류 문구가 남아 있습니다.

**코드 정리와 시험 (B5-CLN, 여러 트랙)**
- `Reflect.get`은 시험에서는 없어졌지만 `src`에 약 50곳(22개 파일, 그중 L4 4곳)이 남아 있습니다. 타입 있는 도우미 설계가 필요합니다.
- 부하가 크면 `core-models` 시험, `cap-mcp` HTTP 연결 시험, `ensure-sidecar` 5초 시험이 간헐적으로 실패합니다.

**장부와 표기**
- 완료된 행도 장부 칸은 `M3b:<트랙>` 그대로입니다. B6 판정에서 고칩니다.
- 이월 목록에만 있는 트랙 이름 `B3-FIX`, `B3-SEC2`, `B5-FIX2`는 `review.m3b-plan` §2에 선언되어 있지 않습니다. 장부 검사는 이 이름을 보지 않습니다.
- 스펙의 구현 표기 가운데 `M3b B1-SCH2`는 선언된 트랙 `B1-SCH`와 이름이 다릅니다.

## 6. 미결 사항

1. 이월 목록의 트랙 이름 `B3-FIX`, `B3-SEC2`, `B5-FIX2`를 `review.m3b-plan` §2에 선언할지, 기존 트랙에 합칠지 정합니다.
2. 스펙 표기 `M3b B1-SCH2`를 `B1-SCH`로 고칠지 정합니다.
3. 트랙 완료 판정 방식을 정합니다. 장부 칸을 B6에서 바꿀지, 완료 목록을 따로 둘지 정합니다.
4. 이월 항목 가운데 어느 것을 M4 전에 끝낼지 사용자가 정합니다.
