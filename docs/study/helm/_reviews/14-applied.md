# 노드 14 수정 반영 기록

대상: docs/study/helm/14-protocol.md. 리뷰: _reviews/14.md. 반영 전에 docs/design/19-client-protocol.md의 §2.3(P-01~P-03), §3.2.1~3.2.6, §3.3.4, §3.4.1~3.4.7, §3.5.1~3.5.9, §3.6.1~3.6.4, §3.7.1, §3.9.1~3.9.4, §3.10.1~3.10.3, §3.11, §3.12, §3.14, §4(F-06, F-42), §6.3(CT-08), §7(Q-11)과 rulings-stage2a.md의 J-281, J-282, J-287, J-288, J-297, J-301, J-321, J-343, J-344를 grep과 읽기로 직접 확인했다. 리뷰어의 인용은 높음·중간 모두 원문과 일치했고 오늘 정리(J-277~J-351)로 뒤집히는 주장은 없었다. 노드 2·4·13 글도 열어 겹치는 부분을 확인했다(13번 노드에는 `localConfirm`이 이미 있어 리뷰의 "13에 없음"은 현재 상태와 다르다).

작업 방식: 글의 순서를 설계 절 순서에서 세 보장(위치 이어받기, 무효화, 멱등) 중심으로 바꾸는 요청이라 절 대부분이 이동·재작성 대상이었다. 그래서 Edit 한 건씩이 아니라 파일 전체를 한 번 다시 썼다(옛 문장 중 맞는 것은 그대로 옮김). 그 뒤 소규모 문구는 Edit 성격의 치환으로 고쳤다.

## 반영한 것

### 기술 문제
- T1(높음): 굵은 문장을 "같은 HTTP + WebSocket 코드와 같은 메서드 집합을 쓰고, 리스너마다 다른 것은 전송 조건, 받는 HTTP 경로, 받는 인증 방식"으로 바로잡았다. Host·Origin·Tailscale 신원·소켓 권한, `/m/*`·`POST /pair`가 `tailnet` 전용이고 `loopback`에서 404인 점은 예로만 쓰고 표는 2번·13번 노드를 가리키게 했다. 체크리스트도 같은 문장으로 고치고 "같은 적합성 시험이 세 리스너와 `ssh -W`에서 통과하는가"를 넣었다.
- T2(높음): 서버 ID 대조를 챌린지 단계(불일치면 `hello`를 보내지 않고 `needsUser`)로 옮겼다. `hello` 뒤에는 `hello.log.storeId`·`hello.connection.deviceId`를 진행 중 명령함 항목과 대조한다고 쓰고, `storeId`가 다르면 캐시를 비우고(`clearServer`) 그 항목을 자동 재전송에서 빼며, 복원된 DB에는 키가 없을 수 있어 두 번 적용될 수 있다는 이유(F-42, CT-08)를 재연결 예에 넣었다. 체크리스트에 두 점검 항목을 추가했다.
- T3: `dependsOn`을 "읽은 레코드 ID와 집계 이름의 목록"으로 고치고 `@inbox` 예와 상한 초과 시 집계 이름 하나로 줄이는 규칙(넓게 무효화하는 쪽)을 추가했다.
- T4: 저장되는 결과(적용·접수·질문으로 바뀜·거부·충돌)와 저장되지 않는 결과(1단계 오류, 3006, 5001~5004, 내부 오류, 일시 실패)를 구분하고, 거부·충돌 뒤 사람이 다시 보낼 때는 새 키를 만든다고 썼다. 체크리스트에 추가했다.
- T5: 범위 키와 지문에 행위자·출처(기기)가 들어가고, 기기가 바뀌면(재페어링 포함) 범위가 달라진다는 문장을 넣었다. 지문 정의는 줄이고 4번 노드를 가리킨다.
- T6: 자동 재전송 제외 여섯 사유를 번호 목록으로, 초안 되살리기와 `command.lookup`, 24시간 이후에도 이중 적용이 없는 이유, (2)·(3)의 "이미 처리됐을 수 있음" 표시를 넣었다. "동기화 중 새 사람 결정은 막고, 이미 보낸 명령은 같은 키로 다시 보낸다"로 구분했다. `schemaHash`는 "다르다는 사실만으로 빼지 않고 새 스키마 통과 여부로 판단"으로 고쳤다.
- T7: 보장 범위를 "명령을 보낸 연결의 실시간 구독 중 필터에 맞는 것"으로 좁히고, 보장 밖(재생 중, 구독 없음, 필터가 거르는 경우, `POST /m/cmd`)과 클라이언트의 `lastSeq` 비교를 썼다. 체크리스트에 클라이언트 쪽 항목을 추가했다.
- T8: 휘발 상태 삭제를 두 규칙(영속 이벤트가 오면 해당 `messageId`·`toolCallId`를 버림, run 종료의 `end` 조각은 `finalSeq`에 이를 때까지 유지)으로 나눴다. 체크리스트에 추가했다.
- T9: 구독 범위(Concern, run, 작업 단위, 전체)와 조각 번호 단위(run마다 1부터)를 분리하고 `active`·`run.partial` 복원 문장을 넣었다.
- T10(중간): 오류 코드와 닫는 코드의 이름 공간이 다름을 명시하고, 겹치는 숫자(1001, 1008, 1011, 4001, 4008, 4009)와 Helm 전용 4000을 한 표로 비교했다. 범위 설명에 3010·3011(도구 결과), 4008~4010·5008(웹 도구)을 반영했다.
- T11(낮음): 수치를 "기본값"으로 표시하고 정책에서 읽는 값임을 `hello` 응답 절에서 한 번 밝혔다.
- T12(낮음): TUI·관리 CLI의 기본 인증을 `localAdmin`으로 쓰고, 결정 표(헤더 토큰)와 로컬 경로 절·미결 사항 표(`localAdmin` 기본)가 설계 문서 안에서 아직 정리 중이라는 점을 한 문장으로 밝혔다. 한쪽을 단정하지 않았다.
- T13(낮음): "메서드마다 대응하는 커널 명령이 하나이고, 둘 이상의 메서드가 같은 커널 명령으로 가기도 한다(`question.proceedWithAssumption`)"로 고쳤다.
- T14(낮음): 버전을 올리는 변경 목록에 선택 params를 필수로 바꾸기, 오류 코드의 뜻 변경, 순서 계약 변경을 더하고 "만"을 뺐다.

### 지침 위반
- 의인화 10곳을 모두 고쳤다(프로토콜이 허용, 메서드가 허용, 알림이 담고·넘겨 주고, 프로토콜이 순번을 매기고, `asOfSeq`가 알려 주고, 조각이 싣고 오고, 규칙이 보장하고, 프로토콜이 돌려주고, 서버가 알려 준 시간, 서버가 기억하고). 새로 쓴 문장도 주어를 서버·클라이언트·데몬·코어 또는 상태 서술로 맞췄다.
- "A가 아니라 B" 구호형 1곳(`gated` 문장)을 "`gated` 상태의 성공 응답으로 돌아옵니다"로 고쳤다. 단순 부정("배치 요청은 받지 않습니다", "빠뜨리거나 두 번 보내지 않는가" 등)도 긍정문으로 바꿨다.
- W32: 메시지 형식 첫 단락을 목록으로, 오류 코드·큰 데이터·버전 단락에 이유 연결어를 넣었다(큰 데이터는 "base64 첨부가 메시지 한도를 쉽게 넘기기 때문").
- W26: `hello` 응답 단락을 정책 단락과 저장소 정보 단락으로, 서버의 명령 처리를 번호 목록으로, 연결 상태 단락을 상태 이름·백오프·중단 조건으로 나눴다. 범위 밖 처리는 표로 옮겼다.
- W2: `localAdmin`·`localConfirm`·`runtimeAdapter`를 이 노드에서 짧게 정의했고, 권한 범위(`read`, `decide`, `decideMobile`, `devices`, `admin`), 백오프 모양(0.5초부터 두 배, 최대 30초, 절반 지터), "스냅숏 경로"(구체적 단계로 대체)를 풀었다.
- W43: "권한 범위(scope)"로 통일, 뷰 용어를 "뷰"로 통일("화면 캐시"는 "뷰 캐시"). "스냅숏"은 설계 표기를 따라 쓰지 않거나 "스냅샷"으로 썼다.
- W48: "구독 먼저" 안내가 두 곳에 반복되던 것을 한 곳으로 모았고, gap 문장의 되풀이를 줄였다.
- W22: 그림 라벨을 글과 맞췄다(`HelloResult`는 "hello 응답", `ViewResult`는 "화면 응답", `events` 알림은 "이벤트 알림").

### 독자 흐름
- L1: 도입에 세 보장을 먼저 세우고 각 절을 "보장 1·2·3"에 붙였다. 절 순서는 바탕(메시지·경로), 연결, 보장 1, 2, 3, 재연결, 코드 표, 큰 데이터, 버전이다.
- L2: "구독 먼저" 숫자 예(100, 101~104 / 101, 102, 103)를 넣었다.
- 재연결 단계별 예(저장 위치 120, head 150, `ik_A`, S1/S2 분기, 133·147의 무효화)를 넣었다.
- L3: 충돌 절 첫머리에서 `basisSeq`·`revisionSeq` 비교를 4번 노드로 짚고, 범용 실행 메서드가 없는 이유를 연결했다.
- L4: 판정 순서 문장에 인증 방식 세 가지를 밝혔다.
- L5: 리스너 표, 지문 정의, 토큰 검사 상세를 줄이고 2·4·13번 노드를 가리킨다.
- L6: 체크리스트에 T2, T4, T6, T7, T8과 `local` 소켓 격리 항목을 추가했다. `localAdmin`·`localConfirm`은 이 노드에서 짧게 정의하고 격리 상세는 13번 노드에 맡겼다.

### 표상
- R1: 시퀀스 다이어그램에 명령 요청 화살표(`question.answer(ik_…, basisSeq)`)를 추가하고, 제목을 "연결에서 첫 명령까지"로 고쳤다. 개략도 캡션(타이머·권한 범위 부여·`minSeq` 대기 생략, 첫 접속과 재접속의 차이)을 넣었다. mermaid 11.4.1 `mermaid.parse`로 `sequence` 인식을 확인했다.
- R2: `replay.outOfRange` 사유별 처리 표, 오류 코드와 닫는 코드 비교 표(숫자 기준 한 표)를 넣었다. 표상은 그림 1개와 표 2개로 한정했다.

## 반영하지 않은 것

- R2의 리스너 x 경로 x 조건 x 인증 3x4 표: 2번 노드와 13번 노드에 같은 표가 있어 중복이므로 두지 않고 가리켰다(요청에 따름).
- R2의 연결 상태 다이어그램과 송신 큐 단계 표: R4(한두 개)에 맞춰 뺐다. 상태 이름·백오프·중단 조건은 문장으로, 송신 큐는 한 단락 숫자로 충분하다.
- 오류 코드 전체 표(R3): 요구하지 않는다고 리뷰가 밝혀 영역 설명과 겹치는 숫자만 썼다.
- 체크리스트의 "~하는가" 어미(W31): 리뷰도 위반이 아니라고 판정했고 다른 노드의 점검 목록 관례라 유지했다.
- 지침 부작용 S1~S3: 지침 개선용 관찰이라 글에 반영하지 않았다. 단 S1의 취지(설계 문서끼리 어긋난 곳을 내용으로 쓴다)는 T12에 적용했다.
- V9.5(높음 건 재검토 한 번): 이 작업에서는 새 리뷰어를 띄우지 않았다. 호출자가 필요하면 T1·T2를 고친 부분(경로 절의 굵은 문장, 재연결 순서의 예, 체크리스트 마지막 세 항목)만 다시 검토하면 된다.

## 설계 문서 사이에서 아직 정리 중인 곳

- TUI의 인증 수단: 19 §2.3 P-03은 데스크톱·TUI가 `Authorization: Bearer` 헤더를 쓴다고 쓰고, 같은 문서 §3.2.4와 §7 Q-11은 `localAdmin`을 기본으로 쓴다. 글에 한 문장으로 밝혔다.
- 인증 실패 지연 상한은 13번 노드 글이 이미 18과 19의 차이를 적고 있어 이 노드에서는 다루지 않았다.
