# 노드 06 리뷰 반영 기록

반영 전에 11 §3.2.2·§3.3.1~§3.3.4·§3.4·§3.5.1~§3.5.3·§3.6.3~§3.6.5·§3.7·§3.8.1·§3.10.1~§3.10.2·§3.15·§3.16, 14 §3.13.6, 26 §3.4.3 `planPush`, 08 `WhyNotAsked`, 05 강도 표를 grep과 발췌로 직접 확인했다. 리뷰어 인용과 달라 보이는 곳은 없었다.

## 반영한 것

- 기술 문제 높음 1건(T1)과 중간 11건(T2~T12): 모두 반영했다. `urgencyOf` 표는 11 §3.5.1 의사코드 순서대로 8행으로 다시 썼다(방해 금지, 부재+푸시 불가, 승격 둘, 즉시 둘, 협상 notice, 그 밖 digest).
- 낮음 T13~T23: 모두 반영했다. T24는 푸시 계획 → 전달 기록 순서로 썼고, 11과 19 표현 차이는 11 기준으로 두었다.
- 학습 적합성: 조건 1~3 계산표와 문턱, 보통 문턱에서 `defaultCovered`가 덮임이 아니라는 점, V-AS-02·03 표, D-1~D-10 표, Q-A·Q-B 대입 예(Q-A는 게이트 계산 직후, Q-B는 알림 강도 뒤), 늦은 답 처리, 체크리스트 보강.
- 지침 위반: W51(데이터·규칙 주어 문장, 의도 동사), W16(결정 48·59·60 번호 삭제), W2(질문함, 검토 창, 승격, 복귀 요약, 정책 정의), W23(개요 문단), W22(그림 값 반복 제거), W26(긴 단락 분할), W32(연결어 추가).
- 독자 흐름 F2~F6, 표상 R1 일부(그림 노드 문구와 간선 라벨), R2의 D 규칙 표.

## 반영하지 않은 것

- T24의 11과 19 표현 차이 확인: 사용자 확인이 필요한 사항이라 본문에서는 11을 따르고 구현 리뷰 때 확인할 항목으로 남긴다.
- F1 중 `whyLocalInsufficient` 필수와 V-Q-04 체크리스트 추가: V-Q-04는 권리 게이트 규칙과 같은 내용이라 따로 넣지 않았고, `whyLocalInsufficient`는 질문 레코드 상세라 이 글 범위 밖으로 판단했다.
- F1의 휴대폰 푸시 세부를 15번 노드로 넘기기: 구현 리뷰 체크리스트에 필요한 조건 몇 줄만 남기고 수치는 15번 노드에 맡겼다.
- R1 가로 방향(LR) 변경과 이의 강제 주석 노드: 필수가 아니고 본문에 예외 문단이 있어 그림 구조는 유지했다.
- R2의 임시 가정 시간 경과 도식(sequence)과 갈래별 결과 표: 구조 추가라 이번 범위 밖이다. 시간 순서는 만료점 절 문장으로 풀어 썼다.
- W38 부정문("막지 않는 ..."), 지침 부작용 S1~S4: 분야 용어이거나 지침 개선용 관찰이라 글에 반영하지 않았다.
- Mermaid 재렌더링: 이 환경에서 렌더러를 쓰지 않았다. 노드 문구와 간선 라벨만 따옴표 안에서 바꿔 문법은 바뀌지 않았다.
