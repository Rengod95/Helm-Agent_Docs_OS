# 노드 12 수정 반영 기록

대상: docs/study/helm/12-daemon-ops.md. 리뷰: _reviews/12.md. 반영 전에 17 §3.3.2·§3.4.1~3.4.6·§3.6.6·§3.8~3.11, 09 §3.8.2·§3.14.2, 12 §3.7.6~3.7.7, 18 §3.10.1 원문을 grep과 읽기로 확인했고, 리뷰어의 인용이 모두 원문과 일치했다.

## 반영한 것

- 기술 T1(높음), T2~T10, T18(중간): 모두 반영.
- 기술 T11~T17(낮음): 모두 반영.
- 지침 위반: 의인화, 반복 문형, 단계 서술 번호 목록화, 용어(정본 삭제, 소유 파일을 진단용 JSON 파일로 정의, H-2 코드 제거, linger 풀이), 번역투 피동.
- 독자 흐름 F1~F7: 모두 반영. 안전 모드와 읽기 전용을 별도 절과 비교 표로 정리, 읽기 전용 사유별 해제 조건 표, 주간 전체 검사 실패 처리 추가, 시작 순서 표, 크래시 루프 예(03:50, 03:54, 03:58), 번호 체계 문장, 02·04·07a 중복 축약.
- 표상: 시작 순서 표(단계별 실패 결과, 10단계 쓰기 시작선, 15단계 리스너 선), 읽기 전용 사유 표, 안전 모드 대비 표를 Markdown 표로 넣었다.
- 점검 목록은 고친 내용에 맞춰 개정했다.

## 반영하지 않은 것

- 표상 제안 2(상태 기계 다이어그램): 비교 표와 문장으로 같은 정보(사유 집합, 표시 유지, 해제 시 복귀)를 담았고, 효과가 가장 큰 표상 하나(시작 순서 표)를 우선 넣었다.
- 표상 제안 4(종료 시간 예산 타임라인): 낮은 우선순위. 종료 번호 목록 아래 한 문단의 숫자로 충분하다.
- F4의 사건별 표 전체: Windows 재부팅, `wsl --shutdown`, 정전만 문장으로 옮겼다. 절전 복귀, Wi-Fi 끊김, interop 고장 등은 노드 목적(죽고 살아나는 동작)에서 먼 사건이라 뺐다.
- 7절의 가지치기 중 `OpsStatus` 필드 나열과 관리 CLI 설명은 줄였으나, 시험 종료 지점 설명은 한 문장으로 유지했다(점검 목록이 참조).
- 점검 목록의 "~하는가" 어미: 시리즈 노드 4, 7a와 같은 점검 목록 관례이고 질문형 종결이라 유지했다.
- 지침 부작용(5절) S1~S3: 지침 개선용 관찰이라 글에는 반영하지 않았다. 번호 체계 기준 문서는 이름 없이 "데몬 시작 순서표"로만 썼다.
- T12의 "설계 문서끼리 용도 서술이 다른 곳": 확인 결과 17 §3.1.4가 세 가지 용도를 모두 적고 있어 단정해도 모순이 없었다. 번호 체계만 "정리 중"으로 밝혔다.
