### 2.3 신뢰 경계와 등급 (18 §3.3, §3.12)

- 경계 A(같은 uid 프로세스): 넘으면 모든 것이 가능하다. Helm은 지키지 않는다(D18-04, A18-4).
- 경계 B(기기 토큰): `tailnet`·`loopback` 연결의 경계. 같은 호스트의 다른 OS 사용자 공간도 여기 든다.
- 경계 C(도구 샌드박스): Helm이 직접 만든 가장 중요한 경계. 모델이 실행하는 코드가 경계 A 안으로 못 들어온다.
- 신뢰 등급(§3.12): 사람 입력 > 모델 출력(제안: 커널 검증·합의·격리) > 도구·웹·파일 출력(신뢰 안 함) > 외부 세션 로그(신뢰 안 함) > 관찰 제안(사람 채택만).

### 2.4 루프백은 격리 경계가 아니다 (결정 46; 18 §3.3, §3.4.2, §3.6.4)

- 결정 46: `networkingMode=mirrored`에서 127.0.0.1은 Windows 프로세스와 WSL의 모든 프로세스가 연다. 그래서 모든 리스너는 자격 증명을 요구하고, 도구는 데몬 소켓·데이터·설정을 못 보게 격리한다(06 §3.7.4, 13 §3.6, 18 D18-04).
- WSL의 127.0.0.1 TCP는 Windows 프로세스에서도 열린다 [실험 6]. 그래서 `localAdmin`은 TCP에서 받지 않고 Unix 소켓에서만 인정한다(A18-3).
- serve가 넘긴 연결과 sshd가 넘긴 연결 모두 127.0.0.1에서 온다. "127.0.0.1에서 왔다"는 신뢰 근거가 아니다(사례 §12.2-8을 채택하지 않음).
- 같은 호스트 프로세스에 남는 겹은 기기 토큰뿐이다. 헤더와 XFF는 위조 가능하므로 토큰의 대체가 아니다(D18-01, ADR-18-01).
- 같은 uid 프로세스는 소켓 파일 권한으로 로컬 관리자가 된다. 그래서 도구 샌드박스가 소켓 디렉터리를 가리는 것이 전제다(§3.5 규칙 4(b), R-3). S0에서는 이 전제가 깨져 상태 `sandbox` critical이다.

### 2.5 외부 접속: 리스너 세 개 (18 §3.4.1, §3.4.2; 19 §3.2.1)

| 리스너 | 주소 | 출처 | 주체 | 인증 |
|---|---|---|---|---|
| `tailnet` | `127.0.0.1:7840`(개발 데몬은 안 연다, 17 F-35) | `tailscale serve`(외부 8448)가 넘긴 연결 | `device` | 신원 헤더 + whois + 기기 토큰 + 노드 묶기 |
| `loopback` | `127.0.0.1:7841`(개발 7851) | `sshd`가 `ssh -W`로 연 연결 | `device`만 | 기기 토큰(헤더). 신원 헤더 무시. `localAdmin` 주장은 1008 |
| `local` | `/run/user/<uid>/helm/rpc.sock`(디렉터리 0700, 소켓 0600) | 같은 uid 프로세스 | `device`, `localAdmin`, `runtimeAdapter` | 파일 권한. 토큰은 선택 |

- 나눈 이유: serve와 SSH 연결을 한 포트에 섞으면 "헤더 없으면 다른 규칙"이라는 예외가 생기고, 같은 호스트 프로세스가 그 예외를 탄다(§3.4.2).

### 2.6 Host·Origin·preflight (18 §3.4.3)

- 순서: Host → Origin → 신원 → 자격. Host가 맞지 않으면 어느 갈래든 403(DNS rebinding 방어). 허용 Host: tailnet은 공개 호스트(`server.tail7ad0b4.ts.net:8448`), loopback은 `127.0.0.1:7841`·`localhost:7841`.
- 헤더 갈래(데스크톱·TUI·CLI): Origin이 있으면 403. 데스크톱 Rust 전송은 Origin을 보내지 않는다(20 §3.8.5). 예외는 개발 데몬의 `auth.devAllowedOrigins`뿐이고, 정식 데몬이 이 키를 받으면 시작을 거부한다.
- `/pair`, `/devices/self/rotate`: Origin이 있으면 모바일 출처라도 403(본문에 토큰이 실림).
- 쿠키 갈래와 `/m/*` 상태 변경: Origin이 `auth.allowedOrigins`(기본 `[publicOrigin]`)와 스킴·호스트·포트까지 정확히 같아야 한다. 8443~8447 출처도 403(X-16).
- `originGetRule`(GET): Origin이 정확히 맞거나, Origin이 없고 `Sec-Fetch-Site: same-origin`이다(A18-5, iOS 26 실기기 확인은 26 §6.2).
- 규칙: 한 요청에 `Authorization`과 쿠키가 같이 오면 헤더만 쓴다(19 P-03). `localAdmin`·`runtimeAdapter`는 `local`에서만 인정하고, 다른 리스너에서 주장하면 1008 `auth.methodNotAllowed`.

### 2.7 tailnet 신원 확인 (18 §3.6.1)

- 본 헤더: `Tailscale-User-Login`과 마지막 hop의 `X-Forwarded-For`(가정 A18-1, A18-2; 실제 serve 동작은 T18-05 수동 확인).
- 거부 순서: 헤더 없음(`ingress_headers_missing`) → Funnel 표식(`funnel`) → `auth.tailscale.allowedLogins` 밖(`login_not_allowed`, 기본은 설치 때 `helm doctor`가 얻은 소유자 로그인) → whois 실패(`whois_unavailable`) → 태그 노드(`tagged_node`) → whois 로그인과 헤더 불일치(`whois_mismatch`). 모두 401과 `auth.denied`.
- whois는 Windows `tailscale.exe whois --json <ip>`를 WSL에서 자식 프로세스로 부른다(5초 제한, 성공 60초·실패 5초 캐시, `TAILSCALE_EXE`로 경로 변경). 실패 기본은 fail closed(`auth.tailscale.whoisFailure="deny"`). `"token-only"`는 `auth.policy_relaxed`를 남기고 권하지 않는다(Q18-05).

### 2.8 기기 토큰 판정 (18 §3.4.5, §3.6.1; 19 §3.4.3)

- `helloDeviceAuth` 순서: 형식 → 해시 조회(현재 또는 회전 유예 해시) → 상수 시간 비교 → 폐기(1005 `revoked`) → 만료(1005 `expired_absolute`·`expired_idle`) → 기기 ID(1008 `device_mismatch`) → 전달 수단(1008 `carrier_mismatch`) → tailnet이면 노드(1008 `node_mismatch`) → `proofRequired`(꺼짐, 1007은 서명 불일치용).
- 형식 틀림, 없음, 해시 불일치는 모두 1004 `auth.failed`. 기기가 있는지 알려 주지 않는다. 토큰 경로에서 1006(`auth.unknownDevice`)은 쓰지 않는다.
- 업그레이드 단계는 토큰의 존재와 형식만 본다. 해시·폐기·만료는 `hello`에서 본다(§3.4.3 규칙 6, 19 P-03).
- 하위 프로토콜 `Sec-WebSocket-Protocol: helm-bearer.<토큰>`은 받지 않는다(§3.4.4). 이유: (1) 스크립트가 만드는 값이라 토큰이 스크립트 메모리와 웹 저장소에 있어야 하고 XSS 하나로 나간다, (2) 프록시·진단 로그에 남는다, (3) 모바일은 쿠키를 쓴다. 와도 무시하고 헤더·쿠키가 없으면 401. 가짜 데몬 시험에서만 쓴다. SP-15 스파이크가 실패해도 대체하지 않고 사용자 결정으로 올린다(판정 J-241).

### 2.9 기기 등록 (18 §3.7.1, §3.7.3, §3.5 규칙 5)

| 흐름 | 시작 | 신뢰 근거 | 메서드·경로 |
|---|---|---|---|
| A. 코드 | 서버 셸 `helm pair`, 또는 이미 페어링된 데스크톱·TUI의 `device.createPairingCode`(모바일은 못 만든다) | 코드를 만든 쪽이 이미 인증됨 | `POST /pair`(본문에 토큰), 모바일 `POST /m/pair`(쿠키). 둘 다 tailnet만 |
| B. SSH 발급 | 새 기기 앱이 `ssh server helm device issue --stdin --json` | SSH 키로 셸에 들어옴 = 로컬 관리자 | `admin.issueDevice`. 승인 대기 소켓은 두지 않음 |

- 셸 해석 방지: 기기 이름·플랫폼은 인자가 아니라 stdin JSON 한 줄로만 보낸다. 앱은 원격 인자를 POSIX 작은따옴표로 감싸고, `helmCliPath`는 `^~?/[A-Za-z0-9/._-]+$` 또는 `helm`만 받는다.
- 데몬 검증: 이름 1~64자, 제어·양방향 제어 문자 거부. 토큰은 `HELM-DEVICE/1 {json}` 한 줄에만 나온다. `SSH_CONNECTION` 첫 필드로 노드를 미리 묶는다(실패하면 첫 WSS 접속 때 묶음).
- 성공하면 다른 활성 기기에 `notice` 알림("새 기기가 연결되었습니다")을 보낸다. 기기 속성은 서버가 정한다. `/m/pair`는 `mobile`·`ios`·`cookie`로 고정하고 본문 값은 무시한다.

### 2.10 페어링 코드 (18 §3.7.2, §3.7.4)

- 60비트 Crockford base32 12자, `XXXX-XXXX-XXXX` 표시(19의 옛 9자 예시보다 길게 했다). 정규화: 대문자화, `-`·공백 제거, `O→0`, `I/L→1`. 원문은 저장하지 않고 `codeHash`만 둔다.
- 기본 10분(최대 60분), 1회 사용, 시도 5회 뒤 `exhausted`, 동시 유효 3개(넘으면 가장 오래된 것 취소).
- `POST /pair`·`POST /m/pair`는 tailnet + tailscaleIngress 필수. 실패 응답은 사유를 구분하지 않는다(19에서 모두 `1009 pairing.invalidCode`). 사유는 `pairing.code_failed{reason}`로만 남긴다.
- 상태: `active` → 맞는 코드면 `consumed`, 틀린 코드 누적이면 `exhausted`, 만료면 `expired`, 생성자 취소면 `cancelled`. 소진된 뒤의 시도도 같은 1009.

### 2.11 토큰 형식·수명·저장 (18 §3.8.1, §3.8.2, §3.9)

- 형식: `helm_dt_` + base64url(32바이트). `tokenId` = sha256 앞 12자가 로그·화면의 식별자. 서버는 `tokenHash = sha256(토큰)`만 저장하고 상수 시간 비교(D18-06, 소금 불필요).
- 수명: 절대 365일, 유휴 90일(09 `device_presence.last_auth_at`), 만료 30일 전 경고(Q18-01, 추천값이 본문에 반영). 절대 만료는 커널 타이머 `device.expired{absolute}`, 유휴 만료는 하루 한 번 점검 `device.expired{idle}`(J-161).
- 저장: 서버 DB(파일 0600, 디렉터리 0700), 서버 디스크에 토큰 파일 없음. 데스크톱은 OS 키체인(20 APP-D02), 웹뷰·IndexedDB·로그에는 없음. 모바일은 HttpOnly 쿠키, 스크립트 저장소에는 `deviceId`·`serverId`만.
- `device.*` 이벤트의 `tokenHash`는 결정 29 때문에 있지만, 재전송·투영·관찰 입력·진단 묶음에서는 뺀다(T18-18).

### 2.12 회전·폐기·도난 (18 §3.8.3~3.8.5)

- 회전 1차: 자동 회전 없음(20과 같음). 2차(20이 `credential_rotate`를 구현할 때): `POST /devices/self/rotate`, 이전 해시를 5분 또는 첫 사용까지 유효하게 둔다(S-04), `device.token_rotated`. 강제 회전은 `helm device expire-tokens`(재페어링).
- 폐기 주체: 로컬 관리자(`helm device revoke`), 다른 기기 또는 자기 자신(`device.revoke`). 즉시 효과: `revokedAt` → 열린 연결에 `connection.closing{auth.revoked}` 뒤 4009 → 그 기기의 다운로드 티켓 무효 → 그 기기가 만든 유효 코드 무효. 기록 `device.revoked`. 모바일이면 `push_tokens` 행 삭제.
- `--cascade`: 그 기기가 만든 코드로 들어온 기기(자식까지)를 함께 폐기. 대상 목록을 먼저 보이고 확인받는다.
- 도난 절차(§3.8.4): (1) Tailscale 콘솔에서 노드 제거(노드 묶기 때문에 토큰만으로는 tailnet을 못 통과), (2) `helm device revoke <dv_id> --reason stolen --cascade`, (3) 그 기기의 SSH 키 삭제, (4) `helm audit --device <dv_id> --since <마지막 정상 사용>`, (5) 의심 결정에 이의.
- 기기 키 서명: 1차에는 끔(`proofRequired=false`, D18-07, ADR-18-03). 켜는 조건은 하드웨어 보호 키. 모바일도 끔(26 MQ-05).

### 2.13 쿠키 `__Host-helm_dt` (18 §3.4.3 규칙 1~5, §3.9; 19 §3.2.2; 26 §3.3.3)

- 속성: `__Host-helm_dt=<토큰>; Path=/; Max-Age=<남은 수명>; Secure; HttpOnly; SameSite=Strict`. `__Host-` 접두사가 `Secure`, `Path=/`, `Domain` 없음을 강제한다.
- 읽는 곳: tailnet의 `GET /rpc` 업그레이드, `/files/*`, `/m/whoami`, `/m/cmd`뿐. loopback·local은 보지 않는다. 정적 `/m/*`는 쿠키를 읽지도 `Set-Cookie`를 붙이지도 않는다.
- 전달 수단: 쿠키 토큰은 `credentialCarrier: "cookie"` 기기여야 한다. 데스크톱 토큰을 쿠키로 보내면 `1008 carrier_mismatch`.
- CSRF: 쿠키 갈래의 업그레이드와 상태 변경은 Origin 정확 일치, GET은 `originGetRule`, `SameSite=Strict`(T-W2).
- 한계: 쿠키는 포트를 구분하지 않는다. 같은 호스트 다른 포트 서비스는 same-site라 `SameSite`가 못 막는다(RFC 6265 §8.5 [지식]). 1차는 받아들이고, 근본 대응은 Helm 전용 serve 호스트 이름(26 MQ-15)이다(Q18-13).
- 로그아웃 `POST /m/logout`: 쿠키만 지운다(`Max-Age=0`), 기기는 폐기하지 않는다. 쿠키가 없어지면 `/m/whoami` 401 → 페어링 화면(S-15).

### 2.14 도구 샌드박스: 수준과 요구 (18 §3.11.1~3.11.2; 13 §3.6.1)

| 수준 | 방법 | 쓰기·읽기 | 신호 | 조건 |
|---|---|---|---|---|
| S1 | bubblewrap(사용자·마운트·pid·netns) | 커널 EROFS, 최소 루트 | 분리 | `bwrap` 0.9 이상. 이 서버에는 아직 없다 [실험 7] |
| S1b | `systemd-run --user` 일회성 단위 | 허용 목록(홈 tmpfs + 바인드) | 같은 uid에 신호 가능 | bubblewrap이 없을 때. 이 서버에서 된다 [실험 10·22·24] |
| 없음 | `execute`를 끈다 | - | - | S1·S1b 모두 불가 또는 자가 시험 실패. 상태 `sandbox` critical(R-10) |
| S0 | 격리 없음 | 사후 감지만 | 같은 uid 전부 | 운영자 `tools.sandbox="off"`로만. 시작마다 `tools.sandbox_disabled` |

- S0 금지 이유: 합의 한 건으로는 못 연다. S0의 bash는 `rpc.sock`에 붙어 관리 명령을 보내고 TTY를 흉내 내 사람 결정까지 보낼 수 있다(§3.11.2 끝, §3.5 규칙 7).
- 요구 R-1~R-14(§3.11.1) 요약:
  - R-1 모든 `execute`, MCP stdio, codemode 실행 도구를 샌드박스에서 돈다.
  - R-2 환경 변수는 허용 목록만(`PATH`, `HOME`(실행별), `HELM_RUN_ID`, `HELM_TOOL_CALL_ID`, 프록시 변수, 합의가 명시한 이름). 합의로도 못 주는 것: `*_TOKEN`, `*_KEY`, `*_SECRET`, `*_PASSWORD`, `*_API_KEY`, `SOPS_*`, `AWS_*`, `HELM_*`(위 둘 제외), `ANTHROPIC_*`, `OPENAI_*`, `GEMINI_*`, `OPENROUTER_*`, `SSH_AUTH_SOCK`, `WSL_INTEROP`, `NODE_OPTIONS` 등. 예외는 운영자 설정 `tools.mcp[].env`뿐.
  - R-3 숨김: 보호 경로 전부, `/srv/volumes`, `/run/user/<uid>`, `/run/WSL`, `/mnt`.
  - R-4 읽기는 허용 목록(홈 tmpfs에 도구 체인과 작업 공간만). `InaccessiblePaths`는 글롭을 못 받고 실행 뒤 생긴 파일을 놓쳐 주 수단이 아니다 [실험 24].
  - R-5 데몬 메모리·환경 읽기 불가(필수, `PrivateUsers=yes` [실험 23]). PID 분리는 권장(같은 uid 신호는 `ProtectProc=invisible`로도 안 막힌다 [실험 23]).
  - R-6 모든 실행은 별도 netns, 허용 실행만 프록시로 나간다(2.17절). R-8 `NoNewPrivileges`, sudo 불가.
  - R-9 codemode와 하위 호출도 `runToolCall` 경로에서 같은 검사·격리. R-10 수단이 없으면 `execute` 끔, 몰래 낮추지 않음(S-09).
  - R-12 데몬 안 파일 도구(read·write·edit·grep·find·ls)는 샌드박스 밖이므로 realpath로 보호 경로를 검사한다.
  - R-13 데몬 git은 `safeGit` 고정 환경(2.18절). R-14 `drafts/`·`worktrees/` 실행은 S1에서만(J-108).
- S1b 구성(§3.11.2 명령): `systemd-run --user --slice=helm-tools.slice --property=PartOf=helmd.service`에 `PrivateUsers=yes`, `ProtectSystem=strict`, `ProtectHome=tmpfs`, `BindReadOnlyPaths`(도구 체인), `BindPaths`(작업 공간·임시·프록시 소켓), `InaccessiblePaths=/srv/volumes /run/user/<uid> /run/WSL /mnt`, `PrivateNetwork`, `NoNewPrivileges`, `MemoryMax`, `TasksMax`, 명령은 `/usr/bin/env -i`. 기동 약 70 ms [실험 22].
- S1b 한계: 신호 분리 없음(systemd `PrivatePIDs=`는 257 이상 필요, 이 서버는 255 [실험 3]). 바인드한 하위 경로의 `InaccessiblePaths`는 미실험이라 `pre_read_exposed`로 표시(13 §3.6.1).

### 2.15 가리는 것, 실행 전 탐색, 자가 시험 (18 §3.11.4~3.11.5; 13 §3.6.4, §3.6.8)

- 데이터: `/srv/volumes/**`는 샌드박스에서 숨기고 데몬 파일 도구도 거부한다.
- 설정: `~/.config/helm/**`, `~/.config/systemd/user/**`는 보호 경로(바뀌면 다음 재시작에 코드가 돈다).
- 소켓: `/run/user/<uid>/helm/rpc.sock`의 디렉터리를 숨긴다. 로컬 관리자 결정 경로의 전제다(T-M3).
- 실행 전 탐색(13 §3.6.4): 호출 직전에 바인드한 루트에서 `**/.env`, `**/.env.*`(`.env.example` 제외), `secrets/`를 찾아 가린다. 상한 50,000 항목을 넘으면 실행하지 않는다. 한계: 그 호출이 새로 만든 파일은 그 호출 동안 안 가려진다(13 T-E55).
- 자가 시험(데몬 시작·1시간마다·`helm doctor`): `/srv/volumes/helm` 목록 거부, `rpc.sock` 연결 실패, `cmd.exe` 실패, `ip link`에 `lo`만, env가 허용 목록 안, 작업 공간만 쓰기 가능, `~/.ssh`·`~/.config/sops`·`~/.config/gh` 없음, 프록시로 `127.0.0.1:2019` 거부. 하나라도 어긋나면 `execute` 끔 + critical.
- 관찰 자식(16 OB-1): 기본은 격리 없는 fork(J-70). 파일 열기 감싸개가 `/srv/volumes/helm/private/`·`.helm/private/`를 거부한다(OB-T32). 격리 모드(17 §3.1.3)를 켤 시점은 Q17-02.

### 2.17 네트워크 (18 §3.11.8~3.11.9; 13 §3.6.3; J-134, J-205)

- 샌드박스 실행은 항상 별도 netns다. 허용 실행만 `helm-netshim`(`127.0.0.1:3128`)에서 실행별 Unix 소켓을 거쳐 데몬 `helm-egress-proxy`로 나간다. 프록시는 `CONNECT`와 절대 형식 HTTP만 받는다.
- 차단 대역(프록시·데몬 직접 요청 공통): `127/8`, `::1`, `0/8`, `10/8`, `172.16/12`, `192.168/16`, `169.254/16`, `100.64/10`(tailnet), `fd7a:115c:a1e0::/48`, `fc00::/7`, `fe80::/10`. 어떤 부여로도 열리지 않는다.
- 호스트: `net:<호스트>`(합의)는 그 호스트만 통과. `net:public`은 차단 대역 밖 공개 인터넷 전체(결정 55). 포트는 기본 80·443. DNS rebinding 방지를 위해 해석 뒤 IP를 검사하고 그 IP로 연결한다.
- 프록시 환경 변수를 무시하는 프로그램은 netns에 경로가 없어 실패한다(fail closed). 모든 요청은 `tool.net_request{host, port, decision}`으로 남기고 본문은 남기지 않는다.
- 스파이크 실패 시(Q18-12): 네트워크 실행마다 사람 승인 + 홈랩 H-5(Caddy 2019 정리) 선행. `helm doctor`는 2019가 인증 없이 응답하면 FAIL.
- `web_fetch`(데몬 직접, §3.11.8): 같은 차단 대역을 리디렉션마다 검사, `GET`·`HEAD`만, 쿠키·인증 헤더 없음, 10 MiB·30초. URL 질의가 2 KiB를 넘거나 비밀 패턴에 맞으면 `ask`(`disclose_data`). 숨은 텍스트(`display:none`, `aria-hidden`, `script`·`style`·`template`, HTML 주석)는 변환 전에 지운다.

### 2.18 데몬 git 고정 환경 (18 §3.11.10, R-13; 13 §3.5.7)

- `env -i`와 `GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`, `-c core.fsmonitor=false -c core.hooksPath=/dev/null -c core.sshCommand=/bin/false -c core.pager=cat -c protocol.allow=never -c diff.external=`, `--no-ext-diff --no-textconv`.
- `-c`로 못 끄는 것은 `.git/config`의 `filter.*`다. 그래서 필터를 부르는 하위 명령 전에 실행 지점 설정(`filter`, `fsmonitor`, `hooksPath`, `sshCommand`, `pager`, `diff.*.textconv`, `include.path`)을 읽는다. 있으면 git 대신 해시 스캔을 쓰고 `tools.git_config_suspicious`를 남긴다(S-17).
- 샌드박스 안에서는 `.git/config`, `.git/info/attributes`, `.git/hooks/**`, `.gitmodules`를 읽기 전용으로 덮는다.
- 한계: 사람의 셸이나 같은 uid 에이전트가 같은 폴더에서 git을 쓰면 도구가 남긴 설정이 실행된다. 결과 확인 화면이 `.gitattributes`·`.git*`·새 `.git`을 주의 항목으로 보인다(04·21 요구).

### 2.19 브라우저·화면 도구 BR-1~8 (18 §3.11.11; 13 §3.2.5, §3.10.1)

- BR-1 출력은 신뢰 안 함(투영 표식). BR-2 웹 내용을 본 run은 `taint.web`, 이후 `send`는 `ask`.
- BR-3 프로필은 실행마다 새로(작업 공간 밖 tmpfs), 호스트 Chrome 프로필·쿠키를 가져오지 않는다. 지속 신원은 MVP 밖.
- BR-4 CDP는 `--remote-debugging-pipe`로만, 디버그 포트 없음. browserd 환경에 모델 키와 `SecretStore`가 없다. 모델 호출은 데몬만.
- BR-5 최상위 이동은 `http`·`https`만. 다운로드 기본 거부(합의 시 `drafts/<concernId>/downloads/`, 파일당 50 MiB, 실행 권한 없음). 업로드는 항상 `ask`. 위치·카메라·알림·클립보드 거부, 파일 선택 취소, 확장 끔, `javascript_exec` 기본 끔.
- BR-6 네트워크 제한은 프록시가 호스트 단위로 강제한다. 브라우저의 비-GET·업로드·합의 밖 이동은 CDP `Fetch` 가로채기로 잡아 `send`로 올린다(오염과 무관, J-229). 가로채기는 조작 단계와 함께 켠다. 읽기 단계는 세 가지를 `policy.forbidden_resource`로 거부한다(J-208). `sendBeacon`·keepalive·서비스 워커 요청은 놓칠 수 있다(T18-52, S-19).
- BR-7 Chrome 내부 샌드박스 켬. `--no-sandbox`는 S1·S1b에서만, `browser_inner_sandbox: false`와 `tools.sandbox_disabled{browser_no_sandbox}`. bwrap 아래 기동은 아직 미시험(23 스파이크).
- BR-8 컴퓨터 사용은 실행마다 새 X 서버(`-nolisten tcp`), 세션 승인, `externalEffect: uncertain`. 계정·결제·메시지는 이 도구로 하지 않는다(이후 1차).
- 요청 판정(BR-6 표, 요약):

| 요청 | 판정 |
|---|---|
| 최상위 GET·HEAD, 호스트가 `net:public` 또는 합의 웹 부여 안, 질의 2 KiB 이하 | `read`(자동) |
| 하위 자원 GET(이미지·스크립트·XHR GET) | `read`(범위 밖 호스트는 프록시가 거부) |
| POST·PUT·PATCH·DELETE, `fetch`·XHR 변경, `sendBeacon` | `send`(ask). 지문은 호스트·메서드·본문 해시 |
| 웹 내용을 본 뒤의 2 KiB 초과 질의나 경로 있는 GET(J-209), 합의 밖 호스트 이동(J-229) | `send`(ask) |
| 업로드, 평문 HTTP 비-GET | `send`(항상 ask) |
| `file:`, `chrome:` 등 금지 스킴, 차단 대역 | 거부 |

- 로그인·결제·계정 생성·약관·쿠키 동의는 합의가 미리 허용하지 않으면 ask.
- 웹 검색(T-BR8): 제공자 API(Brave 기본, Tavily 예비), Anthropic 서버 측 `web_search`는 쓰지 않는다(J-190 (5)). 질의는 `mask()` 후 `queryMasked`만 보내고 읽기로 분류한다(J-207). 키는 데몬 `SecretStore`에서만 읽는다. 키가 없으면 도구를 뺀다(S-20).

### 2.20 프롬프트 주입과 taint (18 §3.12 규칙 1~11; 16 §3.8~3.9)

- 원칙: 기록 속 문장은 데이터다. 문장 자체는 못 막고, 권한 변경은 구조로 막는다.
- 규칙 1: 모델에게 권한을 바꾸는 도구가 없다(합의 확정, 결과 확인, 다이얼·정책, 기기·페어링, 격리 설정은 사람 메서드만, 결정 14).
- 규칙 2·8: 신뢰하지 않는 내용은 `<untrusted id="…">`로 감싼다. 무작위 id를 붙이고, 렌더러는 본문의 `<untrusted`, `</untrusted`, `<helm_context`(공백·대소문자 변형 포함)를 엔티티로 바꾼다(T18-37). 사람 답 형식(`<helm_context kind=answer>`)은 신뢰하지 않는 글 안에서 만들 수 없다.
- 규칙 3: 승인 화면은 커널 구조 값(경로, 명령, 네트워크 여부)을 먼저 보이고, 모델 요약은 보조다.
- 규칙 7: 클라이언트는 모델·도구 출력을 신뢰하지 않는 자료로 그린다. 원시 HTML 금지, 링크는 `https:`·`helm:`만, `file:`·`javascript:`·`data:` 금지(T18-32).
- 규칙 9: 작업 공간 지침 파일(`AGENTS.md`, 없으면 `CLAUDE.md`)은 등록 때 sha256을 기록하고, 바뀌면 사람이 확인하기 전까지 이전 확인본을 쓴다(T18-41). 확인 질문은 2단계(결정 62).
- 규칙 10: 브라우저·검색 결과는 `<untrusted id source url tabId snapshotGen>`로 감싼다. 스크린샷은 최근 3장만 남긴다(결정 61). 주입 분류기에는 기대지 않는다.
- 규칙 11(taint): 웹 내용을 한 번이라도 본 run은 `taint.web = true`. 이후 `send`는 합의가 허용해도 `ask`이고 승인 화면에 "웹 내용을 본 뒤의 요청"을 보인다. 읽기와 작업 공간 쓰기는 영향 없다. 합의 범위를 넓히는 요청은 질문 도구로만 한다.
- taint 소재(13 §3.10.1, J-215): run 상태 `taint`(08 Run/RunCore 필드, 09 §3.4.12). 별도 이벤트 없음. 웹 도구 `toolcall.completed`에서 재구성(12 §3.2.5). 같은 thread의 새 run과 하위 run이 상속한다.
- 관찰 입력(16): 외부 세션 로그는 신뢰하지 않는다. 관찰 제안은 사람 채택 + 일반 작업 경로(OB-6), 자동 설치 금지(E1-076).
- 집행 구분(canon-3): "승인을 받았다"는 프롬프트 문장을 집행하지 않는다. 집행은 2.21절 기준선, 커널 검사, 샌드박스다(T18-26).

### 2.21 외부 발송 `send`와 권한 레이어 기준선 (18 §3.11.6; 11; 13 §3.10)

- `send` 원시 행동: 메일, 메시지, 원격 push, 외부 API 쓰기, 패키지 배포. 정보가 Helm과 작업 공간 밖으로 나간다.
- 합의 없음 → 커널이 `deny`(결정 15). 합의 있음 → 1차에는 매번 `ask`(Q18-06, J-91).
- 권한 레이어 `PermissionLayer.classify`는 아래 고정 기준선을 먼저 적용하고, 남은 행동에 13 범위 검사와 합의를 적용한다. 모드·다이얼로 못 끈다. effect class는 쓰지 않는다(결정 2).

| 행동 | decision | 권리 범주(`RightsCategory`) | reasonCode |
|---|---|---|---|
| 보호 경로 쓰기 | deny | - | `protected_path.write` |
| 보호 경로 읽기(모델 컨텍스트로) | ask | `disclose_data` | `protected_path.read` |
| `send` 원시 행동 | 합의 없음 deny(커널), 있음 ask | `speak_for_user`; 다른 사람이면 `affect_others`; 돈이면 `spend_money` | `send.requires_human` |
| `externalEffect: uncertain` 호출 | `send`와 같음(J-206) | `send`와 같음 | `send.requires_human` |
| 결과 불명 외부 효과의 해소 | - | `irreversible_external`(J-05) | - |
| 웹 내용을 본 run(`taint.web`)의 `send` | 합의가 허용해도 ask | 위와 같음 | `send.requires_human` |
| 공개 주소 웹 읽기(`web_fetch`, `web_search`, 브라우저 GET·HEAD) | allow, 합의 부여 불필요(J-205, J-207) | - | - |
| 네트워크 실행 | 부여 있으면 allow, 없으면 ask. 차단 대역은 항상 deny | 부여 없으면 `disclose_data` | `network.ungranted` |
| `secrets run`, `sops -d`, `secrets edit`, `secrets dotenv` | ask | `disclose_data` | `secrets.access` |
| `sudo`, `su`, `pkexec`, `doas`, `systemctl`, `loginctl`, `crontab`, `at` | deny | - | `privilege_or_persistence` |
| Windows 실행 파일(`*.exe`, `/mnt/**`, `wsl.exe`) | deny | - | `windows_interop` |
| 그 밖 | 13 범위 검사와 합의 | - | - |

- 합의로 바꿀 수 있는 것은 경로·명령·네트워크의 허용뿐이다. 보호 경로 쓰기, 권한 상승, Windows 실행은 합의로도 안 바뀐다.
- `disclose_data`는 고정 범주다(10 §5.2, 11 §5.2에 대한 답). 정보가 밖으로 나가는 행동은 다이얼과 무관하게 권리 게이트다.
- 판정 형식은 `PermissionVerdict`(08 §3.18: `decision`, `rightsGate`, `rightsCategories`, `reversibility`, `mutating`, `reasonCode`). 권한 레이어는 질문을 만들지 않는다. 묻기는 11이 한다(발췌4 d1).
- 제공자 추가는 `disclose_data`의 결정을 대신하지 않고, 설정 변경(`setting.changed`)으로만 바뀐다. 합의 카드에 이번 작업의 제공자 목록을 보인다.
- `argsPreview`: 마스킹을 거친다. 보호 경로 내용은 경로만 보인다. 잘리면 `truncated: true`와 전체 길이를 싣고 "전체 보기" 전에는 허락 버튼이 꺼진다. 제어·양방향 제어 문자는 코드 포인트 표기로 보인다(T18-38).

### 2.22 정적 서빙 `/m/*`와 `/files/*` 헤더 (18 §3.4.6, J-252; 19 §3.2.5; 26 §3.3.2)

- 이유: `/m/*`와 `/files/*`는 같은 출처다. 모델이 만든 blob이 그 출처에서 스크립트로 실행되면 쿠키가 실린 `/rpc`로 결정 명령을 보낼 수 있다(T-W1).
- `/m/*` 공통 헤더: `Content-Security-Policy: default-src 'self'; script-src 'self'; connect-src 'self' wss://<publicHost>; img-src 'self' blob: data:; style-src 'self'; font-src 'self'; worker-src 'self'; manifest-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; form-action 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `Permissions-Policy: camera=(), microphone=(), geolocation=()`. 인라인 `<style>`·스크립트 금지, `style` 속성은 `style-src-attr 'unsafe-inline'`만.
- 캐시: `/m/` index(확장자 없는 경로 포함)·`/m/sw.js`·`/m/manifest.webmanifest`는 `no-cache`, `/m/assets/<해시>`만 `public, max-age=31536000, immutable`.
- 경로: 릴리스 매니페스트(17 §3.10.1) 밖은 404, `..`·심볼릭 링크 탈출은 거부. 판정은 `hello` 전에 하며 Host·신원만 보고 Origin은 보지 않는다. `clients.mobile`이 꺼져 있으면 모두 404.
- `/files/*` 모든 응답: `Content-Security-Policy: sandbox; default-src 'none'`, `nosniff`, `Cross-Origin-Resource-Policy: same-origin`, `Cache-Control: private, no-store`(J-252로 18이 정본). 인라인은 `image/png`, `image/jpeg`, `image/webp`, `image/gif`, `text/plain; charset=utf-8`만. 나머지(SVG, HTML, XML, PDF 포함)는 `application/octet-stream` + `attachment`.
- 접근 로그에서 티켓 경로를 가린다(18은 `/files/[ticket]/…`, 19는 `/files/t/***` — §8.3).

### 2.24 백업과 복구 (18 §3.16; 09 §3.14.2; 17 §3.9.4)

- 스냅샷은 정본 사본이라 같은 보호를 받는다(0600/0700). 모델 키와 VAPID 키는 없다. 토큰 해시와 페어링 코드 해시는 있다. `push_tokens` 구독 원문은 있다(VAPID 없이는 서명 불가).
- restore-carry: CLI `helm ops restore`(데몬 꺼짐)가 현재 DB를 읽기 전용으로 열 수 있으면 권한을 줄인 이벤트(기기 폐기, 코드 취소, Grant 철회, 합의 좁힘, `dial.set` 하향, `blob.redacted`, HMAC 교체, 그리고 18이 더하라고 요구한 `device.expired`, `device.push_unregistered`)를 `state/restore-carry.json`(0600)에 쓴다. CLI는 HMAC 키가 없고 정본에 쓰지 않는다.
- 첫 부팅: `daemon.booted` → `daemon.safe_mode_entered{restored}` → `store.restored{carried}`, 그리고 리스너를 열기 전에 항목을 `internal:recovery`로 다시 낸다(커널 검증). 처리 전에는 리스너를 열지 않는다. 미소진 승인은 `approval.expired{restored}`.
- 현재 DB를 못 열면 모든 기기 토큰을 무효로 하고(`device.revoked{restore_without_revocation_list}`) 재페어링. Grant·합의는 복원본 그대로(주의 항목은 2단계, 결정 62).
- 복원 직후는 안전 모드(J-152). 진행 중 run을 자동으로 잇지 않는다. 사람이 상태를 보고 해제한다(17 §3.4.6).

### 2.25 공급망 요점 (18 §3.15)

- pi 포크 `v1.1.0`(커밋 `abe508e1`), 갱신은 사람이 검토한 커밋으로만. 정확한 버전(`^` 없음), `pnpm-lock.yaml`, `--frozen-lockfile`. `allowBuilds`에 없는 빌드 스크립트는 설치를 실패시킨다(`ERR_PNPM_IGNORED_BUILDS`). `better-sqlite3`는 소스 빌드하고 `.node` 해시를 매니페스트에 적는다. 실행 중 내려받기 금지(`PI_OFFLINE=1`). 운영 릴리스는 커밋에서만(17 ADR-17-5).

### 2.26 모바일 보안 규칙 (18 §3.18; 26 §3.3, §3.4, §3.3.8)

- 경로: tailnet만. 휴대폰에 Tailscale이 켜져 있어야 한다. SSH 경로는 없다. 18 §3.4.3의 tailnet 조건이 모두 적용된다.
- 페어링: 흐름 A만, 홈 화면 앱 안에서(Safari와 쿠키를 나누지 않음, 26 X-7).
- scope: `read`, `decideMobile`, `devicesLimited`. 권한을 넓히거나 방향을 바꾸는 명령, 페어링 코드 생성은 `1010`. 안전 모드 해제(`daemon.exitSafeMode`)는 허용. 설정은 알림과 조용한 시간만.
- 앱 잠금 없음(1차, 26 MQ-03). 남는 위험: 잠기지 않은 휴대폰.
- 푸시: 강도 `interrupt`·`notice`만(결정 48, 56). `contentLevel` 기본 `hidden`(J-03). 구독 원문은 `push_tokens`에만, 이벤트에는 `tokenHash`·`tokenHint`(해시 앞 8자). 엔드포인트는 `https:`, 443, IP 주소 아님, `push.webpush.allowedEndpointSuffixes`(기본 `push.apple.com`)의 점 경계 접미사만(`evilpush.apple.com`은 불일치). 송신 때 차단 대역이면 보내지 않고 3xx를 따르지 않는다(T18-31).
- 홈랩 ntfy는 Helm 푸시 경로가 아니다.

### 2.27 클라이언트 기기의 데이터 (18 §3.19)

- 오프라인 사본(뷰·명령함·초안·blob 캐시)에 토큰은 없다. 앱 암호화는 1차에 하지 않고 OS 디스크 암호화에 맡긴다(Q18-11). 설정으로 끌 수 있다.

| 사유 | 뷰·blob 캐시 | 진행 중 명령함 | 초안 | 그 뒤 |
|---|---|---|---|---|
| `revoked`(4009 포함) | 지움 | 지움 | 남김 | 페어링 화면 |
| `expired_absolute`·`expired_idle` | 남김 | 남기되 자동 재전송 제외 | 남김 | 재페어링 안내 |
| `node_mismatch`·`carrier_mismatch` | 남김 | 남김 | 남김 | `helm device rebind` 안내 |

### 3.1 tailnet 연결 판정 (18 §3.4.3, §3.6.1; 19 §3.4.1)

1. 인증 전 연결 수 확인(출처별 8, 전체 64). 넘으면 429 또는 503.
2. `preflight`: Host가 다르면 403.
3. `tailscaleIngress`(2.7절). 실패하면 401과 `auth.denied`.
4. 경로 분기: `/healthz`, `/m/*` 정적(쿠키 무시), `/m/pair`·`/m/logout`(Origin 정확 일치), `/m/cmd`(Origin 정확 일치 + 쿠키), `/m/whoami`(`originGetRule` + 쿠키), `/pair`·`/devices/self/rotate`(Origin 있으면 403), `/files/*`(티켓 또는 쿠키 + `originGetRule`), `/rpc`(`upgradeAuth`), 그 밖 404.
5. `upgradeAuth`: `Authorization`이 있으면 헤더 갈래(Origin 있으면 403, 형식 틀리면 401). 없고 쿠키가 있으면 쿠키 갈래(Origin 정확 일치가 아니면 403). 둘 다 없으면 401.
6. 101 뒤 `awaitingHello`. 서버가 먼저 `hello.challenge`(`nonce`, `serverId`, `authMethods`, `proofRequired: false`)를 보낸다. `hello` 전의 다른 요청은 1001 뒤 1008. 10초 안에 `hello`가 없으면 4001.
7. `hello`: 버전 → `authMethods`(아니면 1008) → `helloDeviceAuth`(2.8절) → scope 부여 → `ready`. `device.connected`.
8. 실패하면 오류 응답 뒤 1008로 닫고, 사유는 `auth.denied` 5분 묶음에 든다.

### 3.3 loopback과 local 흐름 (18 §3.5 규칙 4·6·7, §3.6.2~3.6.3; 19 §3.2.3~3.2.4)

- loopback: 앱이 `ssh -T -o BatchMode=yes -W 127.0.0.1:7841 <서버>`를 띄운다(원격 명령 없음). sshd는 키 인증만 받는다(앱 전용 키를 `restrict,port-forwarding,permitopen="127.0.0.1:7841"`로 두는 것은 권장이고 강제는 아니다). 헤더 토큰이 필수이고, `localAdmin`을 주장하면 1008. 같은 호스트 프로세스도 같은 포트를 열 수 있으나 토큰 없이는 못 한다. SSH 키 도난은 셸을 얻는 일이라 이 설계로 막지 못한다(ADR-18-02).
- local: 시작할 때 소켓 디렉터리 0700, 소켓 0600, 소유자 = 데몬 uid를 확인하고 다르면 종료 2. `hello`의 `interactive`는 `tui`, `tty_cli`, `null`(비대화). `tui`는 화면 버튼이 확인 단계다. `tty_cli`는 명령마다 `localConfirm.request`의 4자 문자열(2분, 1회)을 친다. `null`은 읽기·관리만(`denied.channel`). 감사에는 `via: { kind: "local_cli" }`. 같은 uid의 의사 터미널 공격은 막지 못한다(§3.5 규칙 7).

### 3.4 등록·쿠키·회전·폐기 흐름 (18 §3.7, §3.8, §3.4.3; 26 §3.3.4)

1. 데스크톱이 코드와 만료 시각을 보인다(`pairing.code_created`). 모바일용은 설치 QR(`<publicOrigin>/m/`)도 보인다.
2. 새 기기가 `POST /pair` 또는 `POST /m/pair`로 코드를 보낸다(tailnet + tailscaleIngress).
3. 데몬이 정규화 → 해시 조회 → `consumed` 또는 `attemptsLeft--` → 성공이면 기기 생성, 노드 묶기, `device.paired{pairedVia, pairedFrom}`. `/pair`는 본문에 토큰을 한 번 주고, `/m/pair`는 `Set-Cookie`로만 준다. 두 응답 모두 `no-store`.
4. 모바일이 `hello`로 `deviceId`를 보낸다. 저장소를 잃었으면 `GET /m/whoami`로 다시 얻고, 401이면 페어링 화면이다. WebSocket은 실패 코드를 스크립트에 주지 않으므로 `open` 전에 닫히면 `whoami`로 사유를 구분한다(19 §3.10.2).
5. 폐기: 2.12절 순서대로. 재접속은 1005 `revoked`. 클라이언트는 2.27절 표대로 캐시를 지운다.
6. 회전(2차): `POST /devices/self/rotate` → 새 토큰, 이전 해시 5분 유효 → `device.token_rotated` → 앱이 키체인에 쓴다.

### 3.5 도구 실행 흐름 (18 §3.11.1~3.11.6, §3.12; 13 §3.5~3.6, §3.10)

1. 모델이 도구 호출을 제안한다. 커널이 `agent:<role>`로 기록한다. 모델은 사람 결정 명령을 낼 수 없다(규칙 1).
2. `PermissionLayer.classify`: 2.21절 기준선 → 나머지는 13 범위 검사와 합의.
3. `deny`는 기록하고 끝낸다. `ask`는 11 게이트로 올리고 승인 지문을 기록한다. `allow`는 실행한다.
4. 파일 도구는 realpath로 보호 경로를 검사한다(R-12). `execute`는 샌드박스 수준 판정(S1 → S1b → 없음), 실행 전 탐색, 환경 허용 목록, 네트워크 허용이면 netns와 프록시, 그리고 실행.
5. 결과는 정본 쓰기 전에 마스킹한다(2.18절). `details.redactions`에 지운 기록을 남긴다.
6. 웹 도구면 run에 `taint.web`. 투영은 신뢰하지 않는 출력을 `<untrusted>`로 감싸고 스크린샷은 최근 3장만 둔다(규칙 2·8·10).
7. codemode와 하위 호출도 같은 흐름을 탄다(R-9).

### 3.6 `send` 흐름 (18 §3.11.6, §3.12 11번; 11)

1. 모델이 `send` 원시 행동 또는 `externalEffect: uncertain` 호출을 낸다.
2. 합의가 없으면 커널이 `deny`(`send.requires_human`), 기록만 남는다.
3. 합의가 있으면 `ask`. 같은 run에 `taint.web`이 있으면 합의와 무관하게 `ask`이고 승인 화면에 표시한다.
4. 11이 질문을 만들어 전달한다(푸시 강도 `interrupt`·`notice`). 사람이 device 연결에서 승인하면 실행한다. 모델 경로나 비대화 `localAdmin`에서는 결정이 안 들어온다.
5. 감사에는 호스트·메서드·판정만 남는다(`tool.net_request`). 본문은 남기지 않는다.

### 3.7 비밀·감사·복원 흐름 (18 §3.10.1, §3.10.5, §3.13, §3.16)

1. SOPS 원본 `~/projects/helm/secrets/prod.sops.yaml` → 데몬 시작 때 `secrets run` 자식 로더 → 메모리의 `SecretStore`만(결정 45, ADR-17-3). `process.env`에는 비밀이 없다. `SecretStore.registerKnown`으로 마스킹기에 등록(8자 이상).
2. 모델 어댑터는 `get(name)`으로만 키를 읽는다. 도구 환경은 허용 목록이고 MCP는 운영자가 적은 이름만 받는다. `secrets.required`에 `HELM_LEDGER_HMAC_KEY`가 빠지면 종료 2.
3. 정본 이벤트는 해시 체인에 붙는다. 1,000건마다, 정상 종료 때, 백업 때 HMAC 체크포인트를 쓴다(D09-6). `keyId = sha256(key)` 앞 8자를 함께 적는다.
4. 백업 매니페스트 `(storeId, upToSeq, headHash)`는 restic 오프사이트에 이력으로 남는다(H-2 뒤). `helm ops verify --anchors`와 매월 훈련이 같은 seq를 비교한다. 다르면 `integrity_suspect`, 읽기 전용.
5. 복원: 현재 DB를 열 수 있으면 restore-carry(2.24절)로 권한 줄임을 다시 적용하고, 리스너는 그 뒤에 연다.

## 7. 구현 리뷰 체크포인트 후보

설계가 "반드시"로 정하거나 시험으로 고정한 것. 괄호 안은 출처와 시험 ID.

1. 토큰 원문은 로그·이벤트·DB·투영·진단 어디에도 없다. 서버는 해시만 저장한다(§3.8.1, §3.9; T18-18, 공통 카나리아).
2. 사람 결정 명령은 `device` 연결과 대화형 `localAdmin`에서만 행위자 `human`이 된다. 클라이언트가 보낸 행위자 값은 무시한다(§3.5 규칙 1·3; T18-19).
3. 모델 도구 경로(`runtimeAdapter`)에는 사람 결정 명령이 없다. 보내면 `denied.channel`(§3.5 규칙 2; §3.12 규칙 1).
4. 비대화 `localAdmin`은 사람 결정을 못 낸다. `tty_cli` 확인은 명령마다 맞고 2분 안이며 1회다(§3.5 규칙 6; T18-19, J-135).
5. 헤더 갈래 Origin이 있으면 403. `/pair`·`/devices/self/rotate`에 Origin이 있으면 403. Host 불일치는 403(§3.4.3 규칙 4; T18-07).
6. 업그레이드 단계는 존재와 형식만 본다. 해시·폐기·만료는 `hello`에서 본다(§3.4.3 규칙 6; 19 P-03).
7. 토큰 경로에서 1006을 쓰지 않는다. 형식·없음·불일치는 1004(§3.6.1; T18-01).
8. 폐기된 기기의 열린 연결은 4009로 닫히고, 티켓과 그 기기가 만든 코드는 즉시 무효다(§3.8.4; T18-17).
9. 노드 묶기: 묶인 기기가 다른 `StableID`에서 오면 1008 `node_mismatch`. 묶이지 않은 기기는 첫 WSS 접속에서 묶인다(D18-02; T18-04).
10. whois 실패는 fail closed다. `token-only`는 `auth.policy_relaxed`를 남긴다. Funnel 표식과 태그 노드는 거부한다(§3.6.1; T18-02, T18-03).
11. `loopback`에서 `localAdmin`을 주장하면 1008. 쿠키는 `loopback`·`local`에서 읽지 않는다(§3.4.3 규칙 1·7; T18-06).
12. 정식 데몬은 `auth.devAllowedOrigins`가 설정되면 시작을 거부한다(§3.4.5; T18-07).
13. `helm-bearer.` 하위 프로토콜은 토큰으로 쓰지 않는다. 헤더·쿠키가 없으면 401(§3.4.4; T18-07b).
14. 쿠키 갈래: Origin 정확 일치(포트 포함), carrier `cookie`, 헤더와 쿠키가 같으면 헤더만(§3.4.3 규칙 2·3; T18-07b).
15. 페어링 코드: 12자, 1회, 5회 실패 뒤 무효, 동시 3개, 사유 구분 없는 응답, 원문 미저장, tailnet 밖에서 404(§3.7.2, §3.7.4; T18-15).
16. SSH 발급: stdin JSON, 이름 1~64자, 제어·양방향 제어 문자 거부, `helmCliPath` 정규식(§3.7.3; T18-16).
17. `/m/pair` 응답 본문에 토큰이 없고, `Set-Cookie`에 `__Host-`, `HttpOnly`, `Secure`, `SameSite=Strict`가 있다. 본문의 `clientKind`·`credentialCarrier`는 무시한다(§3.7.2; T18-07b).
18. 모바일 scope에서 `device.createPairingCode`, `grant.*`, `dial.set`, `approve_edited`, 결과 확인의 조건부·거절은 1010(§3.5; T18-31).
19. `/m/*` 정적: 목록 밖 404, `..`·심볼릭 링크 거부, CSP와 `nosniff`, 쿠키 미사용, 해시 파일만 immutable(§3.4.6; T18-07b).
20. `/files/*`: CSP `sandbox; default-src 'none'`, `nosniff`, `CORP`, `Cache-Control: private, no-store`, 허용 목록 밖은 `octet-stream` + `attachment`, 로그에서 티켓 가림(§3.4.6, J-252; T18-07c).
21. 샌드박스 환경에는 허용 목록 밖 변수가 없고, 합의로도 `*_KEY`, `HELM_*`, `ANTHROPIC_*`는 못 넘긴다(R-2; T18-29).
22. 샌드박스에서 `/srv/volumes`, `rpc.sock`, `/run/WSL`, 홈 전체가 안 보이고, `/proc/<helmd pid>/environ`과 `/mem` 읽기가 거부된다(R-3~R-5; T18-08~T18-10, T18-14).
23. 격리 시험 T18-08~11과 T18-34~36을 S1과 S1b에서 각각 돈다. 수준이 없으면 `execute`를 켜지 않는다(§3.17 머리말, §6; T18-11).
24. 샌드박스 네트워크: 별도 netns, loopback과 `100.64.x.x`·`2019` 접근 실패, 차단 대역은 어떤 부여로도 열리지 않는다(R-6, §3.11.9; T18-09, T18-34, T18-50).
25. 권한 기준선 표의 각 행은 같은 판정을 내고 모드·다이얼로 바뀌지 않는다(§3.11.6; T18-26).
26. 보호 경로 쓰기 deny, 읽기 ask(`disclose_data`), `secrets run`·`sops -d` ask, `sudo`·Windows 실행 deny(§3.11.6; T18-10, T-M2).
27. 데몬 git: 고정 환경, 실행 지점 설정이 있으면 git을 부르지 않고 해시 스캔과 감사, 샌드박스 안 `.git/config` 쓰기 실패(§3.11.10; T18-35, SG-01~06).
28. `web_fetch`: 차단 대역을 해석 뒤와 리디렉션마다 검사, 해석 IP 고정, `GET`·`HEAD`만(§3.11.8; T18-27).
29. `taint.web`이 달린 run의 `send`는 합의가 허용해도 ask이고 승인 화면에 표시된다. 같은 run의 읽기와 작업 공간 쓰기는 자동이다(§3.11.6, §3.12 11번; T18-43, WB-02).
30. 웹·브라우저 출력은 `<untrusted id=…>`로 감싸고 닫힘 위조 문자열은 엔티티로 바뀐다. 스크린샷은 최근 3장만 남는다(§3.12 8·10번; T18-37, T18-42).
31. 브라우저: CDP는 파이프, 디버그 포트 없음, 모델 키 없음, 프로필은 실행마다 새로, 금지 스킴 거부(BR-3~5; T18-44~46).
32. 요청 가로채기는 조작 단계와 함께만 켜고, 읽기 단계는 비-GET·업로드·합의 밖 이동을 거부한다(BR-6; J-208, J-229; T18-47, T18-52).
33. 마스킹: 알려진 값과 패턴이 정본·휘발 스트림·로그·진단 묶음에 원문으로 남지 않는다. 사람 명령 payload는 커널 입력 전에 마스킹한다(§3.10.3; T18-13, T18-39).
34. `SecretStore`는 `get(name)` 말고는 노출 경로가 없다. `toJSON`과 inspect가 막혀 있다. OAuth 토큰은 로더가 버리고 경고한다(§3.10.1; T18-30).
35. `HELM_LEDGER_HMAC_KEY`가 없으면 시작하지 않는다(종료 2). 키는 `SecretStore`에만 있다(§3.10.5).
36. 감사 이벤트는 값 없는 필드만 담는다. `tokenHash`는 재전송·투영·관찰 입력에서 지운다(§3.13.1; T18-18).
37. 인증 실패는 출처별 5분 묶음으로 쓴다. 맞는 토큰은 실패 묶음과 무관하게 통과한다(§3.13.2, §3.14; T18-20).
38. 체인 재작성은 `verify --anchors`에서 실패하고 모드는 `read_only`다(§3.13.3; T18-23).
39. 복구: 리스너는 restore-carry 처리 전에 안 열린다. 미소진 승인은 `expired{restored}`. 첫 부팅은 안전 모드다. 현재 DB를 못 열면 모든 토큰이 무효다(§3.16; T18-22).
40. 기기 키 서명은 1차에 꺼져 있다(`proofRequired=false`)(§3.8.5, D18-07).
41. 모바일 푸시: 본문 기본 숨김, 구독 원문은 `push_tokens`에만, 엔드포인트 접미사는 점 경계, 차단 대역 연결 금지, 3xx 미추적(§3.18.2 9번; T18-31).
42. 클라이언트 렌더링: 원시 HTML 금지, 링크 `https:`·`helm:`만(§3.12 7번; T18-32).
43. 관찰 자식은 `private/`을 열지 못하고 비밀과 쓰기 권한이 없다(§3.11.3; T18-33, OB-T32).
44. 허용 폴더 등록은 사람 결정 명령으로만, `realpath` 뒤 `projects.roots` 아래여야 하고 심볼릭 링크 탈출은 거부(§3.11.7; T18-28).
45. 결정 46: 모든 리스너가 자격 증명을 요구한다. 루프백 바인딩을 격리 근거로 쓰는 코드나 문서가 없어야 한다(결정 46; 2.4절).
46. 시험 공통 카나리아(`helm_dt_`, `sk-ant-`, `HELM_LEDGER_HMAC_KEY` 시험 값)가 DB 파일, 운영 로그, 진단 묶음, 클라이언트 메시지에 없어야 한다(§3.17 머리말; 22 §5.2).
47. 수동 시험 T18-05(serve 헤더 덮어쓰기)와 T18-12(WSL 소켓 연결 실패)는 완료 기준이다. 결과를 18에 반영한다(§6 완료 기준).

## 8. 헷갈리기 쉬운 점

### 8.1 비슷한 이름

- `loopback`(리스너 이름)과 루프백 바인딩(주소): `loopback` 리스너는 SSH 경로다. `tailnet` 리스너도 127.0.0.1에 바인딩된다. 루프백이라서 안전하다는 뜻이 아니다(결정 46).
- 토큰 여러 종: 기기 토큰 `helm_dt_`, 쿠키 `__Host-helm_dt`(같은 토큰을 나르는 방법), 외부 런타임 `helm_rt_`(별도 주체), 하위 프로토콜 `helm-bearer.`(받지 않음), 다운로드 티켓(5분, 연결에 묶임), 페어링 코드(12자, 1회), SSH 키(토큰이 아님).
- `S0`·`S1`·`S1b`(샌드박스 수준), `S-01`~`S-20`(실패 사례), `S4`(사례 출처), `SP-15`(스파이크) 는 다른 것이다.
- `T-N1`(위협, 18 §3.2), `T18-01`(시험, §3.17), `T-E55`(13 위협), `T-SG-01`(13·22의 git 표본)이 같이 쓰인다. `R-1`~`R-14`(18 요구)와 13의 요구 번호는 다르다. `BR-1`~`BR-8`은 조사 문서의 `B-1`~`B-8`에서 옮겼다.
- 행위자: `human`, `agent:<role>`, `runtime`, `internal:recovery`, `agent:observer`는 각각 다르다.
- `clientKind`(18: `desktop`·`tui`·`mobile`)와 `ClientInfo.kind`(19: 여기에 `cli`·`test`가 더 있다)는 값 집합이 다르다. `cli`가 18의 주체에 어떻게 대응하는지는 적혀 있지 않다.
- `credentialCarrier`(기기 속성, 발급 때 정함)와 `carrier`(연결 속성, 업그레이드 때 정함)는 맞아야 한다(§3.4.3 규칙 3).
- `interactive`의 `null`은 "없음"이 아니라 "비대화"다.
- 1006: 브라우저가 연결 실패를 보일 때 쓰는 비정상 종료 코드이고, 19에는 `auth.unknownDevice`로도 정의되어 있다. 18은 토큰 경로에서 쓰지 않는다고 못 박았다.
- `Sec-Fetch-Site`: 같은 출처 GET은 이 헤더 값으로 판정한다. Origin이 없다는 것만으로 허용하지 않는다(`originGetRule`).

### 8.2 옛 이름과 값

- 페어링 코드 예시: 18 §3.7.2는 19 예시를 "9자 45비트"라고 쓰지만, 19의 현재 예시는 12자(`K7Q4-XM92-PH3D`)다.
- `Via.listener`: 08의 `Via`는 이미 `tailnet | loopback | local`이다(19 `ListenerKind`). 25 N-01 행은 아직 옛 값 `tailscale | ssh | local`을 적고 있다.
- 합의 플래그 이름: 18 R-10·§3.11.2 끝은 `allowUnscopedExecute`(13)라고 쓴다. 13과 08은 `Scope.allowUnknownTargets`다(§8.3).
- 1009: WebSocket 닫는 코드(메시지 크기 초과, 19 §3.2.6·§3.4.5, 18 T18-21)와 JSON 오류 코드(`pairing.invalidCode`, 19 §3.3.4·§3.7.7, 26)가 같은 번호다. 구현할 때 전송 계층과 응답 본문을 구분해야 한다.

- Q18-02 기기 키 서명을 켜는 시점(하드웨어 보호 키가 생길 때).
- Q18-03 격리 수단. bubblewrap 설치는 사람이 해야 한다(`sudo apt install bubblewrap`, J-73). 그 전에는 S1b.

- Q18-08 페어링 코드 생성 권한(데스크톱·TUI 허용, 모바일 거부 추천). 19의 `device.createPairingCode`와 맞춘다.
- Q18-11 오프라인 사본 암호화(OS에 맡김). Q18-12 프록시 스파이크 실패 때(판정대로). Q18-13 쿠키 포트 문제(1차 수용, 26 MQ-15).
- 닫힌 것: Q18-04(J-134), Q18-07(J-135), Q18-09·10(결정 47), Q18-14(J-229), Q18-15(J-209).

결정으로 미룬 것:
- 결정 62: 18 §5.2 (5)(6) 2단계. 복원 뒤 "권한 변경을 확인할 수 없음" 주의와 지침 파일 변경 확인 질문. MVP는 규칙 9의 확인본 사용만 한다.
- 결정 63: `helm-netshim`의 형태는 스파이크 뒤 확정.

- 결정 55의 후속: 컴퓨터 사용은 이후 1차. Stagehand는 의존하지 않는다(J-190).

이후 단계:
- 토큰 회전 2차 구현(20 `credential_rotate`).
- ADR-18-07(해시 체인 밖 민감 필드, 24 후보). 09·10과 함께 바뀐다(J-147). 구현 전에 정한다.

검증할 가정과 실험:
- A18-1·A18-2: `tailscale serve`가 신원 헤더를 덮어쓰고 XFF를 붙이는지(T18-05 수동).

- 프록시 스파이크: S1·S1b에서 `pnpm install`, `git clone`, `curl`이 프록시로 되는지(T18-34, 23).
